SETUP
==============================================================================

Create the topic folder and module — type it, don't copy:

    mkdir func1
    cd func1
    go mod init func1

From here on, type all code into main.go in that folder.
To run the program:

    go run .

------------------------------------------------------------------------------
HOW TO WORK WITH THE EXAMPLES
------------------------------------------------------------------------------

1. Type it out. Don't copy-paste — while you type, your eye catches the
   brackets, dots and quotes that copying slides right past.

2. BEFORE running, write down what it will print. Then run it and compare
   with the answer under the example.

3. A mismatch is the valuable part. Work out why it came out that way
   before moving on.

4. Once it works, break it on purpose: drop the quotes, change the type,
   use a different index. Read what the compiler says.

5. Each example differs from the previous one by a single change — it is
   named in the heading. Spot it before you run anything.

EXAMPLES

------------------------------------------------------------------------------
EXAMPLE 1.  What changed: the first one, type it all
------------------------------------------------------------------------------
package main

import "fmt"

func hello() {
	fmt.Println("hello")
}

func main() {
	hello()
}

OUTPUT:
hello

main is the entry point, everything starts there. hello is declared separately and runs only because the line hello() calls it.
Break it: remove hello() from main. It still compiles and prints nothing — declaring a function is not running it.

------------------------------------------------------------------------------
EXAMPLE 2.  What changed: the function got a parameter
------------------------------------------------------------------------------
package main

import "fmt"

func greet(name string) {
	fmt.Println("hello,", name)
}

func main() {
	greet("Go")
	greet("world")
}

OUTPUT:
hello, Go
hello, world

One function, two calls with different values. The parameter name is a variable created afresh on every call and alive only inside the function.
Break it: call greet() with no argument and read the error.

------------------------------------------------------------------------------
EXAMPLE 3.  What changed: two parameters, the function prints the result
------------------------------------------------------------------------------
package main

import "fmt"

func showSum(a int, b int) {
	fmt.Println(a + b)
}

func main() {
	showSum(2, 3)
	showSum(10, 20)
}

OUTPUT:
5
30

The function computes and prints on the spot. It returns nothing — past the closing brace, nothing of the calculation is left.
Break it: write x := showSum(2, 3). The error showSum(2, 3) (no value) used as value is exactly the difference between printing and returning.

------------------------------------------------------------------------------
EXAMPLE 4.  What changed: the print was replaced by return
------------------------------------------------------------------------------
package main

import "fmt"

func sum(a int, b int) int {
	return a + b
}

func main() {
	fmt.Println(sum(2, 3))
	fmt.Println(sum(10, 20))
}

OUTPUT:
5
30

The output is identical to example 3 — and that is the heart of this topic. On screen the two functions are indistinguishable. The difference is who received the number: before it went straight to the screen, now it goes to main, and main decides what to do with it.

------------------------------------------------------------------------------
EXAMPLE 5.  What changed: the result was fed into another call
------------------------------------------------------------------------------
package main

import "fmt"

func sum(a int, b int) int {
	return a + b
}

func main() {
	x := sum(2, 3)
	fmt.Println(x)
	fmt.Println(sum(x, sum(10, 20)))
}

OUTPUT:
5
35

A returned value is an ordinary number: store it, add it, pass it into another function. The inner sum(10, 20) runs first, its 30 goes out as an argument, 5 + 30 = 35. A printing function can't do this — there is nothing to feed in.

------------------------------------------------------------------------------
EXAMPLE 6.  What changed: the parameter became a slice, a loop appeared inside
------------------------------------------------------------------------------
package main

import "fmt"

func sumAll(nums []int) int {
	total := 0
	for _, n := range nums {
		total = total + n
	}
	return total
}

func main() {
	fmt.Println(sumAll([]int{1, 2, 3, 4}))
}

OUTPUT:
10

The accumulator total is created BEFORE the loop: one for the whole function, surviving every step. return sits AFTER the loop, because the answer is known only once the whole slice is walked. Remember this layout — the next two examples break it one piece at a time.

------------------------------------------------------------------------------
EXAMPLE 7.  What changed: return moved inside the loop
------------------------------------------------------------------------------
package main

import "fmt"

func sumAll(nums []int) int {
	total := 0
	for _, n := range nums {
		total = total + n
		return total
	}
	return total
}

func main() {
	fmt.Println(sumAll([]int{1, 2, 3, 4}))
}

OUTPUT:
1

One line moved and 10 became 1. return does not wait for the loop to finish — it ended the function on the first step. The second return after the loop is required here, otherwise missing return, but control never reaches it.

------------------------------------------------------------------------------
EXAMPLE 8.  What changed: the accumulator moved inside the loop
------------------------------------------------------------------------------
package main

import "fmt"

func sumAll(nums []int) int {
	for _, n := range nums {
		total := 0
		total = total + n
		fmt.Println("total:", total)
	}
	return 0
}

func main() {
	fmt.Println(sumAll([]int{1, 2, 3, 4}))
}

OUTPUT:
total: 1
total: 2
total: 3
total: 4
0

Every step creates a NEW total equal to zero, so what gets printed is the element itself, not a sum. After the loop it doesn't exist at all — hence returning zero.
Break it: replace return 0 with return total. The error is undefined: total: the variable died with the loop's closing brace.

------------------------------------------------------------------------------
EXAMPLE 9.  What changed: a function with no return changes its parameter
------------------------------------------------------------------------------
package main

import "fmt"

func addTen(n int) {
	n = n + 10
	fmt.Println(n)
}

func main() {
	x := 5
	addTen(x)
	fmt.Println(x)
}

OUTPUT:
15
5

Fifteen inside, five outside. n got a copy of the value and x knows nothing about it. For the change to stick, the function must return a new value and main must assign it: x = addTen(x).

EXAMPLE 10.  What changed: the function returns two values
------------------------------------------------------------------------------
package main

import "fmt"

func minMax(nums []int) (int, int) {
	lo := nums[0]
	hi := nums[0]
	for _, n := range nums {
		if n < lo {
			lo = n
		}
		if n > hi {
			hi = n
		}
	}
	return lo, hi
}

func main() {
	a, b := minMax([]int{4, 9, 1, 7})
	fmt.Println(a, b)
	fmt.Println(b - a)
}

OUTPUT:
1 9
8

Types listed in parentheses, values after return comma-separated in the same order. The starting values come from nums[0], not from zero: starting at zero would find the wrong maximum for an all-negative slice.
Break it: write v := minMax([]int{4, 9, 1, 7}) and read the assignment mismatch.
