SETUP
==============================================================================

Create the topic folder and module — type it, don't copy:

    mkdir struct1
    cd struct1
    go mod init struct1

From here on, type all code into main.go in that folder.
To run the program:

    go run .

------------------------------------------------------------------------------
HOW TO WORK WITH THE EXAMPLES
------------------------------------------------------------------------------

1. Type it out. Don't copy-paste — while you type, your eye catches the
   brackets, dots and quotes that copying slides right past.

2. BEFORE running, write down what it will print. Then run it and compare
   with the answer under the example.

3. A mismatch is the valuable part. Work out why it came out that way
   before moving on.

4. Once it works, break it on purpose: drop the quotes, change the type,
   use a different index. Read what the compiler says.

5. Each example differs from the previous one by a single change — it is
   named in the heading. Spot it before you run anything.

------------------------------------------------------------------------------
EXAMPLE 1.  What changed: the first one, type it all
------------------------------------------------------------------------------
package main

import "fmt"

type Person struct {
	name string
	age  int
}

func main() {
	var p Person
	fmt.Println(p)
	fmt.Println(p.name == "", p.age)
}

OUTPUT:
{ 0}
true 0

The struct exists and nothing was put in it — inside are zero values, not garbage. An empty string prints as nothing, which is why there is a space between the brace and the zero.
Break it: add a third field ok bool to the type and see what shows up in the output.

------------------------------------------------------------------------------
EXAMPLE 2.  What changed: the struct is created with values
------------------------------------------------------------------------------
package main

import "fmt"

type Person struct {
	name string
	age  int
}

func main() {
	p := Person{"Bob", 30}
	fmt.Println(p)
	fmt.Println(p.name == "", p.age)
}

OUTPUT:
{Bob 30}
false 30

Values without names go strictly in the order the fields are declared.
Break it: drop the 30 and leave Person{"Bob"} — you get too few values in struct literal.

------------------------------------------------------------------------------
EXAMPLE 3.  What changed: values are given by field name
------------------------------------------------------------------------------
package main

import "fmt"

type Person struct {
	name string
	age  int
}

func main() {
	p := Person{name: "Bob"}
	fmt.Println(p)
	fmt.Println(p.name == "", p.age)
}

OUTPUT:
{Bob 0}
false 0

With names you may skip fields — the skipped ones become zero. This form survives a new field being added to the type; the form from example 2 does not.

------------------------------------------------------------------------------
EXAMPLE 4.  What changed: a field is changed after creation
------------------------------------------------------------------------------
package main

import "fmt"

type Person struct {
	name string
	age  int
}

func main() {
	p := Person{name: "Bob"}
	p.age = 30
	fmt.Println(p)
	fmt.Println(p.name, p.age)
}

OUTPUT:
{Bob 30}
Bob 30

The dot works the same for reading and writing. Remember this output — the next example does exactly the same thing but gives a different result.

------------------------------------------------------------------------------
EXAMPLE 5.  What changed: the same change moved into a function
------------------------------------------------------------------------------
package main

import "fmt"

type Person struct {
	name string
	age  int
}

func setAge(p Person) {
	p.age = 30
}

func main() {
	p := Person{name: "Bob"}
	setAge(p)
	fmt.Println(p)
	fmt.Println(p.name, p.age)
}

OUTPUT:
{Bob 0}
Bob 0

Zero instead of thirty. The line p.age = 30 did run — on a copy that lives only inside the function. No error, no warning.
Break it: add fmt.Println(p) as the last line inside setAge — there it shows 30.

------------------------------------------------------------------------------
EXAMPLE 6.  What changed: the parameter became a pointer
------------------------------------------------------------------------------
package main

import "fmt"

type Person struct {
	name string
	age  int
}

func setAge(p *Person) {
	p.age = 30
}

func main() {
	p := Person{name: "Bob"}
	setAge(&p)
	fmt.Println(p)
	fmt.Println(p.name, p.age)
}

OUTPUT:
{Bob 30}
Bob 30

Two characters separate this from the previous example: * in the declaration and & at the call. Inside the function it is still a copy — a copy of the address, and the address leads to the original.
Break it: remove the & at the call and read the error.

------------------------------------------------------------------------------
EXAMPLE 7.  What changed: no function this time, the pointer itself
------------------------------------------------------------------------------
package main

import "fmt"

type Person struct {
	name string
	age  int
}

func main() {
	p := Person{name: "Bob", age: 30}
	q := &p
	fmt.Println(q == &p)
	fmt.Println(*q)
	fmt.Println(q.name, (*q).name)
	q.age = 31
	fmt.Println(p.age)
}

OUTPUT:
true
{Bob 30}
Bob Bob
31

q.name and (*q).name are the same thing — Go inserts the star for you. The last line is the whole point of a pointer: the write went to q and p changed.
Break it: print q without the star — you'll see &{Bob 30}.

------------------------------------------------------------------------------
EXAMPLE 8.  What changed: a second pointer appeared, with no address
------------------------------------------------------------------------------
package main

import "fmt"

type Person struct {
	name string
	age  int
}

func main() {
	p := Person{name: "Bob", age: 30}
	q := &p
	var z *Person
	fmt.Println(q == nil, z == nil)
	fmt.Println(*q)
	fmt.Println(q, z)
}

OUTPUT:
false true
{Bob 30}
&{Bob 30} <nil>

z is declared but never got an address — inside is nil. Printing it is safe; z.name would kill the program.
Break it, definitely: add fmt.Println(z.name) and read the crash text — it's a panic, not a build error.

------------------------------------------------------------------------------
EXAMPLE 9.  What changed: another struct went inside
------------------------------------------------------------------------------
package main

import "fmt"

type Address struct {
	city string
	zip  int
}

type Person struct {
	name string
	age  int
	addr Address
}

func main() {
	var p Person
	fmt.Println(p)
	p.name = "Bob"
	p.addr.city = "Astana"
	fmt.Println(p)
	fmt.Println(p.addr.city, p.addr.zip)
}

OUTPUT:
{ 0 { 0}}
{Bob 0 {Astana 0}}
Astana 0

A nested struct prints with its own braces — read the output by them. The zero value goes all the way down: Address has all its fields zeroed too.

------------------------------------------------------------------------------
EXAMPLE 10.  What changed: the structs went into a slice
------------------------------------------------------------------------------
package main

import "fmt"

type Person struct {
	name string
	age  int
}

func main() {
	people := []Person{{"Bob", 30}, {"Ann", 25}}

	for _, v := range people {
		v.age = 0
	}
	fmt.Println(people)

	for i := range people {
		people[i].age = 0
	}
	fmt.Println(people)
}

OUTPUT:
[{Bob 30} {Ann 25}]
[{Bob 0} {Ann 0}]

Two loops that look alike, different results. In the first, v is a copy of the element and you zeroed the copy. In the second, people[i] is the element itself.
Inside []Person{...} the type name may be omitted: {"Bob", 30} instead of Person{"Bob", 30}.
