Create the topic folder and module — type it, don't copy:

    mkdir fn1
    cd fn1

From here on, type all code into main.go in that folder.
To run the program:

    go run .

------------------------------------------------------------------------------
HOW TO WORK WITH THE EXAMPLES
------------------------------------------------------------------------------

1. Type it out. Don't copy-paste — while you type, your eye catches the
   brackets, dots and quotes that copying slides right past.

2. BEFORE running, write down what it will print. Then run it and compare
   with the answer under the example.

3. A mismatch is the valuable part. Work out why it came out that way
   before moving on.

4. Once it works, break it on purpose: drop the quotes, change the type,
   use a different index. Read what the compiler says.

5. Each example differs from the previous one by a single change — it is
   named in the heading. Spot it before you run anything.

------------------------------------------------------------------------------
EXAMPLE 1.  What changed: the first one, type it all
------------------------------------------------------------------------------
package main

import "fmt"

func double(x int) int {
	return x * 2
}

func main() {
	fmt.Println(double(5))
}

OUTPUT:
10

An ordinary function and an ordinary call. From here on, only the way we reach this function will change.
Note: double(5) is an expression with the value 10. That is what Println received.

------------------------------------------------------------------------------
EXAMPLE 2.  What changed: the function went into a variable
------------------------------------------------------------------------------
package main

import "fmt"

func double(x int) int {
	return x * 2
}

func main() {
	f := double
	fmt.Println(f(5))
	fmt.Println(double(5))
}

OUTPUT:
10
10

double with no parentheses is the function itself, and it was put into f. Now one function has two names.
Break it: write f := double(5) and keep f(5) below. Read the error — it says a number cannot be called.

------------------------------------------------------------------------------
EXAMPLE 3.  What changed: printing the types
------------------------------------------------------------------------------
package main

import "fmt"

func double(x int) int {
	return x * 2
}

func main() {
	f := double
	fmt.Printf("%T\n", f)
	fmt.Printf("%T\n", f(5))
	fmt.Println(f(5))
}

OUTPUT:
func(int) int
int
10

The whole difference on one screen: f has type func(int) int, while f(5) has type int. The parameter name x is absent from the type — it does not affect it.

------------------------------------------------------------------------------
EXAMPLE 4.  What changed: the function was passed into another function
------------------------------------------------------------------------------
package main

import "fmt"

func double(x int) int {
	return x * 2
}

func square(x int) int {
	return x * x
}

func apply(f func(int) int, n int) int {
	return f(n)
}

func main() {
	fmt.Println(apply(double, 5))
	fmt.Println(apply(square, 5))
}

OUTPUT:
10
25

apply is written once and works by two different rules. Inside it, nothing is known about what f does — only that it can be called with an int.
Break it: pass double(5) instead of double.

------------------------------------------------------------------------------
EXAMPLE 5.  What changed: instead of a name — an anonymous function right in the argument
------------------------------------------------------------------------------
package main

import "fmt"

func apply(f func(int) int, n int) int {
	return f(n)
}

func main() {
	fmt.Println(apply(func(x int) int { return x * 2 }, 5))
	fmt.Println(apply(func(x int) int { return x + 100 }, 5))
}

OUTPUT:
10
105

double and square are gone — the rule is written in place. Watch the comma after the closing brace: it separates the first argument from the second.

------------------------------------------------------------------------------
EXAMPLE 6.  What changed: the functions went into a slice
------------------------------------------------------------------------------
package main

import "fmt"

func main() {
	rules := []func(int) int{
		func(x int) int { return x * 2 },
		func(x int) int { return x + 100 },
		func(x int) int { return x * x },
	}

	fmt.Println(rules[0](5))

	for i, f := range rules {
		fmt.Println(i, f(5))
	}
}

OUTPUT:
10
0 10
1 105
2 25

[]func(int) int is a slice whose items are functions. rules[0] is a function, rules[0](5) is a call to it.
Break it: remove the comma after the last function in the list.

EXAMPLE 7.  What changed: the rule was applied to a whole slice of numbers
------------------------------------------------------------------------------
package main

import "fmt"

func applyAll(nums []int, f func(int) int) []int {
	res := []int{}
	for _, n := range nums {
		res = append(res, f(n))
	}
	return res
}

func main() {
	nums := []int{1, 2, 3, 4}
	fmt.Println(applyAll(nums, func(x int) int { return x * 2 }))
	fmt.Println(applyAll(nums, func(x int) int { return x * x }))
	fmt.Println(nums)
}

OUTPUT:
[2 4 6 8]
[1 4 9 16]
[1 2 3 4]

The loop is written once, the rules are two. The third line shows the original slice is untouched: the result was collected into a new one.

EXAMPLE 8.  What changed: the rule now answers yes/no — a different type
------------------------------------------------------------------------------
package main

import "fmt"

func countIf(nums []int, ok func(int) bool) int {
	c := 0
	for _, n := range nums {
		if ok(n) {
			c++
		}
	}
	return c
}

func main() {
	nums := []int{1, 2, 3, 4, 5, 6}
	fmt.Println(countIf(nums, func(x int) bool { return x%2 == 0 }))
	fmt.Println(countIf(nums, func(x int) bool { return x > 3 }))
}

OUTPUT:
3
3

The rule type became func(int) bool because it answers a question instead of producing a new value. The body of countIf differs from applyAll by one line.
Break it: pass func(x int) int { return x * 2 } here.

EXAMPLE 9.  What changed: a function returns a function
------------------------------------------------------------------------------
package main

import "fmt"

func multiplier(k int) func(int) int {
	return func(x int) int {
		return x * k
	}
}

func main() {
	double := multiplier(2)
	triple := multiplier(3)

	fmt.Println(double(5))
	fmt.Println(triple(5))
	fmt.Printf("%T\n", double)
}

OUTPUT:
10
15
func(int) int

multiplier does not compute — it makes a function. The returned function uses k even though multiplier has already finished: k lives on with it. double and triple each have their own k, and they never mix.

EXAMPLE 10.  What changed: the inner variable changes and survives between calls
------------------------------------------------------------------------------
package main

import "fmt"

func counter() func() int {
	n := 0
	return func() int {
		n++
		return n
	}
}

func main() {
	next := counter()
	fmt.Println(next())
	fmt.Println(next())
	fmt.Println(next())

	other := counter()
	fmt.Println(other())
	fmt.Println(next())
}

OUTPUT:
1
2
3
1
4

n is created afresh on every call to counter(), so other starts at one while next continues at four.
Break it, definitely: move n := 0 inside the returned function and see what happens to the output. That is the test of whether you understood what a closure actually remembers.
