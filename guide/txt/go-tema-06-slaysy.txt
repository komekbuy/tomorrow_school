ПОДГОТОВКА

Создай папку темы и модуль — набери руками, не копируй:

    mkdir slice1
    cd slice1
    go mod init slice1

Дальше весь код набирай в файл main.go в этой папке.
Запуск программы:

    go run .

------------------------------------------------------------------------------
КАК РАБОТАТЬ С ПРИМЕРАМИ
------------------------------------------------------------------------------

1. Набирай руками. Не копируй мышкой — пока печатаешь, глаз замечает
   скобки, точки и кавычки, которые при копировании проходят мимо.

2. ПЕРЕД запуском запиши, что программа выведет. Потом запусти и сверь
   с ответом под примером.

3. Не совпало — это и есть самое ценное место. Разберись, почему вышло
   именно так, и только потом иди дальше.

4. Заработало — сломай нарочно: убери кавычки, поменяй тип, поставь другой
   индекс. Прочитай, что скажет компилятор.

5. Каждый следующий пример отличается от предыдущего одним изменением —
   оно указано в заголовке. Найди его глазами до запуска.

------------------------------------------------------------------------------
ПРИМЕР 1.  Изменилось: первый, набирай целиком
------------------------------------------------------------------------------
package main

import "fmt"

func main() {
	arr := [3]int{10, 20, 30}
	fmt.Println(arr, len(arr))
}

ВЫВОД:
[10 20 30] 3

Массив: в квадратных скобках стоит размер, и он часть типа. Сломай: добавь arr = append(arr, 40) и прочитай ошибку — это и есть главное отличие темы.

------------------------------------------------------------------------------
ПРИМЕР 2.  Изменилось: из квадратных скобок убрали число
------------------------------------------------------------------------------
package main

import "fmt"

func main() {
	sl := []int{10, 20, 30}
	fmt.Println(sl, len(sl), cap(sl))
}

ВЫВОД:
[10 20 30] 3 3

Одно изменение — и это уже слайс. Значения те же, на экране почти то же самое, тип другой. cap пока равен len: место выделено ровно под три.

------------------------------------------------------------------------------
ПРИМЕР 3.  Изменилось: добавили ещё два способа создать слайс
------------------------------------------------------------------------------
package main

import "fmt"

func main() {
	var a []int
	b := []int{10, 20, 30}
	c := make([]int, 3)

	fmt.Println(a, len(a), a == nil)
	fmt.Println(b, len(b), b == nil)
	fmt.Println(c, len(c), c == nil)
}

ВЫВОД:
[] 0 true
[10 20 30] 3 false
[0 0 0] 3 false

a и c печатаются похоже, но это разные вещи: у a ноль элементов, у c — три нуля. Сломай: добавь a[0] = 1 и получишь падение — писать некуда.

------------------------------------------------------------------------------
ПРИМЕР 4.  Изменилось: появился append
------------------------------------------------------------------------------
package main

import "fmt"

func main() {
	a := []int{10, 20, 30}
	fmt.Println(a, len(a), cap(a))

	a = append(a, 40)
	fmt.Println(a, len(a), cap(a))
}

ВЫВОД:
[10 20 30] 3 3
[10 20 30 40] 4 6

len вырос на один, а cap сразу до шести: места не было, Go выделил новый кусок с запасом. Сломай: убери a =  перед append и прочитай ошибку.

------------------------------------------------------------------------------
ПРИМЕР 5.  Изменилось: append переехал в цикл
------------------------------------------------------------------------------
package main

import "fmt"

func main() {
	var a []int
	for i := 1; i <= 5; i++ {
		a = append(a, i*10)
		fmt.Println(a, len(a), cap(a))
	}
}

ВЫВОД:
[10] 1 1
[10 20] 2 2
[10 20 30] 3 4
[10 20 30 40] 4 4
[10 20 30 40 50] 5 8

len растёт по единице, cap — скачками 1, 2, 4, 8. Скачок происходит ровно тогда, когда len упёрся в cap. Это и есть переезд данных на новое место.

------------------------------------------------------------------------------
ПРИМЕР 6.  Изменилось: вместо добавления — перебор
------------------------------------------------------------------------------
package main

import "fmt"

func main() {
	a := []int{10, 20, 30, 40, 50}

	sum := 0
	for i := 0; i < len(a); i++ {
		sum += a[i]
	}
	fmt.Println(sum)

	for i, v := range a {
		fmt.Println(i, v)
	}
}

ВЫВОД:
150
0 10
1 20
2 30
3 40
4 50

Два способа пройти слайс. Сломай: поставь i <= len(a) в первом цикле — получишь panic: index out of range. Последний индекс это len(a)-1.

------------------------------------------------------------------------------
ПРИМЕР 7.  Изменилось: взяли куски слайса
------------------------------------------------------------------------------
package main

import "fmt"

func main() {
	a := []int{10, 20, 30, 40, 50}

	fmt.Println(a[1:3])
	fmt.Println(a[:3])
	fmt.Println(a[2:])
	fmt.Println(a[:])
	fmt.Println(a[2:2], len(a[2:2]))
}

ВЫВОД:
[20 30]
[10 20 30]
[30 40 50]
[10 20 30 40 50]
[] 0

a[1:3] даёт два элемента, а не три: правая граница не входит. Длина куска всегда конец - начало. Сломай: напиши a[1:9] и прочитай slice bounds out of range.

------------------------------------------------------------------------------
ПРИМЕР 8.  Изменилось: срез заменили обычным присваиванием
------------------------------------------------------------------------------
package main

import "fmt"

func main() {
	a := []int{10, 20, 30}

	b := a
	b[0] = 99
	fmt.Println(a, b)

	c := make([]int, len(a))
	copy(c, a)
	c[0] = 7
	fmt.Println(a, c)
}

ВЫВОД:
[99 20 30] [99 20 30]
[99 20 30] [7 20 30]

Правили b, а изменился и a — данные общие. С c такого нет: make выделил свой кусок, copy перенёс в него значения. Сломай: замени make([]int, len(a)) на var c []int — скопируется ноль элементов, и Go не пожалуется.

------------------------------------------------------------------------------
ПРИМЕР 9.  Изменилось: слайс ушёл в функцию
------------------------------------------------------------------------------
package main

import "fmt"

func setFirst(s []int) {
	s[0] = 99
}

func main() {
	a := []int{10, 20, 30}
	setFirst(a)
	fmt.Println(a, len(a))
}

ВЫВОД:
[99 20 30] 3

Функция ничего не возвращает, а a снаружи изменился. Заголовок скопировался, но указывает он на тот же кусок памяти — запись по индексу видна всем.

------------------------------------------------------------------------------
ПРИМЕР 10.  Изменилось: внутри функции вместо записи по индексу — append
------------------------------------------------------------------------------
package main

import "fmt"

func addItem(s []int) {
	s = append(s, 99)
	fmt.Println(s, len(s))
}

func main() {
	a := []int{10, 20, 30}
	addItem(a)
	fmt.Println(a, len(a))
}

ВЫВОД:
[10 20 30 99] 4
[10 20 30] 3

Внутри четыре элемента, снаружи три. append изменил длину у копии заголовка, а она осталась в функции. Сравни с прошлым примером — код почти тот же, поведение противоположное. Почини: верни результат и присвой его снаружи.
