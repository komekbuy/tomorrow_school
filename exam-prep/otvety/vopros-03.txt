  меняют регистр: "HelloWorld" превращается в "Hello_World".

  Дана строка, надо вернуть строку. Первым делом посмотри на ожидаемый вывод
  в задании: "HelloWorld" даёт "Hello_World", а не "hello_world". Значит
  регистр букв не меняется вообще, вся работа — вставить знак подчёркивания
  перед заглавными буквами. Это очень простое действие. Вторым делом
  посмотри, какие строки остались без изменений: "CAMELtoSnackCASE" и
  "hey2". Первая содержит две заглавные буквы подряд, вторая содержит цифру.
  Значит перед вставкой подчёркиваний надо проверить, является ли строка
  вообще правильным camelCase. Отсюда следует структура решения из двух
  отдельных этапов: сначала проверка, потом сборка. Смешивать их в один цикл
  нельзя, потому что нарушение может обнаружиться в конце строки, а к тому
  моменту ты уже что-то собрал. Условие даёт три запрета, и каждый
  превращается в одну проверку внутри первого цикла: символ не буква —
  выход; заглавная буква стоит последней — выход; заглавная буква и перед
  ней тоже заглавная — выход. Слово "выход" здесь значит return s, то есть
  вернуть исходную строку целиком, не изменив её. Если первый цикл дошёл до
  конца и ни разу не сработал, строка правильная, и можно собирать ответ. Во
  втором цикле идём по символам и перед каждой заглавной, кроме самой первой
  позиции, добавляем подчёркивание. Позицию ноль надо исключить отдельно,
  иначе "HelloWorld" даст "_Hello_World". Пустая строка обрабатывается сама
  собой: оба цикла не выполнятся ни разу, и вернётся пустая переменная
  result.

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: Подчёркивание ставится перед заглавной буквой
  только тогда, когда СЛЕДУЮЩАЯ за ней буква строчная. Поэтому в подряд
  идущих заглавных подчёркивание попадёт лишь перед последней из них. Если
  строка содержит что-то кроме букв — она возвращается без изменений.

    	return s >= 'A' && s <= 'Z'

    func CamelToSnakeCase(s string) string {
    	result := ""
    	if len(s) == 0 || !containOnlyAlphabet(s) {
    		return s
    	}
    	for i := 0; i < len(s); i++ {
    		if i != 0 && isUpper(rune(s[i])) && i+1 < len(s) && !isUpper(rune(s[i+1])) {
    			result += "_"
    			result += string(s[i])
    		} else if !isUpper(rune(s[i])) || (i == 0 && isUpper(rune(s[i]))) {
    			result += string(s[i])
    		} else {
    			return s
    		}
    	}
    	return result
    }

  * строка (string) — последовательность символов, например "hello"; в Go
  строку нельзя изменить, можно только собрать новую
  * байт (byte) — число от 0 до 255; каждая латинская буква хранится в
  строке как один байт с кодом этой буквы
  * s[i] — обращение к байту строки по номеру позиции; нумерация начинается
  с нуля
  * len(s) — встроенная функция, возвращающая длину строки в байтах
  * bool — тип из двух значений: true (истина) и false (ложь)
  * && — логическое «и»: всё выражение истинно, только если истинны обе
  части
  * ! — логическое «не»: превращает истину в ложь и наоборот
  * string(c) — преобразование байта в строку из одного символа, чтобы его
  можно было склеить с другой строкой
  * += — сокращение записи «прибавь к переменной»: result += "_" это то же
  самое, что result = result + "_"
  * return — немедленно завершает функцию и отдаёт указанное значение
  вызвавшему коду
  * руна (rune) — целое число, обозначающее один символ Юникода; для
  латиницы можно обойтись байтами, но для русских букв нужны именно руны,
  так как одна русская буква занимает два байта

  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Функция получает строку и сжимает в ней подряд идущие одинаковые символы.
  Каждая цепочка одинаковых символов заменяется на сам символ и число
  повторов. Если символ встретился подряд только один раз, число не пишется.
  Пустая строка возвращается как есть. Пример: AAABBC превращается в A3B2C,
  а ABCABC остаётся ABCABC, потому что там нет подряд идущих повторов.

  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Такое сжатие называется кодированием длин серий: строка идёт слева
  направо, и надо считать, сколько раз подряд повторился текущий символ.
  Значит нужны две вещи: проход по строке и счётчик повторов, который
  начинается с единицы, потому что первый символ это уже одно вхождение.
  Главный вопрос — КОГДА записывать результат. Записывать надо не на каждом
  шаге, а только когда цепочка кончилась: следующий символ отличается от
  текущего либо строка вообще закончилась. Отсюда условие: если следующий
  символ существует и равен текущему — увеличиваем счётчик и идём дальше;
  иначе дописываем символ, дописываем число (только если счётчик больше
  единицы) и сбрасываем счётчик обратно в единицу. Проверка i+1 < len(s)
  обязана стоять ПЕРВОЙ, иначе на последнем символе программа выйдет за
  границу строки и упадёт.

  Никакой особой обработки для пробелов и цифр не нужно: они такие же
  символы и сжимаются по тому же правилу — строка из пяти пробелов даёт
  пробел и цифру 5.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит strconv для этого задания разрешён: будь
  иначе, проверка не собралась бы. Если на экзамене список разрешённого
  окажется строже, перевод числа в строку пишется руками: берёшь остаток
  n%10 как последнюю цифру, прибавляешь к символу '0', приписываешь СЛЕВА к
  накопленной строке и делишь n на 10, пока не станет нулём.

    package piscine
    
    import (
    	"strconv"
    )
    
    func CountRepeats(s string) string {
    	if s == "" {
    		return s
    	}
    
    	var result string
    	var counter = 1
    
    	for i := 0; i < len(s); i++ {
    		if i+1 < len(s) && string(s[i]) == string(s[i+1]) {
    			counter++
    		} else {
    			result += string(s[i])
    			if counter > 1 {
    				result += strconv.Itoa(counter)
    			}
    			counter = 1
    		}
    	}
    	return result
    }

  Главная строка задания: «есть ли следующий символ и совпадает ли он с текущим».
  && — логическое «И», истинно, только когда истинны обе части.
  🔴 ПОРЯДОК ЧАСТЕЙ ЗДЕСЬ ОБЯЗАТЕЛЕН. Go вычисляет && слева направо и, если левая часть оказалась ложной, правую вообще не вычисляет (это называется короткое замыкание). Проверка i+1 < len(s) стоит первой именно поэтому: на последнем символе она ложна, и обращение s[i+1] просто не произойдёт. Поменяй части местами — на последнем символе программа полезет за конец строки и упадёт.
  s[i] даёт БАЙТ, а не строку. string(s[i]) превращает байт в строку из одного символа, чтобы сравнить две такие строки знаком ==.

			counter++
  Символы совпали — увеличиваем счётчик повторов на единицу. Ничего пока не печатаем: цепочка ещё не кончилась.

		} else {
  Иначе — либо следующий символ другой, либо текущий символ последний в строке. В обоих случаях цепочка одинаковых символов только что закончилась, пора её записать.
  🔴 Именно так в ответ попадает последний символ строки: на нём условие i+1 < len(s) ложно, значит выполняется else. Поэтому после цикла НЕ нужен дополнительный код «дописать хвост» — частая ошибка при самостоятельном решении.

			result += string(s[i])
  Дописываем сам символ в накопитель. += для строк означает «приклеить справа»: result = result + string(s[i]).

			if counter > 1 {
  Число пишем только если повторов больше одного — это прямое требование условия.

				result += strconv.Itoa(counter)
  strconv.Itoa переводит целое число в строку («integer to ASCII»): 3 превращается в "3", 12 — в "12". Без этого преобразования склеить число со строкой нельзя, Go не складывает разные типы.
  🔴 Не путай с string(counter) — такое преобразование дало бы символ с номером 3 в Unicode (невидимый управляющий), а не цифру.

			}
			counter = 1
  Сбрасываем счётчик перед следующей цепочкой. Один знак = — присваивание уже существующей переменной, не создание новой.
  🔴 Забыть этот сброс — самая частая ошибка в задании: счётчик поедет дальше и из "AABB" получится "A2B4".

		}
	}
  Закрываются else и цикл.

	return result
  Отдаём накопленный ответ.

}
  Конец функции.

Проверка на примерах из условия: "AAABBC" — три A подряд дают A3, две B дают B2, одинокая C даёт C, итог "A3B2C". "ABCABC" — подряд идущих повторов нет, счётчик всегда 1, числа не пишутся, итог "ABCABC".

------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Даны два числа, надо вернуть одно число. Начни с того, что в Go деление
  двух целых чисел даёт целое: 100 / 10 это 10, а 7 / 2 это 3, дробная часть
  просто отбрасывается. Это и есть главный приём задачи. Одно такое деление
  убирает у числа одну последнюю цифру в системе счисления с основанием
  base. Значит если делить в цикле, пока число не станет нулём, и считать
  количество делений, получится количество цифр. Проверь на примере из
  условия: 100 делим на 10 — получаем 10, это первое деление; 10 делим на 10
  — получаем 1, второе; 1 делим на 10 — получаем 0, третье. Итого 3, ровно
  как в задании. Дальше два дополнительных требования из условия, и порядок
  их важен. Проверку основания надо ставить самой первой, до всего
  остального: в примере DigitLen(100, -1) должно вернуть -1, и если сначала
  полезть в цикл, деление на -1 никогда не даст ноль и программа зациклится.
  Границы 2 и 36 включительные, поэтому условие ошибки записывается как base
  < 2 или base > 36. Смену знака ставим после проверки основания:
  отрицательное число никогда не станет больше нуля, цикл не выполнится и
  ответ будет неверным. Смена знака делается записью n = -n. Условие цикла
  обязано быть строго n > 0, а не n >= 0: при нуле деление ноля на что
  угодно даёт ноль, и цикл будет крутиться вечно.


------------------------------------------------------------------------------
  ГОТОВОЕ РЕШЕНИЕ
------------------------------------------------------------------------------
    package piscine
    
    func DigitLen(n, base int) int {
    
    	if base < 2 || base > 36 {
    		return -1
    	}
    
    	if n < 0 {
    		n = -n
    	}
    
    	count := 0
    	for n > 0 {
    		n /= base
    		count++
    	}
    	return count
    }

```go

		return -1
	}
```
  Проверка допустимости системы счисления. `||` — «или»: сработает при любом из двух условий.
  Границы включающие: 2 и 36 — допустимы, поэтому `< 2` и `> 36`, а не `<= 2` и `>= 36`.
  `return -1` — ранний выход: как только ввод плохой, дальше считать нечего.
  🔴 **Эта проверка обязана стоять первой.** При `base` равном 0 строка `n /= base` ниже уронила бы программу с `panic: integer divide by zero`. При `base` равном 1 деление на 1 ничего не уменьшает — цикл стал бы бесконечным. Обе беды закрыты одной проверкой в начале.
  🔴 Почему именно 36: цифрами в системах счисления служат `0-9` (10 штук) плюс `a-z` (26 штук), итого 36 разных знаков. Больше просто нечем записывать.

```go
	if n < 0 {
		n = -n
	}
```
  Отрицательное число заменяем на положительное: `-n` меняет знак.
  🔴 Здесь `=`, а не `:=`. `n` уже существует — это параметр функции, он объявлен в её заголовке. `:=` создало бы **новую** переменную с тем же именем, а старая осталась бы без изменений.
  🔴 Менять параметр внутри функции безопасно: в Go параметры передаются копией. Число у вызывающего кода не изменится.
  🔴 Без этой строки цикл ниже (`for n > 0`) для отрицательного `n` не выполнился бы ни разу, и функция вернула бы 0.

```go
	count := 0
```
  **Накопитель** — счётчик цифр. `:=` создаёт новую переменную и сразу кладёт в неё 0. Тип `int` Go выводит сам.

```go
	for n > 0 {
```
  🔴 Цикл только с условием, без счётчика и без шага — в Go это и есть «пока». Отдельного ключевого слова `while` в языке нет, его роль играет `for` с одним условием.
  Работает, **пока** число ещё не обнулилось.

```go
		n /= base
```
  `n /= base` это то же, что `n = n / base`.
  🔴 Деление **целочисленное**: остаток просто отбрасывается, округления нет. Для `n = 123, base = 10` получается 123 → 12 → 1 → 0. Ровно три шага, ровно три цифры.

```go
		count++
```
  Увеличить счётчик на 1. То же, что `count = count + 1`. В Go `++` это отдельная инструкция, а не выражение: `x := count++` написать нельзя.

```go

	return count
}
```
  Цикл закончился, когда `n` стало нулём. Возвращаем накопленное.
  🔴 `return` стоит **вне** цикла. Внутри он оборвал бы функцию после первого же деления.

### Проверь себя (проверено запуском)
- `DigitLen(0, 10)` → **0** 🔴 не 1. Цикл `for n > 0` при `n = 0` не выполняется ни разу. Ноль по этому коду имеет ноль цифр — знай про этот край.
- `DigitLen(9, 10)` → 1
- `DigitLen(10, 10)` → 2
- `DigitLen(-123, 10)` → 3 (знак снят, считаем как 123)
- `DigitLen(255, 16)` → 2 (это `ff`)
- `DigitLen(255, 2)` → 8 (это `11111111`)
- `DigitLen(5, 1)` → -1 (основание меньше 2)
- `DigitLen(5, 37)` → -1 (основание больше 36)

------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Поставить проверку основания не первой. При base равном -1 или 0 цикл
  деления никогда не закончится или программа упадёт с делением на ноль.
  Проверка обязана идти самой первой строкой.
  * Спутать включительные границы. Значения 2 и 36 разрешены, поэтому пишем
  base < 2 || base > 36, а не base <= 2 || base >= 36.
  * Написать условие цикла как n >= 0 — получится вечный цикл, потому что
  ноль делится на что угодно и остаётся нулём.
  * Забыть про отрицательное число: DigitLen(-100, 16) должно дать 2, а без
  строки n = -n цикл не выполнится ни разу и вернётся 0.
  * Менять знак до проверки основания — тогда DigitLen(-100, -16) может
  пойти в цикл вместо возврата -1.
  * Считать длину через превращение числа в строку — это не то, что просит
  условие, и для оснований кроме 10 даст неверный ответ.
  * Для n равного нулю такое решение возвращает 0, потому что ноль делить
  уже не нужно. Это буквальное прочтение условия: «сколько раз можно
  поделить, пока не станет нулём».

  Дана строка, надо вернуть кусок этой строки плюс символ перевода строки.
  Ключ к решению — понять, что первое слово задаётся двумя числами: номером
  символа, где оно начинается, и номером символа, где оно заканчивается.
  Найти эти два числа и вырезать кусок между ними. Смотрим на пример "hello
  .........  bye": ответ "hello", то есть работа заканчивается на первом же
  пробеле, всё остальное неважно. Смотрим на возможный ввод с ведущими
  пробелами: если строка начинается с пробелов, они не часть слова, их надо
  пропустить. Отсюда два последовательных цикла с одной общей
  переменной-счётчиком i. Первый цикл двигает i вперёд, пока стоит пробел —
  так мы находим начало слова. Запоминаем эту позицию в переменную start.
  Второй цикл продолжает двигать i вперёд от того же места, пока символ НЕ
  пробел — так мы находим конец слова. Важно, что i не сбрасывается между
  циклами, она продолжает движение. После этого s[start:i] даёт нужную
  подстроку. Осталось приклеить "\n", как требует условие. Проверь на пустой
  строке: len(s) равен нулю, оба цикла не выполнятся, start и i равны нулю,
  s[0:0] это пустая строка, ответ равен "\n" — ровно то, что показывает
  вывод в задании, где между двумя словами стоит пустая строка. В обоих
  циклах порядок частей условия критичен: сначала i < len(s), потом
  обращение к s[i]. Go проверяет условия слева направо и, если левая часть
  ложна, правую даже не смотрит — благодаря этому обращения к
  несуществующему символу не происходит.

  задания разрешены: будь иначе, проверка не собралась бы.

func FirstWord(s string) string {
  Объявление функции. Один параметр s типа string, возвращает тоже string. Имя с большой буквы — иначе тестовая программа из другого пакета её не увидит.

	words := strings.Fields(s)
  Fields режет строку на слова и сразу отдаёт список (срез строк). Срез — список элементов переменной длины.
  Она делает три вещи разом: режет по ЛЮБЫМ пробельным символам (пробел, таб, перевод строки), схлопывает подряд идущие пробелы, выбрасывает пустые куски по краям. Поэтому ведущие пробелы из условия обрабатываются сами собой, вручную их пропускать не надо.
  Знак := создаёт новую переменную words и сразу кладёт в неё результат; тип ([]string) Go выводит сам.

	res := "\n"
  Создаём переменную-ответ и заранее кладём в неё перевод строки.
  "\n" — это ОДИН символ, перевод строки, записанный двумя знаками внутри кавычек. Обратный слэш здесь означает «дальше идёт спецсимвол», это не буква n.
  Приём: ответ по умолчанию готов заранее. Если слов не найдётся, менять ничего не придётся — вернётся ровно "\n", как требует условие.

	if len(words) > 0 {
  Проверяем, нашлось ли хоть одно слово. len для среза даёт количество элементов (для строки давал бы число байтов).
  🔴 Именно так закрывается краевой случай: для пустой строки и для строки из одних пробелов Fields вернёт срез длиной 0, тело if не выполнится.
  🔴 Без этой проверки обращение words[0] к пустому срезу уронит программу с ошибкой «index out of range».

		res = words[0] + res
  Берём первое слово (нумерация элементов среза начинается с нуля, поэтому первое слово — это words[0]) и приклеиваем его СЛЕВА к тому, что уже лежит в res.
  Знак + для строк означает склейку. 🔴 Порядок частей важен: words[0] + res даёт "слово\n", а res + words[0] дало бы "\nслово" — перевод строки оказался бы спереди, и тест не прошёл бы.
  Один знак = — присваивание уже существующей переменной. 🔴 Если написать здесь := , внутри if создастся ВТОРАЯ переменная res, внешняя останется со старым значением, и функция вернёт просто "\n". Компилятор при этом ещё и откажется собирать код, потому что новая res нигде не используется.

	}
	return res
  Возвращаем ответ. Одна точка выхода на обе ветки: и когда слово нашлось, и когда нет.

}

------------------------------------------------------------------------------
  * s[start:i] — срез строки, подстрока с позиции start включительно до
  позиции i не включительно; если start равен i, получается пустая строка
  * '\n' — символ перевода строки, то есть переход на новую строку при
  печати
  * ' ' — одинарные кавычки задают один символ; двойные кавычки задают
  строку, это разные вещи
  * != — «не равно»
  * && — логическое «и»; Go проверяет части слева направо и не вычисляет
  правую часть, если левая уже ложна
  * len(s) — длина строки в байтах
  * fmt.Print — печать без добавления перевода строки, в отличие от
  fmt.Println, который перевод добавляет сам
  * байт — одно число, хранящее код символа; s[i] даёт именно байт, а не
  строку

------------------------------------------------------------------------------
  * Забыть приклеить "\n" к результату. Вывод не совпадёт, потому что
  тестовая программа использует fmt.Print, который сам перевод строки не
  добавляет.
  * Не пропустить ведущие пробелы — для строки " hi" вернётся пустое слово
  вместо "hi".
  * Обнулить i перед вторым циклом. Тогда второй цикл снова упрётся в
  ведущие пробелы и результат будет пустым.
  * Написать условие цикла как s[i] != ' ' && i < len(s) — на строке,

  * Для пустой строки надо вернуть "\n", а не "". В примере из задания между
  двумя словами печатается пустая строка — это и есть результат вызова на
  пустой строке.
  * Считать разделителем что-то кроме пробела. По условию разделитель только

  * Использовать strings.Split или другие пакеты — на Piscine это обычно

  сначала написать проверку «делится на 2», то шестёрка попадёт в неё и
  вернёт "fish", хотя правильный ответ "fish and chips" — до совместной
  проверки выполнение уже не дойдёт. Общее правило: более частный случай
  ставится раньше более общего. Дальше идут одиночные проверки на 2 и на 3,
  а в самом конце, без всякого if, возвращается ошибка "error: non

  из условий не сработало. Тексты строк надо копировать из задания буква в
  букву вместе с двоеточием и пробелами — проверяющая программа сравнивает
  их точно.

------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Даны два неотрицательных числа, надо вернуть их наибольший общий делитель.
  Перебирать все числа от меньшего вниз и искать первое, которое делит оба,
  можно, но это медленно и на больших числах не пройдёт по времени.
  Правильный приём — алгоритм Евклида, и его стоит просто запомнить, потому
  что вывести его на экзамене с нуля тяжело. Идея алгоритма: наибольший
  общий делитель пары чисел не меняется, если большее число заменить на
  остаток от его деления на меньшее. То есть НОД(42, 10) равен НОД(10, 2),
  потому что 42 % 10 = 2, а тот равен НОД(2, 0). Как только второе число
  становится нулём, ответом является первое. Отсюда цикл: пока b не ноль,
  одновременно присваиваем a значение b, а b значение остатка a%b. Слово
  «одновременно» здесь принципиально: если делать это в два шага без
  временной переменной, первое присваивание испортит a, и второе посчитает
  остаток от нового значения. В Go есть множественное присваивание a, b = b,
  a%b, которое сначала вычисляет обе правые части, а потом записывает их —
  именно то, что нужно. Отдельно надо обработать нули: условие прямо требует
  вернуть 0, если хоть один аргумент ноль, и эту проверку надо поставить до
  цикла, иначе при b равном нулю функция вернёт a, а при a равном нулю
  вернёт b. Ещё одна причина не выбирать вариант алгоритма Евклида через
  вычитание: тип uint не умеет хранить отрицательные числа, и выражение a -
  b при a меньше b даёт не минус, а гигантское число, из-за чего цикл
  ломается. Остаток от деления такой проблемы не имеет.

    package piscine
    
    func Gcd(a, b uint) uint {
    	for a != b {
    		if a > b {
    			a -= b
    		} else {
    			b -= a
    		}
    	}
    	return a
    }

package piscine
  Первая строка любого файла на Go — имя пакета, в который этот файл попадёт.
  Все задания-функции в школе собираются в пакет piscine, поэтому строка всегда ровно такая.
  Блока import здесь нет вообще — задание решается голым языком, ни один пакет не нужен.

func Gcd(a, b uint) uint {
  Объявление функции. Имя с большой буквы — Gcd — значит, что функция экспортируемая,
  то есть её видно из другого пакета (из тестовой программы школы). Если написать gcd
  с маленькой буквы, тест её просто не найдёт.
  Запись (a, b uint) — сокращение для (a uint, b uint): два параметра одного типа
  перечисляются через запятую, а тип пишется один раз в конце.
  uint — беззнаковое целое, то есть число без минуса: 0, 1, 2, ...
  Последнее uint перед фигурной скобкой — тип возвращаемого значения.
  🔴 a и b внутри функции — это КОПИИ чисел вызывающего. Мы их дальше портим
  вычитанием, и это нормально: у вызывающего его переменные не изменятся.

	for a != b {
  Цикл с одним условием — аналог while в других языках. В Go слово while отсутствует,
  цикл всегда пишется словом for; если после for стоит одно условие, тело крутится,
  пока условие истинно.
  Условие a != b читается «пока a не равно b». Значит выход из цикла произойдёт
  ровно в тот момент, когда числа сравняются.
  Идея алгоритма (алгоритм Евклида вычитанием): наибольший общий делитель двух чисел
  не меняется, если из большего вычесть меньшее. Повторяем вычитание, числа уменьшаются,
  в конце оба становятся равны — и это равное значение и есть НОД.

		if a > b {
  Проверяем, какое из чисел больше. Это не украшение, а обязательная часть.
  🔴 Тип uint не умеет хранить отрицательные числа. Если вычесть из меньшего большее,
  результат не станет минусовым — он «завернётся» в огромное число (около 18 квинтиллионов).
  Цикл после этого никогда не закончится. Поэтому вычитаем всегда только из большего.

			a -= b
  Сокращённая запись для a = a - b. Уменьшаем большее число на меньшее.
  Знак = здесь внутри -= — это присваивание в уже существующую переменную,
  новую переменную мы не создаём (для создания был бы знак :=).

		} else {
  Иначе — то есть когда a не больше b. Внутри цикла a != b, значит в этой ветке
  b строго больше a.

			b -= a
  То же самое, только уменьшаем b. Симметричный случай.

		}
  Конец if/else.

	}
  Конец цикла. Управление возвращается к проверке a != b.

	return a
  Сюда попадаем только когда цикл закончился, а он заканчивается только при a == b.
  Значит вернуть можно любое из двух — эталон возвращает a. Написать return b
  было бы столь же верно.

}
  Конец функции.

🔴 ЛОВУШКА ПРО НОЛЬ. По условию, если одно из чисел ноль, ответ 0. Этот эталон
выдаёт 0 только когда ОБА числа нули: тогда a != b ложно сразу, цикл не крутится,
возвращается a, то есть 0. А если ноль только один (например a = 0, b = 5), то
вычитание нуля ничего не меняет: b -= a оставляет b равным 5, a остаётся 0,
условие a != b вечно истинно — программа зависает. Значит тесты школы такой пары
не подают. Знай это ограничение, но на экзамене пиши как в эталоне: бот сравнивает
ответ именно с этим кодом.

🔴 Вторая ловушка: не путай != и !==. В Go знака !== не существует, неравенство —
это ровно два символа !=.

ПРОГОН НА ПАЛЬЦАХ, Gcd(12, 18):
  a=12 b=18 → a не больше b → b = 18-12 = 6
  a=12 b=6  → a больше b   → a = 12-6 = 6
  a=6  b=6  → a == b, цикл кончился → вернули 6. Это и есть НОД(12,18).


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * uint — беззнаковое целое число, то есть только ноль и положительные
  значения; отрицательное значение в него записать нельзя
  * наибольший общий делитель (НОД) — самое большое число, на которое оба
  заданных числа делятся без остатка
  * алгоритм Евклида — способ найти НОД: большее число заменяется остатком
  от деления на меньшее, и так до появления нуля
  * % — остаток от деления; 42%10 равно 2
  * a, b = b, a%b — множественное присваивание: сначала вычисляются все
  выражения справа, потом результаты записываются в переменные слева
  * переполнение (underflow) — ситуация, когда из меньшего беззнакового
  числа вычитают большее и вместо отрицательного значения получается очень
  большое положительное
  * != — «не равно»
  * рекурсия — приём, при котором функция вызывает саму себя; этот же
  алгоритм можно записать рекурсивно как return Gcd(b, a%b) с выходом при b
  равном нулю, но версия с циклом надёжнее и не расходует стек


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Забыть проверку на ноль до цикла. Условие явно требует вернуть 0, а
  обычный алгоритм Евклида при Gcd(5, 0) вернул бы 5.
  * Использовать вариант алгоритма через вычитание. У типа uint выражение a
  - b при a меньше b даёт огромное число вместо отрицательного, и цикл либо
  зависает, либо даёт мусор.
  * Разбить множественное присваивание на две строки без временной
  переменной: сначала a = b, потом b = a%b. Второе выражение возьмёт уже
  изменённое a, и ответ будет неверным.
  * Взять остаток без проверки на ноль в делителе — деление на ноль вызывает
  аварийное завершение программы.
  * Написать условие цикла как for b > 0 — для uint это работает одинаково,
  но при переходе на int сломается для отрицательных; привычка писать b != 0
  надёжнее.
  * Возвращать b вместо a после цикла — в момент выхода из цикла b равно
  нулю, и ответ всегда будет 0.
  * Перебирать делители от меньшего числа вниз: на больших входных числах
  решение не уложится по времени.

  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано: одна строка. Надо: новая строка ровно такой же длины, где каждый
  символ пересчитан по формуле. Первое, что надо заметить — длина строки в
  формуле одна на все символы, она не меняется по ходу цикла, поэтому её
  считают один раз до цикла и кладут в переменную. Второе — что вообще такое
  «код символа»: в Go запись s[i] даёт байт, то есть число от 0 до 255, и
  для латиницы это ровно ASCII-код. Третье — зачем нужен остаток от деления
  на 127: сложение кода и длины может дать число больше 126, а таблица ASCII
  заканчивается на 127, поэтому остаток загоняет результат обратно в
  диапазон 0–126. Четвёртое — почему нужна поправка на 33: коды 0–31 это
  управляющие символы, они не видны на экране, и условие велит прибавить к
  ним 33, после чего получится код от 33 до 64, то есть обычный видимый
  знак. Порядок действий строго такой: сначала сложение, потом остаток, и
  только потом проверка на непечатаемость — иначе результат не сойдётся.
  Проверить свою формулу проще всего на первом примере из README: буква 'A'
  имеет код 65, длина строки 1, 65+1=66, 66 % 127 = 66, а код 66 — это буква
  'B', и именно 'B' напечатано в README. Дальше остаётся стандартный приём:
  пустая строка-накопитель, цикл по индексам, дописывание символа в
  накопитель, возврат накопителя.

    package piscine
    
    func HashCode(dec string) string {
    	size := len(dec)
    	hashed := ""
    	for _, char := range dec {
    		hash := (int(char) + size) % 127
    		if hash < 32 || hash > 126 {
    			hash += 33
    		}
    		hashed += string(hash)
    	}
    	return hashed
    }

  переменной длины; здесь список из кусков-слов).
  Fields делает три вещи разом, и именно поэтому её берут в этой задаче:
  1) режет по ЛЮБЫМ пробельным символам — пробел, табуляция, перевод строки;
  2) схлопывает подряд идущие пробелы, пустых кусков между ними не создаёт;
  3) выбрасывает пробелы по краям строки.

  на строке "a  b" вернёт три куска, один из них пустой. Split здесь дал бы неверный
  ответ на строках с двойными пробелами и с пробелами по краям.

	if len(words) > 0 {
  len(words) — длина среза, то есть сколько слов получилось.

  🔴 Эта проверка обязательна. Если строка пустая или состоит из одних пробелов,
  Fields вернёт срез длиной 0, и обращение к words[-1] на следующей строке уронило бы

  строка из одного символа «перевод строки», как требует условие.

  Задача делится на два независимых куска: разрезать строку на слова и
  решить про каждое слово, годится ли оно. Разрезание берёт на себя

  проверке слова. Слово годится, если ВСЕ его символы буквы. Но есть
  послабление: один знак препинания в самом конце разрешён, поэтому перед
  проверкой мы смотрим на последний символ, и если он входит в набор .,!?;:
  — временно отрезаем его. Дальше проверяем два условия: первый символ буква
  и каждый символ буква. Сравнивать длины надо по рунам, а не по байтам,
  потому что буква с диакритикой занимает два байта и посчиталась бы за две.
  Наконец, знак сравнения строго больше, а не больше или равно — именно это
  делает так, что при одинаковой длине выигрывает первое встреченное слово.
  Отдельно запомни неочевидное следствие правил: слово symbols! годится,
  потому что восклицательный знак стоит в конце и отбрасывается, а слово
  word1 не годится, потому что цифра стоит внутри.

    package piscine
    
    import (
    	"strings"
    	"unicode"
    )
    
    func isValidWord(word string) bool {
    	if word == "" {
    		return false
    	}
    
    	last := rune(word[len(word)-1])
    	if strings.ContainsRune(".,!?;:", last) {
    		word = word[:len(word)-1]
    		if word == "" {
    			return false
    		}
    	}
    
    	firstRune := []rune(word)[0]
    	if !unicode.IsLetter(firstRune) {
    		return false
    	}
    
    	for _, r := range word {
    		if !unicode.IsLetter(r) {
    			return false
    		}
    	}
    
    	return true
    }
    
    func LongestWord(s string) string {
    	words := strings.Fields(s)
    	longest := ""
    
    	for _, w := range words {
    		if isValidWord(w) {
    			if len([]rune(w)) > len([]rune(longest)) {
    				longest = w
    			}
    		}
    	}
    
    	return longest
    }

func isValidWord(word string) bool {
  Вспомогательная функция-проверка. Имя с маленькой буквы — значит она видна только внутри пакета piscine, наружу не экспортируется. Возвращает bool: true — слово правильное, false — нет.
  Выносить проверку в отдельную функцию удобно: главная функция остаётся короткой.

	if word == "" {
		return false
	}
  Ранний выход. Пустая строка правильным словом не считается, и одновременно эта проверка защищает следующую строку от обращения к последнему символу несуществующей строки — без неё программа упала бы.

	last := rune(word[len(word)-1])
  Разбираем изнутри: len(word) — длина в БАЙТАХ; последний элемент имеет индекс len-1, потому что нумерация с нуля; word[i] даёт байт (тип byte); rune(...) превращает байт в руну, чтобы сравнивать с символами.
  := создаёт новую переменную last и кладёт туда результат.
  🔴 Это байт, а не символ. Для латиницы и знаков препинания это одно и то же, но если слово оканчивается многобайтовым символом, last будет обрывком. Эталон школы такой случай не покрывает — и этого достаточно.

	if strings.ContainsRune(".,!?;:", last) {
  ContainsRune проверяет, есть ли руна last среди символов строки ".,!?;:" — это и есть весь разрешённый список знаков препинания: точка, запятая, восклицательный, вопросительный, точка с запятой, двоеточие.
  Приём: вместо шести сравнений через || знаки собраны в одну строку и ищутся одним вызовом.

		word = word[:len(word)-1]
  Срез строки: берём с начала (нулевой индекс можно не писать) до len-1 НЕ включая — правая граница в Go всегда не включается. Так отрезается последний символ, знак препинания.
  🔴 Знак = , а не := — переписываем ту же переменную. И это ЛОКАЛЬНАЯ копия параметра: у вызывающей стороны исходное слово не меняется. Поэтому в ответ LongestWord попадёт слово ВМЕСТЕ со знаком препинания, как и требует условие.

		if word == "" {
			return false
		}
  Проверка после отрезания. Если слово состояло из одного знака препинания, теперь оно пустое — правильным словом это не считается. Заодно защищает следующую строку от обращения к нулевому элементу пустого среза.

	}
  Конец if со знаком препинания. Если слово оканчивалось буквой, весь этот блок пропускается.

	firstRune := []rune(word)[0]
  []rune(word) превращает строку в срез рун, [0] берёт первый элемент — первый символ слова.
  Тут же новая переменная firstRune через :=.

	if !unicode.IsLetter(firstRune) {
		return false
	}
  IsLetter отвечает, буква ли это; ! переворачивает; значит выходим с false, если слово начинается не с буквы.
  🔴 Честно: эта проверка избыточна — цикл ниже всё равно проверит каждый символ, включая первый. Но она есть в эталоне школы, и на экзамене нужен именно эталонный код, поэтому пиши как есть.

	for _, r := range word {
  Заголовок цикла. range по СТРОКЕ отдаёт две вещи: байтовый индекс и руну. Индекс не нужен — на его месте _ (пустышка). r — очередной символ слова (уже без отрезанного знака препинания).

		if !unicode.IsLetter(r) {
			return false
		}
  Как только встретился символ, не являющийся буквой — цифра, дефис, любой спецсимвол — сразу выходим с false.
  🔴 Ранний выход через return прямо из цикла: не нужно ни флага, ни break, ни доведения цикла до конца. Это самый короткий способ сказать «условие нарушено».

	}

	return true
  Досюда доходим, только если ни один return false не сработал: строка не пуста, знак препинания (если был) отрезан, все оставшиеся символы — буквы.

}
  Конец isValidWord.

func LongestWord(s string) string {
  Главная функция задания. Имя с БОЛЬШОЙ буквы — значит она экспортируется, то есть видна из других пакетов; тестовая программа вызывает именно её. Прототип обязан совпадать с заданием до символа.

	words := strings.Fields(s)
  Fields режет строку на слова и сразу отдаёт срез строк. Она делает три вещи разом: режет по ЛЮБЫМ пробельным символам (пробел, табуляция, перевод строки), схлопывает подряд идущие пробелы, выбрасывает пустые куски по краям. Именно поэтому здесь Fields, а не Split.

	longest := ""
  Накопитель ответа, стартует пустой строкой. Это одновременно и правильный ответ по умолчанию: если правильных слов нет, вернётся пустая строка, как требует условие.

	for _, w := range words {
  Цикл по срезу слов. range по срезу отдаёт индекс и значение; индекс не нужен, поэтому _. w — очередное слово.

		if isValidWord(w) {
  Отсеиваем неправильные слова. Если функция вернула false — слово пропускается целиком.

			if len([]rune(w)) > len([]rune(longest)) {
  Сравниваем длины в СИМВОЛАХ, а не в байтах: []rune(...) сначала превращает строку в срез рун, и только потом len считает элементы.
  🔴 Знак строго больше, а не >= . Это и обеспечивает требование «при равной длине побеждает то, что встретилось раньше»: при равенстве замена не происходит, и в longest остаётся более раннее слово. Поставишь >= — победит последнее, и задание не зачтётся.
  🔴 Длина считается ПОСЛЕ проверки, у исходного w — то есть вместе со знаком препинания, если он был.

				longest = w
  Запоминаем новое самое длинное слово. Знак = , не := — переменная уже существует; := создало бы новую внутри if и ответ всегда оставался бы пустым.

			}
		}
	}
  Закрываются оба if и цикл.

	return longest
  Отдаём накопленный ответ: либо самое длинное правильное слово, либо пустую строку.

}

------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * strings.Fields — режет строку на слова по пробелам, схлопывая подряд
  идущие пробелы и выбрасывая пустые куски
  * руна (rune) — один символ текста; в отличие от байта, руна вмещает и
  не-латиницу, где символ занимает несколько байтов
  * []rune(s) — перевод строки в список символов; нужен, чтобы считать длину
  в символах, а не в байтах
  * unicode.IsLetter — отвечает, является ли символ буквой любого алфавита
  * strings.ContainsRune(набор, символ) — есть ли такой символ в наборе
  * word[:n] — кусок строки с начала до позиции n, не включая саму n
  * range по строке — перебор символов целиком, а не байтов


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Считать длину через len(w) вместо len([]rune(w)) — для слов с
  не-латиницей длина окажется завышена, и выиграет не то слово.
  * Написать >= вместо > — тогда при равной длине победит последнее слово, а
  надо первое.
  * Считать, что слово с восклицательным знаком не годится. Годится:
  symbols! проходит, знак в конце разрешён.
  * Считать, что word1 годится. Нет: цифра внутри делает слово негодным
  целиком.
  * Отрезать знак препинания дважды или в цикле — по правилу разрешён ровно
  один хвостовой знак.
  * Забыть, что строка из одних пробелов и строка из одних спецсимволов
  должны дать пустой ответ.

  Написать функцию RepeatAlpha, которая берёт строку и возвращает новую, где
  каждая буква латинского алфавита повторена столько раз, каков её
  порядковый номер в алфавите: 'a' один раз, 'b' два, 'e' пять, 'z' двадцать
  шесть. Для заглавных букв номер считается по той же шкале от 'A', и
  повторяется именно заглавная буква: 'C' превращается в 'CCC'. Все
  остальные символы — цифры, пробелы, знаки препинания — переписываются один
  раз без изменений.

  Дано: строка. Надо: новая строка. Вся задача сводится к одному вопросу,
  который надо задать про каждый символ: сколько раз его напечатать. Для
  всего, что не буква, ответ всегда один раз — поэтому логично завести
  переменную n и сразу положить в неё 1, а менять только для букв. Дальше
  нужен способ узнать номер буквы в алфавите, не заводя таблицу из 26 строк.
  Ключ в том, что в ASCII латинские буквы идут подряд: 'a' 97, 'b' 98, ...
  'z' 122. Значит разность кода буквы и кода 'a' даёт смещение от начала
  алфавита: у 'a' это 0, у 'b' 1, у 'z' 25. Номер в алфавите на единицу
  больше смещения, поэтому формула — разность плюс один. Для заглавных то же
  самое, но отсчёт от 'A' (код 65), потому что заглавные лежат в другом
  месте таблицы. Из той же непрерывности следует, как проверить «это буква»:
  достаточно сравнить код с границами диапазона, то есть c >= 'a' && c <=
  'z' или c >= 'A' && c <= 'Z'. Дальше — два вложенных цикла: внешний идёт
  по символам входной строки, внутренний дописывает текущий символ n раз в
  накопитель. Пустая строка обрабатывается сама собой: внешний цикл не
  выполнится ни разу, вернётся пустая строка. Функция ничего не печатает —
  она возвращает строку, печатает её тестовая программа.

  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого

    package piscine
    
    import "unicode"
    
    func RepeatAlpha(s string) string {
    	res := ""
    	for _, r := range s {
    		if unicode.IsLetter(r) {
    			rep := unicode.ToLower(r) - 'a' + 1
    			for i := 0; i < int(rep); i++ {
    				res += string(r)
    			}
    		} else {
    			res += string(r)
    		}
    	}
    	return res
    }

package piscine
  Имя пакета. Задание — функция, значит пакет учебный, main тут нет.

import "unicode"
  Подключается пакет unicode. Здесь однострочная форма импорта — она используется,
  когда пакет один. Из пакета нужны две функции: IsLetter и ToLower.
  Раз эталон школы использует unicode, для этого задания пакет разрешён.

func RepeatAlpha(s string) string {
  Объявление функции. Имя с большой буквы — чтобы её было видно снаружи пакета.
  Один параметр s типа string, возвращает тоже string.

	res := ""
  Создаём накопитель — переменную, в которую будем постепенно доклеивать результат.
  Стартовое значение — пустая строка "" (двойные кавычки, ноль символов внутри).
  Знак := создаёт новую переменную и сразу задаёт значение; тип string выведен из "".
  🔴 Накопитель обязан быть объявлен ДО цикла. Объявишь внутри — на каждом витке он
  будет создаваться заново и всё накопленное потеряется.

	for _, r := range s {
  Цикл по символам строки. range по строке даёт два значения: номер байта и саму руну.
  _ выбрасывает номер — он в задаче не нужен.
  r — очередной символ как руна (руна это один символ целиком, хранится как число —
  код символа).
  🔴 Именно range даёт целые символы. Если бы шли по s[i] в обычном for, получали бы
  байты, и любой не-ASCII символ развалился бы на куски.

		if unicode.IsLetter(r) {
  unicode.IsLetter отвечает true, если руна — буква, и false для цифры, пробела,
  запятой, скобки и прочего. Это развилка задачи: буквы размножаем, остальное
  переписываем один раз.

			rep := unicode.ToLower(r) - 'a' + 1
  Считаем, сколько раз повторять букву.
  unicode.ToLower(r) приводит букву к строчной — чтобы 'C' и 'c' считались одинаково.
  'a' в одинарных кавычках — это не текст, а ЧИСЛО, код буквы a (97). Буквы в таблице
  кодов идут подряд: a=97, b=98, c=99 ... z=122.
  Поэтому вычитание (буква - 'a') даёт порядковый номер буквы, начиная с нуля:
  для 'a' будет 0, для 'b' — 1, для 'c' — 2.
  Прибавляем 1, чтобы нумерация пошла с единицы: 'a' один раз, 'b' два, 'c' три,
  'z' двадцать шесть. Ровно как требует условие.
  Знак := создаёт новую переменную rep. Её тип — rune (то же самое, что int32), потому
  что ToLower возвращает руну.

			for i := 0; i < int(rep); i++ {
  Внутренний цикл: повторить действие rep раз.
  i := 0 создаёт счётчик, i < int(rep) — условие продолжения, i++ — прибавить единицу.
  Счётчик идёт 0, 1, ... , rep-1 — это ровно rep повторений.
  🔴 int(rep) — обязательная переделка типа. i имеет тип int, rep имеет тип rune. В Go
  нельзя сравнивать значения разных числовых типов напрямую: запись i < rep не
  скомпилируется с ошибкой «mismatched types int and rune». Поэтому rep явно
  переводят в int.

				res += string(r)
  Доклеиваем символ к накопителю. Запись res += x — короткая форма res = res + x.
  string(r) превращает руну в строку из одного символа.
  🔴 Клеим именно r — ИСХОДНУЮ руну, а не приведённую к нижнему регистру. Регистр
  используется только для подсчёта количества. Поэтому 'C' даёт "CCC", а не "ccc".
  Напишешь тут string(unicode.ToLower(r)) — заглавные буквы сломаются.
  🔴 string(r), где r — руна, даёт символ с этим кодом. Не путай с strconv.Itoa:
  string(65) это "A", а не "65".

			}
  Конец внутреннего цикла повторений.

  Написать программу, которая получает ровно 3 аргумента командной строки:
  строку, символ который надо найти, и символ на который его надо заменить.
  Программа печатает строку, где все вхождения искомого символа заменены, и
  в конце ставит перевод строки. Если аргументов не ровно 3 — программа не
  печатает вообще ничего. Если искомого символа в строке нет — строка
  печатается как есть, тоже с переводом строки в конце.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Это не функция, а программа: значит нужен пакет main, функция main как
  точка входа, и аргументы берутся из os.Args. Первое, что надо знать про
  os.Args: нулевой элемент там — путь к самой программе, а то, что ввёл
  пользователь, начинается с первого. Поэтому сразу берём os.Args[1:] и
  дальше считаем аргументы обычным образом: их должно быть ровно три.
  Условие явно говорит: если аргументов не три — не печатать ничего, значит
  первым делом идёт проверка и выход из main через return, без всякого
  вывода. Второй и третий аргументы названы буквами, то есть строками из
  одного символа, поэтому их длину тоже стоит проверить: если там пусто или
  несколько символов, обращение к нулевому байту может уронить программу.
  Дальше нужен приём замены: пройти по первой строке символ за символом и
  для каждого решить, что дописать в результат — заменяющий символ, если
  совпало с искомым, или исходный символ, если не совпало. Отдельная
  проверка «содержится ли искомый символ в строке» не нужна вообще: если он
  ни разу не совпадёт, результат сам собой окажется равен исходной строке, а
  перевод строки печатается в любом случае — это ровно то поведение,
  которого требует условие. В конце делаем один вывод целиком, а не печать
  на каждый символ: так меньше кода и меньше шансов забыть перевод строки.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

  🔴 Здесь нет else. Если аргументов не три, тело просто не выполняется и программа молчит — ровно как требует условие.
  🔴 Сравни с hiddenp: там обратный приём — «если не столько, return». Оба варианта верны, но смешивать их в одном коде нельзя.

		fmt.Println(strings.Map(func(r rune) rune {
  Эту строку надо читать изнутри наружу.
  strings.Map(функция, строка) прогоняет КАЖДУЮ руну строки через переданную функцию и собирает новую строку из того, что функция вернула.
  func(r rune) rune {...} — безымянная функция, написанная прямо внутри вызова. Принимает руну, возвращает руну. Её тело идёт следующими строками.

			if r == []rune(os.Args[2])[0] {
  []rune(os.Args[2]) — строка превращается в срез рун, то есть в список символов; [0] берёт из него первый символ.
  Так делают, потому что аргумент приходит строкой, а сравнивать надо с руной r.
  🔴 Берётся только ПЕРВЫЙ символ аргумента. Запуск с "ab" в качестве искомого заменит только 'a'.
  🔴 Если второй аргумент — пустая строка, срез пустой и [0] уронит программу с index out of range. Эталон от этого не защищается.
  🔴 Преобразование стоит ВНУТРИ функции, значит выполняется заново для каждого символа строки. Медленно, но правильно.

				return []rune(os.Args[3])[0]
			}
  Совпало — возвращаем первый символ третьего аргумента. Именно эта руна попадёт в результат вместо исходной.

  Не совпало — символ возвращается как был, то есть остаётся на месте.
  🔴 Этот return обязателен: функция должна вернуть руну на ЛЮБОМ пути. Он стоит после if, а не в else — работает так же.
  🔴 Если бы здесь вернули отрицательное число, символ бы просто исчез: Map выбрасывает из результата все отрицательные значения.

  иначе взятие куска выйдет за границу и программа упадёт. Дальше два цикла:
  по списку приставок и по списку окончаний, и в каждом выход по break на
  первом же совпадении — именно поэтому берётся первая подходящая, а не
  самая длинная. Начальные значения обеих переменных — пустые строки, тогда
  случай «не нашлось» обрабатывается сам собой, без отдельной ветки.
  Последнее и самое коварное — формат вывода. Строка склеивается ровно так:
  слово prefix, двоеточие, пробел, найденная приставка, затем запятая, затем
  пробел, слово suffix, двоеточие, пробел, найденное окончание. Один лишний
  или пропущенный пробел — и бот не засчитает, поэтому формат надо
  переписать из условия символ в символ.

    package piscine
    
    func WordAnatomy(initialWord string, prefixArray []string, suffixArray []string) string {
    	matchedPrefix := ""
    	matchedSuffix := ""
    
    	for _, prefix := range prefixArray {
    		if hasPrefix(initialWord, prefix) {
    			matchedPrefix = prefix
    			break
    		}
    	}
    	for _, suffix := range suffixArray {
    		if hasSuffix(initialWord, suffix) {
    			matchedSuffix = suffix
    			break
    		}
    	}
    
    	return "prefix: " + matchedPrefix + "," + " suffix: " + matchedSuffix
    }
    
    func hasPrefix(initialWord, prefix string) bool {
    	if len(prefix) > len(initialWord) {
    		return false
    	}
    
    	return initialWord[:len(prefix)] == prefix
    }
    
    func hasSuffix(initialWord, suffix string) bool {
    	if len(suffix) > len(initialWord) {
    		return false
    	}
    
    	return initialWord[len(initialWord)-len(suffix):] == suffix
    }

package piscine

func WordAnatomy(initialWord string, prefixArray []string, suffixArray []string) string {
  Прототип с тремя параметрами: само слово и два списка строк. []string означает
  «список строк». Порядок параметров менять нельзя.

	matchedPrefix := ""
	matchedSuffix := ""
  Что нашли. Пустые строки как стартовые значения: если ничего не найдётся,
  они так и попадут в ответ, и отдельная ветка «не нашлось» не нужна.

	for _, prefix := range prefixArray {
		if hasPrefix(initialWord, prefix) {
			matchedPrefix = prefix
			break
		}
	}
  Идём по списку приставок по порядку. Подчёркивание значит, что номер позиции не нужен.
  break прерывает цикл на ПЕРВОМ совпадении — поэтому из списка un, re, in, im, dis, pre
  для слова unbelievable выбирается un, даже если бы подходило что-то ещё.

	for _, suffix := range suffixArray {
		if hasSuffix(initialWord, suffix) {
			matchedSuffix = suffix
			break
		}
	}
  То же самое для окончаний. Обрати внимание на слово preorder: в списке окончаний
  er стоит раньше, чем ing, поэтому найдётся er.

	return "prefix: " + matchedPrefix + "," + " suffix: " + matchedSuffix
}
  Склейка ответа. Записана нарочно по кускам, чтобы было видно каждый пробел:
  "prefix: " с пробелом на конце, затем приставка, затем запятая, затем " suffix: "
  с пробелом в начале и на конце, затем окончание. Итог для unbelievable выглядит так:
  prefix: un, suffix: able

func hasPrefix(initialWord, prefix string) bool {
	if len(prefix) > len(initialWord) { return false }
  Если приставка длиннее слова — совпасть не может, и брать кусок нельзя: вылетит за границу.
  Эта проверка обязательна, без неё программа падает.

	return initialWord[:len(prefix)] == prefix
}
  Берём начало слова ровно такой же длины, как приставка, и сравниваем целиком.

func hasSuffix(initialWord, suffix string) bool {
	if len(suffix) > len(initialWord) { return false }
	return initialWord[len(initialWord)-len(suffix):] == suffix
}
  Зеркально: берём конец слова. Начало куска считается как длина слова минус длина
  окончания, а двоеточие без второго числа значит «до самого конца».


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * приставка (prefix) — начало слова; проверяется сравнением первых
  символов
  * окончание (suffix) — конец слова; проверяется сравнением последних
  символов
  * []string — список строк переменной длины
  * break — немедленный выход из цикла; именно он даёт «первое совпадение, а
  не самое длинное»
  * s[:n] — кусок строки с начала до позиции n; s[n:] — кусок от позиции n
  до конца
  * склейка строк (конкатенация) — соединение строк знаком +


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Промахнуться с пробелами в итоговой строке. Формат ровно такой: "prefix:
  X, suffix: Y". Лишний пробел перед запятой или его отсутствие после —
  задача не засчитана.
  * Забыть проверку длины в hasPrefix и hasSuffix — программа упадёт, как
  только в списке окажется элемент длиннее слова.
  * Искать самое длинное совпадение вместо первого. Берётся первое по
  порядку списка, за это отвечает break.
  * Считать, что если приставки нет, надо что-то написать вместо неё. Нет:
  место просто остаётся пустым, как в happiness -> "prefix: , suffix: ness".
  * Слово convert не имеет ни приставки, ни окончания из списков — ответ
  "prefix: , suffix: " с двумя пустыми местами. Это нормальный результат, а
  не ошибка.
