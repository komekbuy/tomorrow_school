  Дано: одна строка. Надо: другая строка, и она ВСЕГДА заканчивается
  переводом строки — в тестовой программе стоит fmt.Print, а не Println, но
  в ожидаемом выводе каждая строка помечена символом $ от cat -e. Сначала
  отсекаются два особых случая, и их порядок важен: пустая строка возвращает
  "\n", строка короче 5 символов возвращает "Invalid Input\n". Пустая строка
  тоже короче пяти, поэтому её проверка обязана стоять первой, иначе вместо
  "\n" вернётся "Invalid Input\n". Дальше главное наблюдение: пробелы
  исходной строки в задаче вообще не считаются символами — из "This is a
  short sentence" получается "Thisi ashor sente ce", все старые пробелы
  исчезли, а появившиеся пробелы это уже новые разделители. Значит удобно за
  один проход собрать вспомогательную строку без пробелов и дальше работать
  только с ней, потому что в ней нумерация идёт подряд без дыр. Второе
  наблюдение: период задачи равен шести, а не пяти. Проверь на примере
  "abcdefghijklmnopqrstuwxyz": печатаются abcde, выбрасывается f, печатаются
  ghijk, выбрасывается l — расстояние между выброшенными f и l ровно 6.
  Отсюда правило по индексу i (счёт с нуля) в очищенной строке: если i%6 ==
  5, символ пропускаем, иначе добавляем в ответ. Разделитель ставится перед
  началом новой группы, то есть когда i%6 == 0, но не перед самой первой
  группой — поэтому дополнительное условие i != 0. Пробел ставится именно
  ПЕРЕД группой, а не после неё, потому что при варианте «после» на границе
  строки останется лишний висячий пробел: у "abcdef" ответ должен быть
  "abcde", а не "abcde ". В конце к собранному результату приклеивается
  "\n".

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: Каждый шестой символ по счёту не пропускается, а
  ЗАМЕНЯЕТСЯ пробелом — сам символ теряется. Пробел ставится даже тогда,
  когда шестой символ оказался последним: тогда строка заканчивается
  пробелом перед переводом строки.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

    package piscine
    
    import "strings"
    
    func FifthAndSkip(str string) string {
    	if str == "" {
    		return "\n"
    	}
    	if len(str) < 5 {
    		return "Invalid Input\n"
    	}
    	s := strings.ReplaceAll(str, " ", "")
    	var _str strings.Builder
    	j := 0
    	for _, char := range s {
    		if j == 5 {
    			_str.WriteRune(rune(' '))
    			j = 0
    		} else {
    			_str.WriteRune(rune(char))
    			j++
    		}
    	}
    	_str.WriteRune('\n')
    	return _str.String()
    }

package piscine
  Библиотека, а не программа. Функцию будет вызывать чужой файл, func main здесь нет.

import "strings"
  Из пакета strings нужны две вещи: функция ReplaceAll и тип Builder. Раз эталон школы его использует — для этого задания strings разрешён.

func FifthAndSkip(str string) string {
  Один параметр str типа string, возвращает string. Функция ничего не печатает — только возвращает готовую строку.

	if str == "" {
		return "\n"
	}
  Первый краевой случай из условия: пустая строка на входе — вернуть только перевод строки.
  🔴 "\n" — это НЕ пустая строка. Вернуть "" — уже другой ответ, тест не пройдёт.

	if len(str) < 5 {
		return "Invalid Input\n"
	}
  Второй краевой случай: дословный текст из условия плюс перевод строки.
  🔴 len у строки считает БАЙТЫ, а не символы. Для латиницы это одно и то же, для кириллицы — нет.
  🔴 Проверка идёт по ИСХОДНОЙ строке, до удаления пробелов. Поэтому "a b c" (5 байт) её проходит, хотя букв всего 3, и эталон вернёт "abc\n", а не "Invalid Input\n". Порядок двух проверок и удаления пробелов менять нельзя.

	s := strings.ReplaceAll(str, " ", "")
  Все пробелы заменяются на пустую строку, то есть просто выбрасываются.
  := создаёт новую переменную s и кладёт в неё результат. Сама str не меняется — строки в Go неизменяемы, любая «замена» делает новую строку.

	var _str strings.Builder
  Builder — накопитель строки: в него дописывают куски, а в конце забирают готовую строку одним вызовом.
  var без значения даёт нулевое значение, и у Builder оно рабочее сразу — ни make, ни new не нужны.
  Имя _str — просто имя переменной, подчёркивание в начале в Go ничего не означает.
  Зачем накопитель: запись вида s += ... в цикле каждый раз создаёт новую строку целиком, а Builder дописывает в один буфер.

	j := 0
  Счётчик символов, уже положенных в ТЕКУЩУЮ группу. Создаётся через := со значением 0.

	for _, char := range s {
  Идём по строке БЕЗ пробелов. range по строке даёт индекс байта и руну; индекс выброшен через _, char — очередной символ.

		if j == 5 {
  В текущей группе уже лежат 5 символов — значит char, который пришёл сейчас, и есть шестой.

			_str.WriteRune(rune(' '))
  Вместо шестого символа в накопитель пишется пробел.
  🔴 Главный момент задания: шестой символ НЕ записывается никуда, он выбрасывается. Пробел ставится ВМЕСТО него, а не в дополнение к нему.
  rune(' ') — преобразование лишнее, ' ' в одинарных кавычках и так руна. Ошибкой это не является, код компилируется.

			j = 0
  Счётчик обнуляется — начинается новая группа.
  🔴 Здесь = , а не := — переменная j уже существует. := создало бы НОВУЮ j, видимую только внутри этого if, а внешняя навсегда осталась бы равна 5.

		} else {
			_str.WriteRune(rune(char))
  Обычный символ дописывается в накопитель. rune(char) — снова лишнее преобразование, char уже руна.

			j++
  Символ в группу положен — счётчик растёт. j++ это краткая запись j = j + 1.
  🔴 j++ стоит ТОЛЬКО в else. В ветке if его нет, поэтому после записи пробела счёт новой группы начинается с нуля, а не с единицы.
		}
	}

	_str.WriteRune('\n')
  Перевод строки дописывается в конец, как требует условие. Одинарные кавычки — руна.

	return _str.String()
}
  String() превращает накопитель в обычную строку, и она возвращается.

  Прогон: "Hello World!" → пробел убран → "HelloWorld!" (11 символов)
    H e l l o — записаны, j дорос до 5
    W — j == 5, пишется пробел, буква W ВЫБРАСЫВАЕТСЯ, j = 0
    o r l d ! — записаны, j = 5
    конец строки, дописывается \n
    результат "Hello orld!\n"
  🔴 Если после удаления пробелов длина кратна 6, последним действием цикла окажется запись пробела: "abcdefghijkl" даёт "abcde ghijk \n" — с пробелом перед \n. Эталон ведёт себя именно так, «чинить» это не надо.


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * строка (string) — последовательность байт, менять её символы напрямую
  нельзя, можно только собирать новую
  * байт — число от 0 до 255; str[i] возвращает именно байт, а не символ
  * руна (rune) — один полноценный символ Unicode, псевдоним для int32;
  нужна, когда во входе есть кириллица или эмодзи, здесь вход только ASCII,
  поэтому хватает байт
  * len(str) — количество байт в строке
  * % (остаток от деления) — 13%6 равно 1; используется, чтобы вычислить
  позицию внутри повторяющейся группы
  * continue — оператор, который обрывает текущий шаг цикла и переходит к
  следующему
  * += для строк — создаёт новую строку, склеенную из старой и добавленной;
  исходная строка при этом не меняется
  * string(b) — преобразование байта b в строку длиной один символ
  * ':=' — короткое объявление: создаёт переменную и определяет её тип по
  значению справа
  * '\n' — один символ перевода строки, код 10; cat -e показывает его как
  знак $ в конце строки


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Проверка «меньше 5» делается по ИСХОДНОЙ строке, до удаления пробелов.
  Для "1234" длина 4, ответ Invalid Input.
  * Проверку на пустую строку надо писать ПЕРЕД проверкой длины: пустая
  строка тоже короче 5, и при обратном порядке вернётся Invalid Input вместо
  "\n".
  * Период цикла шесть, а не пять. Если написать i%5, шестой символ не
  выбросится и получится "abcde fghij" вместо "abcde ghijk".
  * Пробел ставить ПЕРЕД группой (i%6 == 0), а не после пятого символа. При
  варианте «после» у входа "abcdef" получится "abcde " с висячим пробелом на
  конце.
  * Условие i != 0 обязательно, иначе результат начнётся с пробела.
  * "\n" нужен во всех трёх ветках возврата, включая "Invalid Input\n".
  * Разделитель — ровно один пробел, не запятая, не два пробела.
  * str[i] это байт: clean += str[i] не скомпилируется, нужна обёртка
  string(...).
  * Для входа с не-ASCII символами (кириллица) байтовый перебор разрежет
  символ пополам. Тогда пишут r := []rune(str) и работают с r; на тестах
  этого задания вход латинский.
  * Строка из одних пробелов длиной 5 и более даёт "\n" — условие такой
  случай не описывает, падать здесь нельзя.
  * Пропускать шестой символ вместо замены на пробел — потеряется
  разделитель.
  * Не поставить пробел, если шестой символ оказался последним в строке.
  Эталон его ставит.

  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано: строка. Надо: строка плюс "\n" в конце в любом случае. Первое, что
  надо понять — это задача не про числа, а про работу с текстом. Посмотри на
  пример: "1.20525856" даёт "120525856", то есть просто удалили точку.
  Умножать на 10^n в виде float нельзя категорически: float64 не хранит
  длинные дроби точно и вернёт мусор в младших разрядах, а ответ должен
  совпадать посимвольно. План из пяти шагов: отсеять пустую строку,
  проверить что перед нами вообще число, отсеять случаи «нет точки» и «после
  точки одни нули», склеить строку без точки и убрать ведущие нули, вернуть
  с переводом строки. Проверка «это число» делается одним проходом по
  символам: точка — запомнить её позицию, но если точка уже была, значит их
  две и это не число; цифра — увеличить счётчик цифр; любой другой символ —
  сразу возврат строки как есть. Именно на этом ловится пример из условия
  "-0.0f00d00": на букве f. Минус выносится отдельной переменной ДО прохода,
  чтобы он не мешал ни проверке цифр, ни последующему срезанию ведущих нулей
  — иначе первым символом окажется '-' и вся логика поедет. Ведущие нули
  появляются потому, что склейка "0" и "1" даёт "01", а ответ должен быть
  "1": идём слева и пропускаем нули, но обязательно останавливаемся, оставив
  хотя бы один символ, иначе из "0" получится пустая строка. Проверки идут
  строго в этом порядке: пустая строка, валидность, «нет точки»/«одни нули»,
  и только потом склейка — каждая следующая опирается на то, что предыдущие
  уже отработали.

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: Считается количество символов после первой
  точки, затем строка разбирается как дробное число и умножается на десять в
  этой степени, результат печатается целым. Порядок именно такой: дробные
  числа хранятся приблизительно, и любой другой способ убрать точку даст
  расхождение в последней цифре. Если строка числом не является —
  возвращается как есть.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

    package piscine
    
    import (
    	"math"
    	"strconv"
    )
    
    func NotDecimal(dec string) string {
    	j := -1
    	n := 0
    	if len(dec) == 0 {
    		return "\n"
    	}
    	for i := 0; i < len(dec); i++ {
    		if j == -1 && dec[i] == '.' {
    			j++
    		} else if j == 0 {
    			n++
    		}
    	}
    	s, err := strconv.ParseFloat(dec, 64)
    	if err == nil {
    		return strconv.Itoa(int(s*math.Pow(10, float64(n)))) + "\n"
    	}
    	return (dec + "\n")
    }

func NotDecimal(dec string) string {
  Объявление функции. Один параметр dec типа string, возвращает тоже string. Имя с большой буквы — обязательно: в Go имя с заглавной видно из других пакетов, с маленькой — нет, а тест лежит в другом пакете.

Дальше в коде встретится просто = — это присваивание в уже существующую переменную. j принимает всего два значения за всю жизнь: -1 (точки не было) и 0 (точка была).

	n := 0
  Накопитель — переменная, в которой копится результат подсчёта. Здесь считаем, сколько символов идёт после точки.

	if len(dec) == 0 {
  len у строки — количество байт в ней. Ноль означает пустую строку.

		return "\n"
  Ранний выход — выйти из функции сразу, не доходя до остального кода. 🔴 Возвращается не пустая строка "", а именно перевод строки. Разница между «вернуть пусто» и «вернуть перевод строки» на проверке видна.

	}
  Конец блока if.

	for i := 0; i < len(dec); i++ {
  Классический цикл со счётчиком, в заголовке три части через точку с запятой:
  i := 0 — счётчик создаётся один раз перед началом;
  i < len(dec) — пока условие верно, тело крутится;
  i++ — после каждого прохода прибавить 1.
  Знак < , а не <= , потому что индексы идут от 0 до len-1. При <= последний оборот полез бы за конец строки и программа упала бы с ошибкой index out of range.

		if j == -1 && dec[i] == '.' {
  dec[i] — байт под индексом i (тип byte, то есть просто число — код символа). '.' в ОДИНАРНЫХ кавычках — байт-константа точки; в двойных было бы строкой, и сравнение не скомпилировалось бы.
  && — «и», причём ленивое: если левая часть ложна, правая даже не вычисляется. Порядок частей здесь смысловой: сначала проверяем «точки ещё не было», поэтому ветка срабатывает ровно на ПЕРВОЙ точке в строке.

			j++
  j становится 0. С этого момента первая ветка не сработает никогда: j больше не равен -1.

		} else if j == 0 {
  Сюда попадаем только когда точка уже пройдена — значит текущий символ стоит ПОСЛЕ точки.

			n++
  Плюс один к счётчику символов после точки. 🔴 Считаются ВСЕ символы после точки, а не только цифры. Если точки в строке нет вообще, j навсегда остаётся -1, и n остаётся 0.

		}
	}
  Закрытие if/else и цикла.

	s, err := strconv.ParseFloat(dec, 64)
  ParseFloat пытается прочитать ВСЮ строку как дробное число; 64 — разрядность результата (тип float64).
  Функция возвращает ДВА значения сразу: число и ошибку. Слева через запятую перечислены две переменные, := объявляет обе разом. Если строка не число, s будет 0, а err — не nil.

	if err == nil {
  nil — «ничего/пусто». err == nil означает «ошибки не было», то есть строку удалось прочитать как число.

		return strconv.Itoa(int(s*math.Pow(10, float64(n)))) + "\n"
  Читается изнутри наружу, четыре действия подряд:
  float64(n) — перевод типа: n у нас int, а math.Pow принимает только float64;
  math.Pow(10, ...) — десять в степени n, то есть сдвиг запятой на n позиций вправо;
  s * это — само число без точки, но всё ещё дробного типа;
  int(...) — перевод в целое, и именно здесь пропадают ведущие нули: "0.1" → 1.0 → 1;
  strconv.Itoa(...) — целое в строку;
  + "\n" — приклеивается обязательный перевод строки.
  🔴 int() ОТБРАСЫВАЕТ дробную часть, а не округляет. Проверено запуском эталона: "0.29" даёт "28", потому что 0.29*100 в двоичной дробной арифметике равно 28.999999999999996. "1.005" даёт "1004". Это поведение самого эталона школы — знать про него надо, чинить в ответе не надо.

	}
	return (dec + "\n")
  Сюда доходим, только если ParseFloat дал ошибку, то есть строка вообще не число: возвращаем её саму плюс перевод строки. Круглые скобки вокруг выражения ничего не меняют, это стиль автора.

}

------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Никакого strconv.ParseFloat и никакой арифметики с float64: 1.20525856 в
  двоичном float хранится неточно, ответ разъедется в младших разрядах.
  Задача чисто строковая.
  * Ведущие нули обязательно срезать: "0.1" после удаления точки даёт "01",
  а ожидается "1". Первая же строка теста провалится, если забыть.
  * При срезании нулей оставлять минимум один символ (условие cut <
  len(num)-1), иначе из "0" выйдет пустая строка.
  * Минус хранить отдельной переменной. Если оставить его внутри числа,
  проверка «это цифра» его отбракует, а срезание нулей поедет по позициям.
  * Если строка не число — возвращать её ЦЕЛИКОМ и без изменений:
  "-0.0f00d00" даёт "-0.0f00d00\n", а не пустоту и не ошибку.
  * Пустой аргумент — только "\n", без слов и без пробела.
  * Проверку на пустоту писать до обращения dec[0], иначе программа упадёт с
  index out of range.
  * Две точки ("1.2.3") — не число. Один флаг dot и проверка «уже была» это
  ловят.
  * Точка в конце ("12.") — цифр после неё нет, возвращаем как есть.
  * "5.0" возвращается целиком как "5.0", а не как "5" и не как "50":
  условие в этой же фразе для варианта «нет точки» под словами return the
  number понимает сам аргумент.
  * Плюс в начале ('+') знаком не считается, "+1.5" вернётся как есть. В
  условии и примерах плюса нет, ориентируемся только на минус.
  * В README блок Usage напечатан без префикса пакета (NotDecimal("0.1")),
  хотя импортируется piscine. Для проверки пиши piscine.NotDecimal — так
  сделано в рабочем тесте.
  * Убирать точку перестановкой символов — на некоторых числах последняя
  цифра разойдётся с эталоном.
  * Считать после точки только цифры. Эталон считает ВСЕ символы после
  первой точки.

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Функция получает два среза целых чисел и возвращает новый срез. Оба
  исходных читаются с конца к началу. Пока один срез длиннее другого, в
  ответ идут только его «лишние» элементы. Как только остатки сравнялись по
  длине, элементы берутся по очереди: сначала из первого среза, потом из
  второго, и так до конца. Если срезы были равной длины с самого начала,
  чередование начинается с первого среза.

------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано: два среза чисел. Надо: новый срез. Условие сформулировано мутно,
  поэтому логика вытаскивается из примеров. Разбери второй пример:
  RevConcatAlternate([1 2 3], [4 5 6 7 8 9]) даёт [9 8 7 3 6 2 5 1 4].
  Второй срез длиннее первого на 3 элемента, и первые три числа ответа — 9,
  8, 7 — это как раз его хвост, взятый с конца. Дальше идёт 3, 6, 2, 5, 1, 4
  — чередование по одному числу с конца каждого среза, начиная с первого.
  Третий пример зеркальный: [1 2 3 9 8] длиннее на 3, ответ начинается с 8,
  9, 3 — последние три элемента первого среза, тоже с конца. Четвёртый
  пример проверяет крайность: второй срез пустой, значит «лишними»
  оказываются все три элемента первого, ответ [3 2 1] и никакого
  чередования. Отсюда приём: заводим два курсора i и j, каждый стоит на
  последнем элементе своего среза, то есть на len минус один. Пока i больше
  j, первый срез длиннее — сливаем из него по одному. Пока j больше i,
  длиннее второй — сливаем из него. Сработает ровно один из этих двух
  циклов, второй просто не выполнится ни разу, и заранее знать какой не
  нужно. После них i и j обязательно равны, и остаётся один общий цикл: пока
  i не ушёл ниже нуля, берём slice1[i], потом slice2[j], и сдвигаем оба
  курсора влево. Сравнивать надо именно i с j, а не длины срезов: курсор
  одновременно и позиция, и мера остатка, поэтому одна проверка закрывает
  обе задачи и код не разъезжается по ходу выравнивания.

    package piscine
    
    func RevConcatAlternate(slice1, slice2 []int) []int {
    	len1 := len(slice1)
    	len2 := len(slice2)
    	maxLen := len1
    	result := make([]int, 0, len1+len2)
    
    	if len2 > maxLen {
    		maxLen = len2
    	}
    
    	for i := maxLen; i >= 0; i-- {
    		if i < len1 {
    			result = append(result, slice1[i])
    		}
    		if i < len2 {
    			result = append(result, slice2[i])
    		}
    	}
    
    	return result
    }

package piscine
  Имя пакета. Задание — функция, пакет учебный. Импортов нет вообще: нужны только

func RevConcatAlternate(slice1, slice2 []int) []int {
  Объявление функции. Два параметра, оба типа []int (срез целых чисел — список чисел
  переменной длины). Запись slice1, slice2 []int — сокращение: когда типы у соседних
  параметров совпадают, тип пишут один раз, в конце.
  После скобок []int — тип результата: функция возвращает новый срез целых.

	len1 := len(slice1)
  len(slice1) — количество элементов в первом срезе. Сохраняем в переменную len1,
  чтобы дальше не вызывать len каждый раз. := создаёт новую переменную типа int.

	len2 := len(slice2)
  То же для второго среза.

	maxLen := len1
  Заготовка под «длину более длинного среза». Пока просто кладём туда len1, потом
  при необходимости поправим. Это стандартный приём поиска максимума: взять первое
  значение как текущего лидера и сравнить с остальными.

	result := make([]int, 0, len1+len2)
  Создаём срез для ответа. make для среза принимает три вещи: тип, длину и ёмкость.
  []int — тип, 0 — ДЛИНА (в срезе пока нет ни одного элемента), len1+len2 — ЁМКОСТЬ
  (заранее выделенное место под столько чисел, чтобы append не перевыделял память по
  ходу дела). Ёмкость влияет только на скорость, на результат — нет.

  🔴 Частая ошибка: написать make([]int, len1+len2) с двумя аргументами. Тогда длина
  сразу станет len1+len2, срез будет забит нулями, а append добавит настоящие числа
  ПОСЛЕ этих нулей. Ответ окажется вдвое длиннее и начнётся с нулей. Ноль на месте
  длины — принципиален.

	if len2 > maxLen {
  Сравниваем: второй срез длиннее текущего лидера?

		maxLen = len2
  Да — записываем в maxLen длину второго. Здесь именно = , а не := : переменная maxLen
  уже существует, мы меняем её значение. Написал бы := — создалась бы новая переменная
  внутри блока if, снаружи её никто не увидит, и maxLen остался бы прежним.

	}
  Конец if. После этого блока в maxLen лежит длина более длинного из двух срезов.

	for i := maxLen; i >= 0; i-- {
  Цикл, идущий НАЗАД. Три части заголовка: i := maxLen — старт с максимальной длины;
  i >= 0 — работаем, пока номер не ушёл ниже нуля; i-- — уменьшать на единицу
  на каждом витке.
  Именно обратный ход даёт «читать срезы с конца», как требует условие.

  🔴 Условие i >= 0, а не i > 0. Элемент с номером 0 — первый элемент среза, его тоже
  надо взять. С i > 0 первые элементы обоих срезов потерялись бы.

  🔴 Первый виток холостой. Максимальный существующий номер в срезе — это длина минус
  один, поэтому при i равном maxLen оба условия ниже ложны и в ответ ничего не идёт.
  Паники нет ровно потому, что обращения к срезу защищены проверками. Фактически
  работа начинается со следующего витка, i = maxLen-1.

		if i < len1 {
  Проверка «номер i существует в первом срезе». Допустимые номера — от 0 до len1-1,
  то есть строго меньше len1.
  🔴 Эта проверка обязательна. Пока i больше длины короткого среза, обращение к нему
  уронило бы программу с паникой «index out of range». Именно эти два if и реализуют
  правило «пока один срез длиннее, берём только его лишние элементы».

			result = append(result, slice1[i])
  append добавляет элемент в конец среза и возвращает НОВЫЙ срез. Результат обязательно
  присваивается обратно в result: append не меняет переменную сам, он только возвращает
  значение. Запись просто append(result, x) без присваивания бесполезна — Go даже
  откажется компилировать такую строку как «значение не использовано».
  slice1[i] — элемент первого среза под номером i.

		}
  Конец первого if.

		if i < len2 {
  То же самое для второго среза: существует ли номер i в нём.

			result = append(result, slice2[i])
  Добавляем элемент второго среза.

		}
  Конец второго if.

  🔴 ПОРЯДОК ДВУХ БЛОКОВ — это и есть «чередование». На одном витке сначала уходит
  элемент slice1, потом элемент slice2. Поменяешь блоки местами — чередование
  перевернётся, и на равных длинах ответ начнётся не с того среза.

	}
  Конец цикла.

	return result
  Возвращаем накопленный срез.

	}
  Конец функции.

КАК ЭТО РАБОТАЕТ НА ПРИМЕРЕ
  slice1 = [1 2 3], slice2 = [7 10 15 3 6]. len1=3, len2=5, maxLen=5.
  i=5: 5<3 нет, 5<5 нет  → ничего (тот самый холостой виток)
  i=4: 4<3 нет, 4<5 да   → 6
  i=3: 3<3 нет, 3<5 да   → 3
  i=2: да → 3,  да → 15
  i=1: да → 2,  да → 10
  i=0: да → 1,  да → 7
  Ответ: [6 3 3 15 2 10 1 7]. Сначала вышли два «лишних» элемента длинного среза,
  потом пошло чередование, начиная с первого среза.

ЛОВУШКИ ЗАДАНИЯ
  🔴 make с ДЛИНОЙ 0 и ёмкостью len1+len2 — три аргумента, не два.
  🔴 i >= 0, иначе теряются нулевые элементы.
  🔴 Оба if обязательны — они и защита от паники, и реализация правила про «лишние»
     элементы длинного среза.
  🔴 append всегда с присваиванием обратно.
  🔴 На равных длинах чередование начинается с slice1 — это следствие того, что блок
     slice1 стоит выше.

------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Порядок частей ответа строгий: сначала «лишние» элементы более длинного
  среза, только потом чередование. Перепутаешь — все примеры кроме равных
  длин развалятся.
  * В чередовании первым идёт элемент ПЕРВОГО среза. Это отдельно прописано
  в условии и проверяется первым же примером.
  * Идти надо С КОНЦА (от len-1 к 0), а не с начала — в названии задачи
  слово Rev.
  * Нужны оба выравнивающих цикла: заранее неизвестно, какой срез длиннее.
  Сработает ровно один, второй не выполнится ни разу.
  * Пустой срез даёт len-1 равное -1, и никакой индексации при этом не
  происходит: третий цикл стартует только при i равном j и i >= 0. Обращения
  slice2[-1] не будет.
  * append без присваивания (просто append(result, x)) молча ничего не
  добавляет — компилятор такое пропустит только внутри выражения, но логика
  сломается.
  * Не сравнивать len(slice1) с len(slice2) один раз до циклов и не пытаться
  считать «разницу» отдельной переменной — сравнение курсоров i и j делает
  то же самое короче и не рассыпается по ходу.
  * Функция не должна менять входные срезы, только читать из них.
  * Оба среза пустые — ответ [] (пустой срез), не паника.

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Функция получает срез строк и одно или несколько целых чисел, возвращает
  часть этого среза. Если число одно — кусок начинается с этой позиции и
  идёт до конца среза. Если чисел два — от первой позиции до второй, причём
  вторая позиция не включается. Числа могут быть отрицательными: тогда к ним
  прибавляется длина среза, то есть позиция отсчитывается от конца. Если
  после пересчёта начало оказалось правее конца, функция возвращает nil.

------------------------------------------------------------------------------
  Дано: срез строк a и переменное количество целых чисел. Надо: кусок этого
  среза. Первое, что надо увидеть — в Go уже есть готовая операция
  a[start:end], которая и есть «взять кусок». Значит вся задача сводится к
  тому, чтобы правильно посчитать start и end и не дать программе упасть.
  Запись nbrs ...int означает переменное число аргументов; внутри функции
  nbrs — это обычный срез int, у него есть len и индексы, так что «сколько
  чисел передали» узнаётся через len(nbrs). Значение по умолчанию для конца
  — это len(a), поэтому end сразу инициализируется длиной среза и
  перезаписывается только если чисел передали больше одного. Отрицательные
  разбираются на примере: Slice(a, -3) на срезе из 5 элементов даёт
  последние три, то есть start равен -3 плюс 5, то есть 2. Отсюда правило:
  отрицательное число просто складываем с длиной. То же для конца: Slice(a,
  -2, -1) даёт start 3 и end 4, а a[3:4] это ровно ["package"] — совпадает с
  примером из README. Дальше защита от падения: Go прекращает работу
  программы (panic), если индексы вышли за границы или начало больше конца,
  а компилятор такое не ловит — проверять надо руками. Поэтому start,
  оставшийся отрицательным даже после прибавления длины, поднимаем до нуля,
  а end, превысивший длину, опускаем до len(a). Последний пример особенно
  важен: Slice(a, 2, 0) обязан напечататься как []string(nil), а не
  []string{} — глагол %#v эти два случая различает, значит в этой ветке надо
  написать именно return nil.

    func ifNegative(a []string, n int) int {
    	if n < 0 {
    		n = len(a) + n
    	}
    
    	if n < 0 {
    		n = 0
    	} else if n > len(a) {
    		n = len(a)
    	}
    
    	return n
    }
    
    func Slice(a []string, nbr ...int) []string {
    	if len(nbr) == 0 {
    		return a
    	}
    
    	first := nbr[0]
    	if len(nbr) == 1 {
    		if first < 0 {
    			first = len(a) + first
    			if first < 0 {
    				return a
    			}
    		}
    		return a[first:]
    	}
    	second := nbr[1]
    
    	first = ifNegative(a, first)
    	second = ifNegative(a, second)
    
    	if first > second {
    		return nil
    	}
    
    	return a[first:second]
    }

ПРОГОН ПРИМЕРОВ (срез из 5 элементов, len(a) = 5)
Slice(a, 2) → одно число, положительное → a[2:] → элементы 2, 3, 4.
Slice(a, -2) → одно число → first = 5 + (-2) = 3 → a[3:] → элементы 3, 4.
Slice(a, -10) → first = 5 + (-10) = -5, всё ещё меньше нуля → return a, весь срез.
Slice(a, 1, 3) → ifNegative ничего не меняет → a[1:3] → элементы 1, 2.
Slice(a, -3, -1) → first = 2, second = 4 → a[2:4] → элементы 2, 3.
Slice(a, 4, 1) → first = 4, second = 1, начало правее конца → nil.
Slice(a) → чисел нет → весь срез.


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * срез (slice) — список значений одного типа переменной длины; []string
  это срез строк
  * variadic-параметр (nbrs ...int) — приём произвольного количества
  аргументов одного типа; внутри функции это обычный срез
  * a[start:end] — взятие куска среза, полуоткрытый интервал: start входит,
  end не входит
  * полуоткрытый интервал — правая граница исключена, поэтому a[2:4]
  содержит два элемента
  * len(a) — количество элементов; допустимый индекс для взятия куска — от 0
  до len(a) включительно
  * nil — «пустая ссылка», для среза означает отсутствие данных; печатается
  через %#v как []string(nil)
  * panic — аварийная остановка программы во время выполнения, например при
  выходе индекса за границы
  * %#v — формат печати, показывающий значение в виде исходного кода Go и
  различающий nil и пустой срез
  * подсрез разделяет память с исходным срезом: изменение элемента
  результата изменит и оригинал


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Последняя строка ожидаемого вывода []string(nil), а не []string{}.
  Значит в «плохом» случае надо написать именно return nil. Если вернуть
  []string{}, %#v напечатает []string{} и тест не сойдётся.
  * Правая граница не включается: a[2:4] это элементы с индексами 2 и 3, то
  есть "ascii" и "package".
  * Отрицательные числа надо ПРИБАВЛЯТЬ к длине, а не вычитать: start = -3 +
  5 = 2.
  * a[start:end] при start больше end это паника во время выполнения, а не
  ошибка компиляции. Проверку пишешь сам.
  * len(nbrs) надо проверить до обращения nbrs[0], иначе вызов без чисел
  уронит программу.
  * Прототип в README напечатан как nbrs... int — gofmt перепишет в nbrs
  ...int, три точки перед типом. Так и должно быть, школа проверяет
  отформатированный код.
  * Конец по умолчанию — len(a), а не len(a)-1: последний элемент попадёт в
  кусок только если правая граница равна длине.
  * Третье и последующие числа игнорируются — условие ничего про них не
  говорит, лишь бы не падало.
  * Возвращается кусок того же массива, а не копия. Условие прямо говорит
  the returned slice is part of the received one, так что копировать не
  надо.
