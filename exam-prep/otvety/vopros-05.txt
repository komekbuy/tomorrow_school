  Программа получает ровно один аргумент командной строки — положительное
  целое число. Надо сложить все простые числа, которые меньше или равны
  этому числу, и напечатать сумму, а после неё перевод строки. Если
  аргументов не ровно один, либо аргумент не является положительным числом,
  программа печатает 0 и перевод строки. Пример: для 5 ответ 10 (2+3+5), для
  7 ответ 17 (2+3+5+7).

  Дано: аргументы командной строки, то есть срез строк os.Args. Надо
  получить: одно число и перевод строки. Задача разбивается на четыре
  независимых куска, и каждый удобно оформить отдельной функцией. Первый
  кусок — проверить количество аргументов: os.Args[0] это всегда имя самой
  программы, поэтому «ровно один аргумент» означает len(os.Args) == 2, и
  любое отклонение сразу даёт вывод «0\n». Второй кусок — превратить строку
  в число: идём по байтам строки, каждый байт обязан быть цифрой, иначе
  строка невалидна; результат накапливаем как n = n*10 + цифра. Минус в этом
  разборе не разрешён специально — тогда аргумент «-2» отвергается сам
  собой, а README как раз требует для него ноль. Третий кусок — проверка на
  простоту: число простое, если оно не меньше 2 и не делится ни на одно
  число от 2 до квадратного корня из него; корень не вычисляем, а пишем
  условие i*i <= n, так не нужен пакет math и нет дробей. Искать делители
  дальше корня бессмысленно: если делитель больше корня, то парный ему
  делитель меньше корня уже был бы найден. Четвёртый кусок — превратить
  сумму обратно в строку: последнюю цифру берём как n%10, превращаем в
  символ через '0'+цифра и приклеиваем слева, потому что цифры извлекаются с
  конца. Свои atoi и itoa написаны, чтобы обойтись одним пакетом os:
  os.Stdout.WriteString принимает строку и доступен всегда. Главное в этой
  задаче — не забыть, что при любом плохом вводе печатается не «ничего», а
  именно «0» с переводом строки.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

    package main
    
    import "os"
    
    func atoi(s string) (int, bool) {
    	if len(s) == 0 {
    		return 0, false
    	}
    	n := 0
    	for i := 0; i < len(s); i++ {
    		if s[i] < '0' || s[i] > '9' {
    			return 0, false
    		}
    		n = n*10 + int(s[i]-'0')
    	}
    	return n, true
    }
    
    func itoa(n int) string {
    	if n == 0 {
    		return "0"
    	}
    	result := ""
    	for n > 0 {
    		result = string(rune('0'+n%10)) + result
    		n /= 10
    	}
    	return result
    }
    
    func isPrime(n int) bool {
    	if n < 2 {
    		return false
    	}
    	for i := 2; i*i <= n; i++ {
    		if n%i == 0 {
    			return false
    		}
    	}
    	return true
    }
    
    func main() {
    	if len(os.Args) != 2 {
    		os.Stdout.WriteString("0\n")
    		return
    	}
    	n, ok := atoi(os.Args[1])
    	if !ok || n <= 0 {
    		os.Stdout.WriteString("0\n")
    		return
    	}
    	sum := 0
    	for i := 2; i <= n; i++ {
    		if isPrime(i) {
    			sum += i
    		}
    	}
    	os.Stdout.WriteString(itoa(sum) + "\n")
    }

package main

  только такой пакет Go умеет компилировать в запускаемый файл.

import "os"
  Пакет os даёт доступ к операционной системе: аргументы командной строки (os.Args)
  и стандартный вывод (os.Stdout). Раз эталон подключает только его, значит
  fmt и strconv в этом задании не используются — превращение строки в число и
  числа в строку написано руками ниже.

func atoi(s string) (int, bool) {
  Своя функция «строка в число» (ascii to integer). Имя с маленькой буквы — она
  нужна только внутри этого файла, наружу её отдавать не надо.
  (int, bool) — ДВА возвращаемых значения: само число и признак «получилось ли».
  Go умеет возвращать несколько значений сразу, это его обычный способ сообщить
  об ошибке вместо исключений.

	if len(s) == 0 {
  Пустая строка — не число.

		return 0, false
  Возвращаем оба значения через запятую: ноль как заглушку и false как «не вышло».
  Ранний выход — дальше функция не идёт.

	}
  Конец проверки.

	n := 0
  Накопитель для собираемого числа. := создаёт новую переменную (тип int выведется
  из нуля справа).

	for i := 0; i < len(s); i++ {
  Идём по строке слева направо, по одному байту.
  i < len(s) строго меньше: последний индекс равен len(s)-1.

		if s[i] < '0' || s[i] > '9' {
  s[i] — один байт. Одинарные кавычки '0' и '9' — символьные константы, то есть
  просто числа: коды символов. Цифры в таблице кодов идут подряд, поэтому «символ
  является цифрой» проверяется сравнением на диапазон.
  Если байт вне этого диапазона — строка не число.
  🔴 Минус здесь не обрабатывается: для "-5" функция вернёт false, и программа
  напечатает 0. По условию это правильно — нужно положительное число.

			return 0, false
  Сообщаем «не число» и выходим.

		}
  Конец проверки.

		n = n*10 + int(s[i]-'0')
  Главная строка перевода. Разбираем:
  s[i]-'0' — вычитание кодов даёт значение цифры: код '7' минус код '0' равен 7.
  int(...) — преобразуем байт в int, чтобы сложить с n (Go не смешивает типы сам).
  n*10 — сдвигаем уже набранное число на разряд влево.
  Знак = (а не :=), потому что n уже существует, мы её просто перезаписываем.
  Для "123": n=0 → 0*10+1=1 → 1*10+2=12 → 12*10+3=123.

	}
  Конец цикла.

	return n, true
  Число собрано, признак успеха true.

}
  Конец функции atoi.

func itoa(n int) string {
  Обратная функция: число в строку (integer to ascii). Тоже своя, без strconv.

	if n == 0 {
  Отдельный случай для нуля.

		return "0"
  🔴 Без этой проверки ноль напечатался бы как ПУСТАЯ строка: цикл ниже устроен как
  «пока n > 0», а для нуля он не сделал бы ни одного прохода.

	}
  Конец проверки.

	result := ""
  Накопитель для результата — пустая строка.

	for n > 0 {
  Цикл с одним условием, крутится пока в числе остались разряды.
  Слова while в Go нет, его роль играет for с одним условием.

		result = string(rune('0'+n%10)) + result
  Самая хитрая строка. Изнутри наружу:
  n%10 — остаток от деления на 10, то есть ПОСЛЕДНЯЯ цифра числа.
  '0'+n%10 — прибавляем к коду символа '0' значение цифры и получаем код нужного
  символа: 0+5 даёт код символа '5'.
  rune(...) — приводим к руне, string(...) — превращаем руну в строку из одного символа.
  + result — 🔴 приём, ради которого всё затевалось: новая цифра приклеивается
  СПЕРЕДИ, а не сзади. Цифры добываются с конца числа, поэтому и складывать их
  надо в обратном порядке — иначе число вышло бы задом наперёд.

		n /= 10
  Сокращение для n = n / 10. Целочисленное деление отбрасывает последнюю цифру:
  123 становится 12, потом 1, потом 0 — и цикл заканчивается.

	}
  Конец цикла.

	return result
  Готовая строка с числом.

}
  Конец функции itoa.

func isPrime(n int) bool {
  Проверка на простоту. Возвращает bool — правда или ложь.
  Простое число — то, которое делится нацело только на 1 и на само себя.

	if n < 2 {
  Ноль, единица и всё отрицательное простыми не считаются по определению.

		return false
  Ранний выход.

	}
  Конец проверки.

	for i := 2; i*i <= n; i++ {
  Перебираем возможных делителей, начиная с 2.
  🔴 Условие i*i <= n, а не i <= n — это ускорение и одновременно правило:
  если у числа есть делитель, то один из пары делителей обязательно не больше
  квадратного корня. Значит дальше корня проверять бессмысленно.
  Записано именно как i*i <= n, чтобы не тащить math.Sqrt и не связываться
  с дробными числами.
  Для n = 2 и n = 3 условие 4 <= n ложно сразу, цикл не крутится ни разу,
  и функция честно вернёт true.

		if n%i == 0 {
  Остаток от деления равен нулю — значит делится нацело, значит не простое.

			return false
  Ранний выход из функции: нашли делитель, дальше искать нечего.

		}
  Конец проверки.

	}
  Конец цикла.

	return true
  Ни один делитель не нашёлся — число простое.

}
  Конец функции isPrime.

func main() {
  Точка входа программы. Функция main вызывается автоматически при запуске,
  параметров не принимает и ничего не возвращает.

	if len(os.Args) != 2 {
  os.Args — срез (список переменной длины) строк с аргументами командной строки.
  🔴 os.Args[0] — это всегда ИМЯ САМОЙ ПРОГРАММЫ, а пользовательские аргументы
  начинаются с индекса 1. Поэтому «ровно один аргумент» означает длину среза 2.

		os.Stdout.WriteString("0\n")
  Печать в стандартный вывод без пакета fmt.
  os.Stdout — стандартный вывод, WriteString — метод, пишущий туда строку.
  \n — перевод строки, он требуется условием.

		return
  Пустой return в main завершает функцию, а значит и всю программу.

	}
  Конец проверки.

	n, ok := atoi(os.Args[1])
  Вызов своей atoi для первого пользовательского аргумента.
  Слева ДВЕ переменные через запятую — так принимают два возвращаемых значения.
  := создаёт обе сразу: n типа int, ok типа bool.

	if !ok || n <= 0 {
  ! — логическое НЕ. !ok значит «строка не была числом».
  n <= 0 отсекает ноль (сам по себе аргумент "0" разбирается успешно, но по условию
  число должно быть положительным).
  || ленивое: если !ok истинно, вторая часть даже не проверяется.

		os.Stdout.WriteString("0\n")
  Тот же ответ по умолчанию: ноль и перевод строки.

		return
  Выход из программы.

	}
  Конец проверки.

	sum := 0
  Накопитель суммы простых чисел, стартует с нуля.

	for i := 2; i <= n; i++ {
  Перебор всех чисел от 2 до n.
  🔴 Здесь <=, а не <, потому что по условию само число тоже участвует:
  для 5 ответ 10 = 2+3+5, пятёрка входит в сумму.
  Начинаем с 2, потому что 0 и 1 простыми не бывают.

		if isPrime(i) {
  Вызов своей проверки. Условие в if — уже готовое булево значение, писать
  == true не нужно.

			sum += i
  Прибавляем простое число к сумме. Сокращение для sum = sum + i.

		}
  Конец проверки.

	}
  Конец цикла.

	os.Stdout.WriteString(itoa(sum) + "\n")
  Превращаем сумму в строку своей itoa, приклеиваем перевод строки и печатаем.
  🔴 Склеить строку с числом через + нельзя, поэтому itoa обязательна.
  🔴 Перевод строки обязателен — тест сравнивает вывод посимвольно.

------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * срез — список значений переменной длины, объявляется как []тип, длину
  даёт len
  * строка (string) — последовательность байтов, неизменяемая; s[i]
  возвращает один байт
  * байт (byte) — целое число от 0 до 255, один символ ASCII занимает ровно
  один байт
  * руна (rune) — код одного символа Юникода, целое число; string(rune(x))
  делает из кода строку из одного символа
  * os.Args — срез строк с аргументами командной строки, где os.Args[0] это
  имя самой программы, а os.Args[1] первый аргумент пользователя
  * os.Stdout.WriteString — печать строки на экран без пакета fmt
  * bool — тип с двумя значениями true и false
  * функция с двумя возвращаемыми значениями — записывается как (int, bool),
  результат принимается сразу в две переменные
  * целочисленное деление — деление с отбрасыванием дробной части: 7/2 равно
  3
  * остаток от деления (%) — то, что осталось после целочисленного деления:
  7%2 равно 1
  * простое число — целое не меньше 2, делящееся нацело только на 1 и на
  себя
  * рекурсия — когда функция вызывает сама себя; здесь не используется, всё
  сделано обычными циклами, стек вызовов не растёт


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * При невалидном вводе надо напечатать 0 и перевод строки, а не выйти
  молча. Молчаливый выход — самая частая ошибка в этой задаче.
  * Забыть \n в конце. Чекер сравнивает вывод побайтово, отсутствие перевода
  строки это провал.
  * Проверять len(os.Args) > 2 вместо != 2: тогда запуск вообще без
  аргументов пройдёт дальше и упадёт на обращении к os.Args[1] (panic: index
  out of range).
  * Считать 1 простым числом. Единица не простая, поэтому в isPrime стоит n
  < 2.
  * Считать 0 положительным. README показывает, что для 0 ответ 0.
  * В itoa писать result += string(...) вместо result = string(...) + result
  — цифры выйдут в обратном порядке (для 17 получится 71).
  * В itoa забыть отдельный случай n == 0 — вернётся пустая строка, и
  программа напечатает только \n.
  * В atoi забыть проверку на пустую строку — аргумент "" пройдёт как
  валидный ноль (правда, здесь всё равно приведёт к выводу 0, но в других
  задачах это ломает ответ).
  * В цикле суммирования писать i < n вместо i <= n — потеряется само число
  n.
  * Внутри isPrime перебирать делители до n вместо i*i <= n: для больших
  аргументов программа будет считать заметно дольше.

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Дан срез беззнаковых целых []uint. Число на каждой позиции — это точное
  количество шагов вперёд, которое обязан сделать тот, кто на этой позиции
  стоит. Старт с позиции 0; надо определить, попадём ли мы ровно на
  последний индекс, ни разу не выпрыгнув за границы среза. Пустой срез даёт
  false, срез из одного элемента даёт true, потому что стартовая позиция в
  нём уже является последней. В README нет блока Expected function — подпись
  выводится из текста задания и из тестовой программы.

  Бот школы сверяет подпись функции посимвольно. Другое имя, другой порядок
  или тип параметров, лишний или недостающий возврат — задача не засчитана.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Главное слово в условии — «exact number of steps you must take», то есть
  ровно столько шагов, а не «не более». Из этого следует ключевой вывод:
  выбора на каждом шаге нет, из любой позиции ведёт ровно один ход, а значит
  весь маршрут из позиции 0 определён однозначно. Поэтому не нужен ни
  перебор вариантов, ни рекурсия, ни жадный алгоритм — достаточно один раз
  пройти по цепочке позиций и посмотреть, чем она кончится. Дальше надо
  перечислить, чем эта цепочка может закончиться, и это ровно три исхода.
  Первый: попали ровно на последний индекс — это успех. Второй: наступили на
  позицию со значением 0, которая не последняя — двигаться больше некуда,
  застряли, это провал. Третий: шаг уводит за пределы среза — тоже провал,
  потому что условие требует не выйти за массив. Проверять оба провала надо
  ДО того, как менять позицию, иначе можно обратиться к несуществующему
  индексу и получить панику. Цикл пишем как «пока текущая позиция меньше
  последней»: как только она сравнялась с последней, ответ true, а больше
  последней она стать не может, потому что мы это заранее отсекаем.
  Зацикливания не будет: шаг всегда строго больше нуля (нулевой мы уже
  отсеяли), значит позиция строго растёт и цикл конечен. Отдельно
  обрабатываем пустой срез в самом начале: без этого last получится −1, цикл
  не выполнится ни разу и функция ошибочно вернёт true. Случай одного
  элемента специально обрабатывать не нужно — при last равном 0 цикл не
  выполняется и возвращается true, причём само значение input[0] даже не
  читается, что и требует README для []uint{0}. Последняя тонкость — типы:
  input[pos] имеет тип uint, а last-pos имеет тип int, и Go не даёт
  сравнивать разные типы напрямую, поэтому приводим int к uint, а не
  наоборот.

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: Число в ячейке — это МАКСИМАЛЬНАЯ длина прыжка,
  а не обязательная. Поэтому считается самая дальняя достижимая позиция: на
  каждом шаге берётся большее из уже достигнутого и суммы «текущий индекс
  плюс его значение». Ответ «да» только когда эта дальность оказывается
  РОВНО последним индексом — перескок за конец не считается успехом.

    package piscine
    
    func CanJump(steps []uint) bool {
    	if len(steps) == 0 {
    		return false
    	}
    
    	maxReach := 0
    	for i := 0; i < len(steps); i++ {
    		if i > maxReach {
    			return false
    		}
    		maxReach = max(maxReach, i+int(steps[i]))
    		if maxReach == len(steps)-1 || len(steps) == 1 {
    			return true
    		}
    	}
    	return false
    }
    
    func max(a, b int) int {
    	if a > b {
    		return a
    	}
    	return b
    }

  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * срез — список значений переменной длины, объявляется как []тип;
  количество элементов даёт len
  * uint — целое число без знака, отрицательным быть не может, на 64-битной
  машине хранит значения до 18446744073709551615
  * индекс — номер позиции в срезе, нумерация начинается с нуля, поэтому
  последний индекс равен len-1
  * len — встроенная функция, возвращающая количество элементов среза
  * bool — тип с двумя значениями: true и false
  * приведение типа — запись вида uint(x) или int(x), которая переводит
  значение из одного числового типа в другой; Go не делает это автоматически
  * || — логическое «или»: всё выражение истинно, если истинна хотя бы одна
  из частей
  * panic: index out of range — ошибка времени выполнения при обращении к
  несуществующему индексу среза, программа при этом падает
  * рекурсия — вызов функцией самой себя; здесь не нужна, потому что маршрут
  единственный и обходится обычным циклом, стек вызовов не растёт

  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Решать это как известную задачу Jump Game, где значение это МАКСИМАЛЬНОЕ
  число шагов и можно прыгнуть на меньшее расстояние. Здесь значение —
  ТОЧНОЕ число шагов, выбора нет. Проверка: для [3 2 1 0 4] жадный алгоритм
  из Jump Game вернул бы true, а правильный ответ здесь false.
  * Забыть проверку на пустой срез. Тогда last станет −1, условие 0 < −1
  ложно, цикл не выполнится и вернётся true вместо false.
  * Двигать позицию до проверки — обращение к input[pos] за границей среза
  вызовет panic.
  * Не проверять step == 0: если значение нулевое и позиция не последняя,
  позиция перестанет меняться и цикл будет крутиться вечно.
  * Пытаться отдельно обработать нулевое значение на последней позиции.
  Этого делать не надо: условие цикла pos < last гарантирует, что элемент на
  последнем индексе вообще не читается, и []uint{0} правильно даёт true.
  * Сравнивать int(step) > last-pos вместо step > uint(last-pos). При очень
  большом значении uint приведение к int даст отрицательное число, проверка
  не сработает, и следующий шаг выпрыгнет за границы.
  * Считать, что попадание ЗА последний индекс тоже успех. Условие требует
  «reach and stay at the last index», то есть встать ровно на него; перелёт
  это провал.
  * Считать, что прыгать надо ровно на указанное число шагов. Это максимум,
  а не точная длина.
  * Считать успехом любой перескок за последний индекс. Эталон требует
  точного попадания в него.

  Третье: как резать. В Go есть подсрез — запись slice[i:end] даёт кусок с

  этом копировать не нужно. Поэтому цикл идёт не по одному элементу, а шагом
  size: i = 0, потом size, потом 2*size и так далее, пока i меньше длины.
  Четвёртое: конец куска. Наивно end это i+size, но у последнего куска это
  может оказаться больше длины среза, и обращение slice[i:end] вылетит с
  паникой. Поэтому после вычисления end его надо прижать: если end больше
  len(slice), сделать его равным len(slice). Пятое: случай size равного
  нулю. Его надо отсечь в самом начале по двум причинам — README прямо
  требует напечатать перевод строки, и потому что шаг i += 0 дал бы
  бесконечный цикл. Отрицательный size README не описывает, но он тоже
  зациклил бы программу, поэтому условие пишем как size <= 0. Пустой входной

  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Функция получает два среза целых чисел и возвращает новый срез, в котором
  элементы идут по очереди: один из первого, один из второго, снова из
  первого и так далее. Срезы могут быть разной длины. Начинать надо с
  элемента более длинного среза; при равных длинах первым идёт элемент
  первого аргумента. Хвост более длинного среза, которому уже нет пары,
  дописывается в конец подряд.

    }

------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Задача распадается на два независимых вопроса: кто ходит первым и как
  чередовать. Первый вопрос решается по правилу из условия — начинать надо с
  элемента более длинного среза, а при равных длинах с первого аргумента.
  Значит нужно сравнение строго «больше»: если длина второго строго больше
  длины первого, меняем их местами, во всех остальных случаях (включая
  равенство) первым остаётся slice1. Именно строгое сравнение обеспечивает
  правило равных длин; со сравнением «больше или равно» пример [1 2 3] и [4
  5 6] дал бы [4 1 5 2 6 3] вместо ожидаемого [1 4 2 5 3 6]. Чтобы дальше не
  писать два симметричных варианта кода, заводим две вспомогательные
  переменные first и second и работаем только с ними — так весь остальной
  код не знает, какой срез откуда пришёл. Второй вопрос: цикл идёт по
  индексам более длинного среза, то есть от 0 до len(first). На каждом шаге
  всегда кладём first[i], а second[i] кладём только если индекс i ещё
  существует во втором срезе. Этот приём заменяет собой отдельный цикл
  дописывания хвоста: когда короткий срез кончился, условие i < len(second)
  перестаёт выполняться и оставшиеся элементы длинного просто идут подряд.
  Результат собираем через append в срез, объявленный пустым — заранее
  вычислять длину не требуется. Пустые срезы обрабатываются тем же кодом без
  отдельных проверок: если second пуст, внутреннее условие ложно на всех
  шагах, а если пусты оба, цикл не выполняется ни разу. Обязательно
  проверить логику на третьем примере README: для [1 2 3] и [4 5 6 7 8 9]
  первым становится второй срез, получается 4 1 5 2 6 3, затем хвост 7 8 9.

    package piscine
    
    func ConcatAlternate(slice1, slice2 []int) []int {
    	var result []int
    
    	if len(slice1) < len(slice2) {
    		slice1, slice2 = slice2, slice1
    	}
    	for i, v := range slice1 {
    		result = append(result, v)
    		if i < len(slice2) {
    			result = append(result, slice2[i])
    		}
    	}
    	return result
    }

package piscine
  Библиотека. Импортов нет — ничего постороннего не требуется, а неиспользуемый импорт в Go не компилируется.

func ConcatAlternate(slice1, slice2 []int) []int {
  Два параметра одного типа записаны одним []int в конце — это короткая форма записи slice1 []int, slice2 []int. Смысл тот же.
  Возвращает []int — новый срез целых чисел.

	var result []int
  Накопитель ответа. Нулевое значение среза — nil, срез без выделенной памяти.
  make здесь не нужен: append умеет работать с nil-срезом и сам выделит память при первом добавлении.
  var, а не := — значения на этой строке ещё нет.

	if len(slice1) < len(slice2) {
  Проверяем, кто из двух длиннее.
  🔴 Знак строго < , а не <=. При РАВНЫХ длинах обмена не происходит, и первым в ответ идёт элемент первого аргумента — ровно как требует условие. Поставь <= — и на равных длинах порядок перевернётся.

		slice1, slice2 = slice2, slice1
	}
  Обмен значениями в одну строку. Правая часть вычисляется целиком, потом раскладывается по левым переменным, поэтому третья, временная переменная не нужна.
  После этой строки в slice1 гарантированно лежит более длинный (или равный) срез — дальше весь код опирается на это.
  Обмениваются копии внутри функции; у того, кто вызвал функцию, ничего не меняется.
  = , а не := — обе переменные уже существуют, это параметры функции.

	for i, v := range slice1 {
  Идём по ДЛИННОМУ срезу. i — индекс, v — значение.
  Именно по длинному: хвост, которому нет пары, всё равно надо дописать в конец, и так он допишется сам собой, без второго цикла.

		result = append(result, v)
  Сначала кладём элемент длинного среза. append возвращает новый срез, поэтому результат присваивают обратно в result.

		if i < len(slice2) {
  Проверяем, есть ли у короткого среза элемент с таким же номером.
  🔴 Знак строго < : индексы идут от 0 до len-1, поэтому i == len(slice2) — это уже выход за границу и падение программы.

			result = append(result, slice2[i])
		}
	}
  Есть пара — кладём её сразу за элементом длинного среза. Когда i дорастает до len(slice2), эта ветка перестаёт срабатывать, и остаток длинного среза идёт в ответ подряд.

	return result
}
  Возвращаем накопленное.
  🔴 Если оба среза пустые, result так и остался nil. Это нормально: len у него 0, а Println напечатает []. Специально возвращать make([]int, 0) не требуется.

  Прогон: ConcatAlternate([]int{1,2,3}, []int{4,5,6,7,8})
    первый короче → обмен: slice1 = {4,5,6,7,8}, slice2 = {1,2,3}
    i=0: кладём 4, потом 1 → [4 1]
    i=1: кладём 5, потом 2 → [4 1 5 2]
    i=2: кладём 6, потом 3 → [4 1 5 2 6 3]
    i=3: кладём 7, пары нет → [4 1 5 2 6 3 7]
    i=4: кладём 8, пары нет → [4 1 5 2 6 3 7 8]
  Прогон при равных длинах: ConcatAlternate([]int{1,2,3}, []int{4,5,6}) → [1 4 2 5 3 6], обмена не было.

------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Это самая простая задача из шести, и вся мысль здесь в одном: завести
  пустой срез-накопитель, пройти первый вход и добавить каждый его элемент,
  потом пройти второй и сделать то же самое. Длину заранее считать не нужно,
  потому что append сам увеличивает срез по мере добавления. Пустые входы не
  требуют отдельных проверок: если срез пуст, соответствующий цикл просто не
  выполнится ни разу. Есть соблазн написать одну строку return
  append(slice1, slice2...), и она пройдёт примеры из README, но так делать
  нельзя — и вот почему. Срез в Go это не сами данные, а описание куска
  памяти: указатель на массив, длина и ёмкость. Если у slice1 ёмкость больше
  длины, append запишет элементы второго среза прямо в этот же массив и
  испортит данные, на которые смотрят другие срезы того же массива. Это
  реально воспроизводится, и на чекере с подготовленными входами такое
  решение может дать неверный результат. Явные циклы этого недостатка
  лишены: каждый элемент копируется в свежий накопитель, входные срезы
  только читаются. Ещё один плюс явных циклов — на защите такой код
  объясняется одной фразой, а поведение append с многоточием пришлось бы
  объяснять через устройство памяти. Инициализация result := []int{} даёт
  непустой по факту, но нулевой длины срез; вариант var result []int (это
  nil) работает так же и печатается тоже как [], но с явной инициализацией
  понятнее, что переменная готова к добавлению.

package piscine

func ConcatSlice(slice1, slice2 []int) []int {
  Объявление функции. Два параметра типа []int (срез целых чисел — список чисел
  переменной длины). Тип написан один раз в конце, потому что у обоих параметров он
  одинаковый.
  []int после скобок — тип результата: возвращается новый срез целых.

	var result []int
  Объявляем переменную result типа []int БЕЗ начального значения.
  Форма var имя тип используется, когда значения пока нет. Форма := тут не подошла бы:
  ей обязательно нужно значение справа от знака.
  Срез без значения равен nil — «пустой срез, ничего не указывает». Длина его 0.
  Это нормальное рабочее состояние: append умеет добавлять в nil-срез, создавая
  память сам. Специально писать result := []int{} не обязательно.

	for _, v := range slice1 {
  Цикл по всем элементам первого среза. range для среза даёт два значения: номер
  элемента и сам элемент.
  _ (подчёркивание) выбрасывает номер — он не нужен, а неиспользуемая переменная в Go
  это ошибка компиляции, поэтому подчёркивание обязательно.
  v — очередное число из slice1.
  🔴 range сам знает, где срез кончается, поэтому границы задавать не надо и выйти за
  них невозможно.

		result = append(result, v)
  append добавляет элемент в конец среза и возвращает НОВЫЙ срез. Результат
  обязательно присваивается обратно в result — append не меняет переменную сам.
  Строка просто append(result, v) без присваивания не сработает: Go откажется
  компилировать, потому что возвращённое значение никуда не идёт.
  Здесь = , а не := : result уже существует, мы обновляем его значение.

	}
  Конец первого цикла. К этому моменту в result лежит полная копия slice1 в исходном
  порядке.

	for _, v := range slice2 {
  Второй цикл, по второму срезу. Всё устроено так же.
  🔴 Переменная v объявляется здесь заново своим собственным := внутри заголовка range;
  та v из первого цикла жила только внутри первого цикла и уже не существует.
  Конфликта имён нет.

		result = append(result, v)
  Дописываем элементы второго среза в конец того же накопителя. Поскольку первый цикл
  уже прошёл целиком, элементы slice2 гарантированно ложатся ПОСЛЕ элементов slice1 —
  это и даёт требуемый порядок.

	}
  Конец второго цикла.

	return result
  Возвращаем накопленный срез. return стоит после обоих циклов.

	}
  Конец функции.

ЛОВУШКИ ЗАДАНИЯ
  🔴 Порядок циклов = порядок в ответе. Сначала slice1, потом slice2. Поменяешь циклы
     местами — ответ будет неверным, хотя код скомпилируется.
  🔴 append всегда с присваиванием обратно в ту же переменную.
  🔴 Пустые срезы обрабатываются сами собой: если slice1 пуст, первый цикл не сделает
     ни одного витка. Отдельная проверка на пустоту не нужна.
  🔴 Если пусты оба, функция вернёт nil. При печати через fmt.Println nil-срез
     выглядит как [] — ровно так же, как пустой срез, поэтому тест это принимает.
  🔴 Функция строит НОВЫЙ срез и не трогает исходные. Это важно: если бы ты писал
     result := slice1 и потом делал append, ты мог бы испортить исходный срез
     вызывающей стороны.


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * срез — список значений переменной длины, объявляется как []тип; внутри
  устроен как указатель на массив плюс длина плюс ёмкость
  * указатель — адрес участка памяти; в срезе он спрятан внутри и напрямую
  не виден, но именно из-за него два среза могут смотреть на одни и те же
  данные
  * ёмкость (cap) — сколько элементов помещается в массиве под срезом без
  выделения новой памяти; может быть больше длины
  * len — количество элементов среза
  * append — встроенная функция, добавляющая элементы в конец среза и
  возвращающая новый срез; при нехватке ёмкости выделяет новую память, при
  наличии запаса пишет в старую
  * append(a, b...) — форма с многоточием, добавляющая сразу все элементы
  среза b; опасна тем, что при запасе ёмкости у a перезаписывает его память
  * i++ — увеличение переменной на единицу
  * nil-срез — срез без присвоенного значения; len равен 0, fmt печатает его
  как [], добавлять в него через append можно


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Писать return append(slice1, slice2...) вместо явных циклов. Если у
  slice1 ёмкость больше длины, append запишет элементы второго среза прямо в
  память первого и испортит исходные данные. Проверил в песочнице: массив с
  длиной 3 и ёмкостью 10, содержащий [1 2 3], после такого append
  превратился в [1 2 3 4 5]; вариант с явными циклами исходные данные не
  тронул.
  * Вернуть сам slice1 после добавления в него элементов — наружу уйдёт
  срез, связанный со входными данными, любое дальнейшее изменение результата
  отразится на входе.
  * Забыть присвоить результат append обратно в переменную: строка
  append(result, x) сама по себе ничего не добавляет.
  * Во втором цикле продолжить счётчик с того места, где кончился первый (i
  := len(slice1)) — тогда индексы уйдут за границы slice2 и будет panic:
  index out of range. Счётчик второго цикла всегда начинается с нуля.
  * Перепутать порядок и вернуть сначала второй срез, потом первый.
  * Считать, что пустой срез требует отдельной проверки. Не требует: цикл по
  пустому срезу просто не выполняется.

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Программа получает один аргумент — положительное целое число — и печатает
  его разложение на простые множители, а после него перевод строки.
  Множители идут по возрастанию и разделяются символом * без пробелов;
  повторяющиеся множители выписываются столько раз, сколько раз входят
  (225225 даёт 3*3*5*5*7*11*13). Если аргументов не ровно один, аргумент
  невалиден, или у числа нет простых множителей (это 0 и 1), программа не
  печатает ничего — вообще ни одного байта, даже перевода строки.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Главный приём здесь — деление пробным делителем, и его надо понять один
  раз, чтобы больше не путаться. Берём делитель d начиная с 2 и делим число
  на него, пока делится нацело, каждый раз записывая d в ответ; потом
  увеличиваем d на единицу и повторяем. Возникает вопрос: почему не нужно
  проверять, простое ли само d — ведь мы дойдём до 4, до 6, до 9. Ответ: к
  моменту, когда d станет равным 4, из числа уже полностью вычерпаны все
  двойки, поэтому на 4 оно уже не поделится; то же самое с любым составным
  делителем. Значит проверка на простоту делителя лишняя, составные делители
  отсеиваются сами. Второй важный момент — где остановиться. Перебирать d до
  самого числа нельзя: для аргумента вроде 2147483647 это миллиарды
  проходов. Достаточно идти пока d*d <= n, потому что у числа не может быть
  двух разных множителей больше корня одновременно. При этом n по ходу
  уменьшается, и граница пересчитывается на каждом проходе, поэтому цикл
  заканчивается очень быстро. Третий момент — остаток. После выхода из цикла
  оставшееся n либо равно 1 (всё разложилось), либо само является простым
  числом, которое больше корня от исходного; во втором случае его надо
  дописать в ответ, иначе для 9539 вывод окажется пустым. Четвёртое —
  формат. Звёздочка ставится ПЕРЕД очередным числом и только если в строке
  уже что-то есть; признак «строка пустая» проверяется как result != "".
  Если ставить звёздочку после каждого числа, в конце останется лишняя.
  Пятое — невалидные случаи. Их четыре: аргументов не один, строка не число,
  число 0, число 1. Во всех этих случаях делаем return сразу и не печатаем
  НИЧЕГО, даже перевода строки — README говорит «displays nothing», и лишний
  байт \n завалит побайтовое сравнение. Порог n < 2 закрывает и ноль, и
  единицу разом, а отрицательные отсекает сам atoi, потому что минус не
  является цифрой.

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: 🔴 Поведение в краевых случаях взято из ЭТАЛОНА
  школы, а не из текста задания — они местами расходятся, а бот сверяет

  аргументов и при пустом результате: молчание и печать пустой строки — это
  разные вещи, и бот их различает.

    func fprime(value int) {
    	if value == 1 {
    		return
    	}
    	divisionIterator := 2
    	for value > 1 {
    		if value%divisionIterator == 0 {
    			fmt.Print(divisionIterator)
    			value = value / divisionIterator
    
    			if value > 1 {
    				fmt.Print("*")
    			}
    			divisionIterator--
    		}
    		divisionIterator++
    	}
    	fmt.Println()
    }

    		if i, err := strconv.Atoi(os.Args[1]); err == nil {
    			fprime(i)
    		}
    	}
    }

  strconv.Atoi («ASCII to integer») переводит строку в целое число и возвращает ДВА значения: само число и ошибку. Поэтому слева от := стоят две переменные.

  Вызываем разложение для полученного числа.

		}
	}
}
  Закрываются вложенный if, внешний if и main.

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Программа получает два аргумента командной строки — строки s1 и s2. Надо
  проверить, «спрятана» ли s1 внутри s2: каждый символ s1 должен найтись в
  s2 в том же порядке, но не обязательно подряд. Если спрятана — вывести 1 и
  перевод строки, если нет — 0 и перевод строки. Пустая s1 считается
  спрятанной в любой строке. Если аргументов не ровно два — программа не
  выводит ничего.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано две строки, надо вывести одну цифру — 1 или 0. Формально задача
  звучит так: является ли s1 подпоследовательностью s2, то есть можно ли
  вычеркнуть из s2 часть символов так, чтобы осталась ровно s1. Первая мысль
  обычно неверная: для каждого символа s1 искать его в s2 с начала — тогда
  один и тот же символ s2 засчитается несколько раз, и «DD» ошибочно
  найдётся в «DABC». Правильный приём — один проход по s2 с одним счётчиком
  i, который означает «сколько первых символов s1 уже сопоставлено». Берём
  очередной символ c из s2 и сравниваем его только с s1[i]: совпал —
  увеличиваем i, не совпал — просто идём дальше по s2, назад не
  возвращаемся. Такая жадность даёт верный ответ, потому что если нужный
  символ встречается в s2 несколько раз, брать самое раннее вхождение
  никогда не хуже: после раннего вхождения остаётся более длинный хвост s2
  для остальных символов. После цикла ответ читается из i: если i дорос до
  len(s1), значит все символы нашлись по порядку — печатаем 1, иначе 0.
  Правило про пустую s1 выполняется само собой: длина 0, счётчик 0, условие
  i == len(s1) верно с самого начала. Проверку len(args) != 2 надо поставить
  самой первой строкой — до неё нельзя трогать args[0] и args[1], иначе при
  запуске без аргументов программа аварийно остановится. s1 переводим в
  []rune, потому что range по строке выдаёт руны, и типы в сравнении s1[i]
  == c должны совпадать. Разница с задачей wdmatch только в том, что
  печатать в конце: там исходная строка, здесь цифра.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

package main
  Пакет main — это программа, а не библиотека. Только у main есть точка входа func main, и только его можно запустить.

import (
	"fmt"
	"os"
	"strings"
)
  Три пакета в одних скобках — групповой импорт, то же самое, что три отдельные строки import.
  fmt — печать. os — доступ к аргументам командной строки. strings — нужна одна функция, Index.
  Раз эталон школы их использует, для этого задания все три разрешены.

func main() {
  Точка входа. Параметров не принимает: аргументы командной строки берутся не отсюда, а из os.Args.

	var i int
  Объявляется переменная i типа int. Значение не задано, поэтому Go кладёт нулевое значение — 0.
  var используют, когда значения на этой строке ещё нет; через := так написать нельзя, ему нужно значение сразу.
  Смысл i: позиция в s2, начиная с которой продолжаем поиск. Это курсор, он только растёт.

	if len(os.Args) != 3 {
  os.Args — срез строк (срез = список переменной длины) со всем, что было в командной строке.
  os.Args[0] — путь к самой программе, поэтому ДВА пользовательских аргумента дают длину 3, а не 2.
  🔴 Частая ошибка — написать != 2. Тогда программа молчит всегда.

		return
	}
  Ранний выход: аргументов не два — выходим из main, ничего не напечатав.
  🔴 Условие требует именно молчания. Напечатать пустую строку — это уже другой ответ.

	for _, r := range os.Args[1] {
  range по строке выдаёт две вещи: индекс байта и руну (руна = один символ, точнее его код).
  _ означает «это значение мне не нужно», индекс выбрасывается. r — очередной символ строки s1.
  Идём по всем символам s1 и для каждого ищем место в s2.

		j := strings.Index(os.Args[2][i:], string(r))
  os.Args[2][i:] — срез строки: кусок s2 от байта i до конца. Уже просмотренная часть отрезана, поэтому один и тот же символ s2 не будет использован дважды.
  string(r) — руна превращается в строку из одного символа, потому что Index принимает строку, а не руну.
  strings.Index возвращает номер первого вхождения или -1, если не нашлось.
  := создаёт новую j на каждом витке цикла и сразу кладёт туда результат.
  🔴 j отсчитывается ОТ НАЧАЛА КУСКА, а не от начала всей s2. Из-за этого ниже стоит сложение, а не простое присваивание.

		if j == -1 {
  -1 — единственный признак «не нашлось». Значит порядок нарушен, дальше искать бессмысленно.

			fmt.Println("0")
  Печатает 0 и перевод строки. Println добавляет \n сам, вручную его дописывать не надо.
  В кавычках — строка "0", не число; на вывод это не влияет.

			return
		}
  Выход из main сразу после печати. Без него цикл пошёл бы дальше и внизу напечаталась бы ещё и 1 — две строки вместо одной.

		i += j + 1
  Курсор сдвигается на найденный символ и ещё на один вперёд, чтобы следующий поиск начался ЗА ним.
  i += x — краткая запись i = i + x.
  🔴 Без +1 тот же самый символ нашёлся бы снова, и строка "aa" считалась бы спрятанной в "a".
	}

	fmt.Println("1")
}
  Сюда попадаем только если цикл прошёл до конца ни разу не наткнувшись на -1 — все символы нашлись по порядку.
  🔴 Пустая s1: цикл не выполняется ни разу, управление сразу приходит сюда и печатается 1. Это ровно то, что требует условие.

  Прогон: s1 = "fgh", s2 = "abcdefghijk"
    i=0, r='f': ищем в "abcdefghijk" → j=5, i = 0+5+1 = 6
    r='g': ищем в "ghijk" → j=0, i = 6+0+1 = 7
    r='h': ищем в "hijk" → j=0, i = 8
    цикл кончился → печатается 1
  Прогон: s1 = "hgf", s2 = "abcdefghijk"
    r='h': j=7, i=8. r='g': ищем в "ijk" → -1 → печатается 0 и выход. Порядок важен.


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * os.Args — срез строк, в который Go складывает путь к программе (нулевой
  элемент) и все аргументы командной строки.
  * os.Args[1:] — срез без нулевого элемента, то есть только аргументы
  пользователя.
  * срез (slice) — список значений одного типа переменной длины, доступ к
  элементам по индексу начиная с нуля.
  * len — длина: у среза это число элементов, у строки — число байтов.
  * руна (rune) — один символ Unicode, представленный числом (rune это
  другое имя типа int32).
  * байт (byte) — число от 0 до 255; символ ASCII занимает один байт,
  кириллическая буква — два.
  * []rune(s) — преобразование строки в срез рун, после которого индексация
  идёт по символам, а не по байтам.
  * range по строке — цикл, выдающий на каждом шаге пару «позиция в байтах,
  руна».
  * _ (пустая переменная) — место, куда сбрасывают значение, которое не
  нужно.
  * os.Stdout.WriteString — запись строки в стандартный вывод без каких-либо
  добавлений.
  * return в main — немедленное завершение программы.
  * подпоследовательность — символы, взятые из строки по порядку, но,
  возможно, с пропусками.
  * index out of range — паника (аварийная остановка) при обращении к
  несуществующему элементу среза.


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Обратиться к args[0] или args[1] до проверки их количества — программа
  падает с index out of range при запуске без аргументов.
  * При числе аргументов не 2 hiddenp не печатает вообще ничего — ни цифры,
  ни пустой строки (в union требование обратное, там печатается перевод
  строки).
  * Убрать из условия проверку i < len(s1): как только s1 собрана, а s2 ещё
  идёт, s1[i] выйдет за границу среза и программа упадёт.
  * Забыть \n после цифры — школьный тест сверяет вывод побайтово, "1" и
  "1\n" это разные ответы.
  * Пустая s1 даёт ответ 1, а не 0 — это прямо написано в README и легко
  потерять.
  * Решать через «все ли символы s1 вообще встречаются в s2»: тогда "DD" в
  "DABC" даст 1, а правильный ответ 0, потому что нужны два символа D.
  * Использовать strings.Contains — он ищет подстроку идущую подряд, а здесь
  нужны пропуски между символами.
  * Сбрасывать счётчик i внутри цикла или заводить его внутри цикла — он
  должен жить снаружи и только расти.
  * Сравнивать байты вместо рун: при работе с []byte и range (который даёт
  руны) типы не сойдутся и код не скомпилируется.

------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)

  Дано две строки, надо получить строку из их общих символов. Первое, что
  определяет структуру решения — фраза «в порядке, в котором они идут в
  первой»: раз порядок задан первой строкой, значит внешний цикл обязан идти
  по первой строке, а вторая строка нужна только как справочник. Для каждого
  символа c первой строки надо ответить на два вопроса: есть ли c во второй
  строке, и не выводили ли мы c раньше. Оба вопроса — это одна и та же
  операция «встречается ли символ в строке», поэтому её выгодно вынести в
  отдельную функцию, которая пробегает строку и возвращает true или false.
  Второй вопрос не требует отдельного списка «уже выведенных»: накопленный
  ответ result и есть этот список, достаточно спросить, есть ли c в result.
  Ответ копим в переменной типа string и добавляем к ней string(c) —
  преобразование руны в строку из одного символа; без него сложение строки и
  числа не скомпилируется. Печатаем один раз в самом конце, приклеив \n: так
  перевод строки точно не потеряется и точно не удвоится. Если общих
  символов нет, result останется пустым и напечатается только перевод строки
  — README не делает для этого случая исключений. Проверку количества
  аргументов ставим первой строкой main; здесь при неверном количестве не
  печатается вообще ничего, и это отличается от задачи union, где надо
  напечатать перевод строки.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

package main

func result(s1 string, s2 string) string {
  Объявление функции. Два параметра, оба string, тип написан у каждого отдельно. Возвращает одну строку — готовый ответ.
  Имя функции result — обычное имя, никакой магии в нём нет.

	var rest []rune
  Накопитель — переменная, куда собираются подходящие символы. Тип []rune, срез рун. Руна = один символ целиком (в отличие от байта, которых на символ может уйти несколько).
  var, а не := , потому что начального значения нет, есть только тип. Такой срез равен nil, но append в него писать умеет.
  Почему руны, а не строка: дописывать в срез через append дешевле и проще, чем склеивать строку.

	for _, a := range s1 {
  Заголовок внешнего цикла. range по СТРОКЕ отдаёт две вещи: байтовый индекс и руну. Индекс не нужен — на его месте _ (пустышка). a — очередная руна первой строки.
  🔴 Важно: range по строке даёт именно руны, а не байты. Поэтому многобайтовые символы обрабатываются целиком.

		for _, b := range s2 {
  Внутренний цикл: для каждой руны из s1 пробегаем ВСЮ вторую строку. b — очередная руна второй строки.
  Это перебор всех пар — простой и медленный способ найти общие символы, но для экзамена его хватает.

			if a == b && !strings.ContainsRune(string(rest), a) {
  Два условия через && («и»), оба должны быть истинны.
  a == b — символ из первой строки встретился во второй.
  string(rest) — собираем накопленное обратно в строку; ContainsRune проверяет, есть ли там уже руна a; ! переворачивает. То есть второе условие означает «этой руны мы ещё не записывали».
  🔴 Порядок частей осмысленный: сначала дешёвое сравнение двух чисел, и только если оно прошло — дорогая пересборка строки и поиск по ней. && вычисляет левую часть первой и, если она ложна, правую вообще не трогает (короткое замыкание).
  Именно это второе условие обеспечивает требование «без повторов».

				rest = append(rest, a)
  Дописываем руну в конец накопителя. append возвращает НОВЫЙ срез, поэтому результат обязательно присваивается обратно в rest. Знак = , а не := — rest уже существует; := создало бы новую переменную внутри if и потеряло бы всё накопленное.
  🔴 break после append не стоит. Если a встречается во второй строке несколько раз, цикл продолжится, но второй раз добавить не даст проверка ContainsRune.

			}
		}
	}
  Закрываются if, внутренний for, внешний for.

	return string(rest)
  Превращаем срез рун в строку и отдаём. string([]rune) — стандартное преобразование, склеивает символы подряд без разделителей.

}
  Конец функции result.

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Программа получает один или несколько аргументов. Каждый аргумент надо
  преобразовать так: последняя буква каждого слова становится заглавной, все
  остальные буквы — строчными. Результат по каждому аргументу печатается
  отдельной строкой, с переводом строки в конце. Если аргументов нет,
  программа не печатает ничего. Слово — это кусок текста между пробелами
  (пример "IT'S" -> "it'S" из README показывает, что апостроф границей слова
  не считается).


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано несколько строк-аргументов, каждую надо вывести преобразованной на
  отдельной строке. Резать текст на слова через разделение по пробелам
  можно, но проще работать посимвольно: для каждой позиции правило
  формулируется независимо от остальных. Строку в Go менять нельзя, поэтому
  сначала копируем её в срез байтов ([]byte) — у среза элементы менять
  можно. Правило распадается на два простых действия для каждой позиции:
  сперва «сделать строчной», затем «если это конец слова и это буква —
  сделать заглавной». Именно такой порядок внутри одной итерации позволяет
  обойтись одним проходом: символ 'T' в конце слова сначала станет 't', а
  потом снова 'T'. Конец слова определяется двумя вариантами: символ
  последний в аргументе (i == len(b)-1) или следующий символ — пробел.
  Пример README "IT'S" -> "it'S" доказывает, что границей слова служит
  только пробел: если бы границей был любой не-буквенный символ, вышло бы
  "iT'S", а это неверно. Пример "0123456789" без изменений доказывает
  второе: заглавной делаем только настоящую букву, цифру или знак трогать
  нельзя, иначе -32 превратит цифру в мусор. Сам перевод регистра делается
  арифметикой по кодам ASCII: код 'A' равен 65, код 'a' равен 97, разница
  ровно 32 для всех латинских букв, поэтому +32 понижает регистр, а -32
  повышает. Отдельная проверка «аргументов нет» не нужна: цикл по пустому
  срезу просто не выполнится ни разу и ничего не напечатает.

func main() {
  Точка входа программы. Функция обязана называться main, не принимать параметров и
  ничего не возвращать. Когда программу запускают, выполнение начинается отсюда.

  Цикл range — «пройди по всему списку по очереди». Для среза он на каждом витке даёт
  два значения: номер элемента и сам элемент.
  _ (подчёркивание) — «пустая переменная»: номер нам не нужен, и мы его выбрасываем.
  🔴 Просто пропустить его нельзя: неиспользуемая переменная в Go — ошибка компиляции,
  подчёркивание это официальный способ сказать «значение не нужно».
  arg — очередной аргумент, строка.

  os.Args — срез строк со всем, что было в командной строке. Под номером 0 лежит путь
  к самой программе, аргументы пользователя начинаются с номера 1.
  os.Args[1:] — срез среза (по-русски «ломоть»): взять всё начиная с номера 1 и до
  конца. Двоеточие без второго числа значит «до самого конца».
  🔴 Забудешь [1:] — программа напечатает ещё и путь к своему исполняемому файлу.

  🔴 Если аргументов нет, os.Args[1:] пустой, тело цикла не выполнится ни разу, и
  программа не напечатает НИЧЕГО. Условие требует именно этого — никакой пустой строки
  печатать не надо.

		arg := []rune(arg)
  Внутри цикла создаётся НОВАЯ переменная с тем же именем arg, но другого типа —
  срез рун. Это называется затенение (shadowing): внутри тела цикла имя arg теперь
  означает срез рун, а старая строка на время скрыта. Приём законный, но именно
  затенение чаще всего сбивает с толку при чтении.
  Знак := здесь обязателен: он создаёт новую переменную. Простое = не сработало бы,
  потому что нельзя положить срез рун в переменную типа string.

  Руна — это один символ целиком (число, код символа). Строку в Go напрямую менять
  нельзя — она неизменяемая, записать s[0] = 'X' компилятор запретит. Поэтому строку
  превращают в срез рун, который менять МОЖНО, а в конце собирают обратно.

		for j, r := range arg {
  Внутренний цикл по символам одного аргумента.
  j — номер символа, r — сам символ (руна).
  🔴 Важная деталь: здесь range идёт по СРЕЗУ рун, а не по строке. При range по срезу
  номера идут подряд: 0, 1, 2, 3... При range по строке номера были бы байтовые и для
  многобайтовых символов перескакивали бы. Именно поэтому дальше можно спокойно писать
  arg[j+1] — соседний символ действительно лежит под соседним номером.

			if j+1 == len(arg) || arg[j+1] == ' ' {
  Проверка «этот символ — последний в своём слове».
  || это «или»: истинно, если истинна хотя бы одна часть.
  j+1 == len(arg) — следующего символа не существует, значит мы на самом конце
  аргумента (номера идут до len(arg)-1, поэтому j+1 == len(arg) означает «j последний»).
  arg[j+1] == ' ' — следующий символ пробел, значит слово тут кончается.

  🔴 ЛОВУШКА ПОРЯДКА. Проверка на конец строки стоит ПЕРВОЙ не случайно. Оператор ||
  ленивый: если левая часть истинна, правая вообще не вычисляется. На последнем символе
  левая часть истинна, поэтому до arg[j+1] дело не доходит. Переставь части местами — и
  на последнем символе получишь обращение за границу среза и панику
  «index out of range».

				arg[j] = unicode.ToUpper(r)
  Последняя буква слова — делаем её заглавной. unicode.ToUpper берёт руну и возвращает
  её заглавный вариант; если символ не буква (цифра, запятая), он возвращается
  без изменений.
  Знак = здесь именно присваивание существующему элементу среза, поэтому := было бы
  ошибкой: arg[j] — не новая переменная, а ячейка уже существующего среза.
  Запись идёт в тот же самый элемент, из которого r был прочитан на этом витке,
  поэтому ничего не портится: r уже скопирован, а arg[j+1] ещё не тронут.

			} else {
  Иначе (символ не последний в слове).
  🔴 else обязан стоять на одной строке с закрывающей скобкой предыдущего блока —
  таково правило Go.

				arg[j] = unicode.ToLower(r)
  Все прочие символы делаем строчными. Если символ не буква — остаётся как был.

			}
  Конец if/else.

		}
  Конец внутреннего цикла по символам.

		fmt.Println(string(arg))
  string(arg) собирает срез рун обратно в строку.
  fmt.Println печатает её и САМ добавляет перевод строки в конце — по условию каждый
  аргумент печатается отдельной строкой.
  🔴 Печать стоит внутри внешнего цикла, значит выполняется по разу на каждый аргумент.
  Вынесешь наружу — напечатается только последний.

	}
  Конец внешнего цикла по аргументам.

}
  Конец main.

ЛОВУШКИ ЗАДАНИЯ
  🔴 Апостроф границей слова НЕ считается. Проверь на "IT'S": символы I, T, ', S.
     У ' следующий символ S, не пробел — значит ' идёт в ветку ToLower и остаётся
     апострофом. У S следующего символа нет — он становится заглавным. Итог "it'S".
  🔴 Строку в Go нельзя изменить по номеру символа. Отсюда весь приём с []rune и
     обратной сборкой через string().
  🔴 Нет аргументов — нет вывода вообще, даже пустой строки.
  🔴 Println добавляет \n сам; вручную приклеивать "\n" не нужно, иначе будет лишняя
     пустая строка.


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * []byte — срез байтов; в отличие от строки, его элементы можно изменять.
  * байт (byte) — число от 0 до 255; один символ ASCII занимает ровно один
  байт.
  * ASCII — таблица кодов символов, где 'A' = 65, 'Z' = 90, 'a' = 97, 'z' =
  122.
  * символьная константа ('A') — запись символа в одинарных кавычках, для
  компилятора это просто число (его код).
  * строка в Go неизменяема — присвоить отдельный символ строке нельзя,
  нужна копия в виде среза.
  * string(b) — преобразование среза байтов обратно в строку.
  * || — логическое «или»: истинно, если истинна хотя бы одна часть; правая
  часть не вычисляется, когда левая уже истинна.
  * len(b)-1 — индекс последнего элемента среза, потому что индексация
  начинается с нуля.
  * классический цикл for i := 0; i < len(b); i++ — обход по индексам, нужен
  когда надо заглядывать на соседние элементы.
  * += и -= — «прибавь к текущему значению» и «вычти из текущего значения».
  * os.Args[1:] — аргументы пользователя без пути к программе.

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Функция SaveAndMiss получает строку и целое число num. Строка мысленно
  режется на куски длиной num подряд идущих символов: первый кусок
  сохраняем, второй пропускаем, третий сохраняем, четвёртый пропускаем и так
  до конца строки. Возвращаем строку, собранную из сохранённых символов.
  Если num равен нулю или отрицателен, функция возвращает исходную строку
  без изменений.


------------------------------------------------------------------------------
  ПРОТОТИП — переписывать БУКВА В БУКВУ
------------------------------------------------------------------------------
    func SaveAndMiss(arg string, num int) string {
    
    }

  Бот школы сверяет подпись функции посимвольно. Другое имя, другой порядок
  или тип параметров, лишний или недостающий возврат — задача не засчитана.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано строку и размер куска, надо вернуть строку из «чётных» кусков. Первым
  делом обрабатываем граничное правило: если num меньше или равен нулю,
  сразу возвращаем исходную строку. Это не только требование README, но и
  защита: при num равном нулю деление i/num вызвало бы аварийную остановку
  «integer divide by zero». Дальше главный вопрос — как понять, к какому
  куску относится символ с индексом i, не заводя отдельных счётчиков и
  переключателей. Ответ даёт целочисленное деление: номер куска это ровно
  i/num, потому что при делении целых чисел дробная часть отбрасывается —
  индексы 0,1,2 при num = 3 все дают 0, индексы 3,4,5 дают 1, и так далее.
  Сохраняем кусок номер 0, пропускаем номер 1, сохраняем номер 2 — то есть
  сохраняем, когда номер куска чётный, а чётность проверяется остатком от
  деления на два: (i/num)%2 == 0. В итоге весь алгоритм это один цикл по
  индексам и одно условие, без флага «сейчас сохраняем или пропускаем»,
  который легко забыть перевернуть. Ответ копим в переменной result и
  добавляем к ней arg[i:i+1] — кусочек строки длиной один символ; писать
  result += arg[i] нельзя, потому что arg[i] это байт, то есть число, а
  число со строкой не складывается. Проверяем на примере README: "123456789"
  при num = 3 даёт куски "123" (номер 0, берём), "456" (номер 1,
  пропускаем), "789" (номер 2, берём) — получается "123789", совпадает.
  Неполный последний кусок обрабатывается сам собой: цикл просто закончится
  на последнем индексе. Пустая строка тоже обрабатывается сама: цикл не
  выполнится ни разу и вернётся пустая строка.


------------------------------------------------------------------------------
  ГОТОВОЕ РЕШЕНИЕ
------------------------------------------------------------------------------
    package piscine
    
    func SaveAndMiss(arg string, num int) string {
    	if num <= 0 || num > len(arg) {
    		return string(arg)
    	}
    	_str := ""
    	for i := 0; i < len(arg); i++ {
    		if i != 0 && i%num == 0 {
    			i += num
    			if i > len(arg)-1 {
    				break
    			}
    		}
    		if i != len(arg) {
    			_str += string(rune(arg[i]))
    		}
    	}
    	return _str
    }

package piscine
  Имя пакета. Задание-функция — значит piscine. Импортов нет: ни один пакет не нужен.

func SaveAndMiss(arg string, num int) string {
  Функция принимает строку arg и целое num, возвращает строку.
  Имя с большой буквы, чтобы тест школы её увидел.
  Смысл задачи: строка мысленно режется на куски по num символов, куски берутся
  через один — первый сохраняем, второй пропускаем, третий сохраняем, и так далее.

	if num <= 0 || num > len(arg) {
  Защита от бессмысленных значений num, проверяются сразу два случая.
  || — логическое ИЛИ, оно ленивое: если левая часть истинна, правая не считается.
  num <= 0 — по условию при нуле и минусе строка возвращается как есть.
  num > len(arg) — кусок длиннее всей строки. Тогда вся строка и есть тот самый
  первый «сохраняемый» кусок, пропускать нечего.
  len(arg) — длина строки в БАЙТАХ.
  🔴 Без второй половины условия код сломался бы на i += num: индекс улетел бы
  за конец строки. Обе половины нужны.

		return string(arg)
  Возврат исходной строки. string(arg) — преобразование строки в строку, то есть
  ничего не делающая операция; можно было написать просто return arg.
  Ранний выход: дальше функция уже не идёт.

	}
  Конец проверки.

	_str := ""
  Накопитель — переменная, в которую по ходу цикла будет прирастать ответ.
  Начинается с пустой строки.
  := создаёт новую переменную и сразу кладёт в неё значение (тип string выведется сам).
  🔴 Подчёркивание в начале имени — просто часть имени, никакого особого смысла в Go
  оно не несёт. Особый смысл имеет только одиночный символ _ — «выбросить значение».

	for i := 0; i < len(arg); i++ {
  Классический цикл со счётчиком, три части через точку с запятой:
  i := 0 — создаём счётчик и ставим на 0, потому что индексы строки начинаются с нуля;
  i < len(arg) — условие продолжения;
  i++ — увеличить i на единицу после каждого прохода тела.
  🔴 Здесь строго <, а не <=. Последний существующий индекс — len(arg)-1;
  при <= обращение к arg[len(arg)] уронило бы программу с ошибкой
  index out of range.

		if i != 0 && i%num == 0 {
  Определяем момент, когда закончился очередной сохраняемый кусок и начинается
  пропускаемый.
  % — остаток от деления. i%num == 0 значит «i кратно num», то есть i стоит
  ровно на границе кусков.
  i != 0 стоит ПЕРВЫМ и обязательно: ноль тоже кратен любому num, но самый первый
  кусок мы обязаны сохранить, а не пропустить. && ленивое, поэтому при i == 0
  остаток даже не вычисляется.

			i += num
  Прыжок через пропускаемый кусок: сокращение для i = i + num.
  🔴 Это изменение счётчика ВНУТРИ тела цикла. Оно складывается с обычным i++
  из заголовка, поэтому за один проход тела индекс сдвигается на num+1.
  Именно так и надо: после прыжка мы попадаем на первый символ следующего
  сохраняемого куска, тут же его записываем, а i++ переводит нас на следующий.

			if i > len(arg)-1 {
  После прыжка проверяем, не вышли ли мы за конец строки.
  len(arg)-1 — последний допустимый индекс.

				break
  Выход из цикла. Без этого следующая строка обратилась бы к несуществующему
  индексу и программа упала бы.

			}
  Конец внутренней проверки.

		}
  Конец блока прыжка.

		if i != len(arg) {
  Ещё одна страховка от выхода за границу перед обращением к символу.
  Честно говоря, сработать она не может: если бы i дорос до len(arg), нас бы
  уже выкинуло по break выше или по условию цикла. Строка лишняя, но она есть
  в эталоне — значит на экзамене её просто оставляем.

			_str += string(rune(arg[i]))
  Дописываем символ в накопитель. += это _str = _str + ....
  Разбираем матрёшку изнутри:
  arg[i] — один БАЙТ строки, тип byte (это то же самое, что uint8).
  rune(arg[i]) — преобразование байта в руну, то есть в код символа Unicode.
  string(...) — преобразование руны в строку из одного символа.
  🔴 Без преобразования не обойтись: string(arg[i]) без rune компилятор Go
  ругает предупреждением, а склеить строку с байтом через + нельзя вообще.
  🔴 Для латиницы и цифр байт и символ совпадают, всё честно. Для кириллицы
  один символ занимает два байта, и такая порезка даст мусор. Тесты школы
  на этом задании подают латиницу.

		}
  Конец проверки.

	}
  Конец цикла.

	return _str

ПРОГОН НА ПАЛЬЦАХ, SaveAndMiss("abcdefghij", 2):
  i=0 → i==0, прыжка нет → пишем 'a' → i становится 1
  i=1 → 1%2=1, прыжка нет → пишем 'b' → i становится 2
  i=2 → 2%2=0 → прыжок i=4, за конец не вышли → пишем 'e' → i становится 5
  i=5 → 5%2=1 → пишем 'f' → i становится 6
  i=6 → 6%2=0 → прыжок i=8 → пишем 'i' → i становится 9
  i=9 → 9%2=1 → пишем 'j' → i становится 10, цикл кончился
  Итог: "abefij" — сохранили ab, пропустили cd, сохранили ef, пропустили gh, сохранили ij.

  котором они идут в командной строке: сначала символы первого аргумента,

------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано две строки, надо получить строку из всех встречающихся в них символов
  без повторов. Порядок задан фразой «в том же порядке, в котором символы
  появляются в командной строке» — то есть сначала весь первый аргумент,
  потом весь второй. Раз порядок именно такой, ничего не мешает склеить оба
  аргумента в одну строку через args[0] + args[1] и пройти по ней один раз
  одним циклом; отдельные проходы по каждой строке дадут тот же результат,
  но кода будет больше. Для «без повторов» нужен ответ на вопрос «этот
  символ уже в ответе?». Отдельный список хранить не надо: накопленный
  result и есть список уже выведенных символов, поэтому условие добавления
  ровно одно — символа ещё нет в result. Проверку «есть ли символ в строке»
  выносим в маленькую функцию, которая пробегает строку и возвращает true
  или false. Отличие этой задачи от inter и hiddenp — в поведении при
  неверном числе аргументов: здесь README прямо показывает, что go run . без
  аргументов через cat -e печатает $, то есть надо вывести перевод строки, а
  не промолчать. Правильность трактовки порядка стоит проверить на третьем
  примере README: "rien" плюс "cette phrase ne cache rien" даёт "rienct
  phas" — сначала r,i,e,n из первой строки, затем новые c,t,пробел,p,h,a,s
  из второй. Пробел здесь виден в ответе, значит он считается обычным
  символом и никак не выделяется.

    			}
    		}

    			}
    		}
    		fmt.Print(res)
    	}
    	fmt.Println()
    }

  По сути это та же задача, что hiddenp: надо понять, является ли первая

  означающий «сколько первых символов первой строки уже собрано». Берём

  нет никогда, и это ровно то, что означает требование «не нарушая порядок»:
  каждый символ второй строки используется не более одного раза и только в
  том месте, где он встретился. Жадный выбор самого раннего совпадения
  корректен, потому что после раннего совпадения остаётся более длинный
  хвост второй строки для остальных символов. После цикла: если i дорос до
  len(s1), собрали всё — печатаем args[0] и перевод строки, иначе не
  печатаем вообще ничего, даже пустой строки. Печатать надо именно исходный
  args[0], а не накопленную строку: они совпадают, поэтому копить нечего.

    func ok(s1 string, s2 string) bool {
    	runes1 := []rune(s1)
    	runes2 := []rune(s2)
    	var rest string
    	count := 0
    	for i := 0; i < len(runes1); i++ {
    		for j := count; j < len(runes2); j++ {
    			if runes1[i] == runes2[j] {
    				rest += string(runes1[i])
    				j = len(runes2) - 1
    			}
    			count++
    		}
    	}
    	return s1 == rest
    }
    
    func main() {
    	if len(os.Args) == 3 {
    		if ok(os.Args[1], os.Args[2]) {
    			fmt.Println(os.Args[1])
    		}
    	}
    }

package main
  Задача: проверить, встречаются ли все символы первой строки во второй
  ПО ПОРЯДКУ (не обязательно подряд).

  Приём — два указателя. Один идёт по первой строке (что ищем),
  другой по второй (где ищем). Совпал символ — сдвигаем оба.
  Не совпал — сдвигаем только второй.

  В конце проверяется, дошёл ли первый указатель до конца своей строки.
  Дошёл — значит все символы нашлись по порядку, печатается первая строка.
  Не дошёл — печатается пустая строка.

  Аргументов не два — программа молчит.


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * подпоследовательность — символы, взятые из строки по порядку, но,
  возможно, с пропусками.
  * жадный алгоритм — способ решения, при котором на каждом шаге берётся
  первый подходящий вариант без перебора остальных.
  * счётчик-указатель — переменная, хранящая, до какого места мы дошли в
  другой строке.
  * os.Args — срез аргументов командной строки; нулевой элемент это путь к
  программе.
  * срез (slice) — список значений переменной длины с доступом по индексу от
  нуля.
  * руна (rune) — один символ Unicode в виде числа.
  * []rune(s) — преобразование строки в срез рун, после которого индексация
  идёт по символам.
  * range по строке — цикл, выдающий пару «позиция в байтах, символ».
  * && — логическое «и»; правая часть не вычисляется, если левая ложна, и
  это спасает от выхода за границу среза.
  * len — число элементов среза или число байтов строки.
  * os.Stdout.WriteString — печать строки как есть, без добавлений.
  * index out of range — аварийная остановка при обращении к несуществующему
  элементу.


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Убрать проверку i < len(s1) — как только первая строка собрана, а вторая
  ещё идёт, s1[i] выйдет за границу и программа упадёт.
  * Решать через «каждый символ первой строки где-то есть во второй»: пример
  "error" и "rrerrrfiiljdfxjyuifrrvcoojh" должен дать пустой вывод, а такая
  проверка ошибочно даст ответ.
  * Печатать при неудаче пустую строку, ноль или сообщение — README требует
  не печатать ничего.
  * При числе аргументов не 2 тоже не печатать ничего (в union наоборот —
  там нужен перевод строки).
  * Обратиться к args[0]/args[1] до проверки их количества.
  * Забыть, что пробел это обычный символ: строка "quarante deux" требует,
  чтобы во второй строке нашёлся и пробел в нужном месте.
  * Забыть кавычки при передаче аргумента с пробелами — оболочка разобьёт
  его, и аргументов станет больше двух, а программа промолчит.
  * Печатать не args[0], а вторую строку или накопленную переменную.
  * Забыть \n после напечатанной строки.
  * Пустая первая строка считается собранной: печатается пустая строка с
  переводом строки.
