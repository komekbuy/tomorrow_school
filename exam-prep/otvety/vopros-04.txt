  Функция получает строку и должна вернуть её в записи snake_case: перед
  каждой заглавной буквой ставится знак подчёркивания. Если строка пустая —
  вернуть пустую строку. Если строка не является правильным camelCase —
  вернуть её без изменений. Правильным camelCase считается строка, которая
  состоит только из букв (без цифр и знаков), не заканчивается заглавной
  буквой и не содержит двух заглавных букв подряд. Буквы при переводе НЕ
  меняют регистр: "HelloWorld" превращается в "Hello_World".

  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дана строка, надо вернуть строку. Первым делом посмотри на ожидаемый вывод
  в задании: "HelloWorld" даёт "Hello_World", а не "hello_world". Значит
  регистр букв не меняется вообще, вся работа — вставить знак подчёркивания
  перед заглавными буквами. Это очень простое действие. Вторым делом
  посмотри, какие строки остались без изменений: "CAMELtoSnackCASE" и
  "hey2". Первая содержит две заглавные буквы подряд, вторая содержит цифру.
  Значит перед вставкой подчёркиваний надо проверить, является ли строка
  вообще правильным camelCase. Отсюда следует структура решения из двух
  отдельных этапов: сначала проверка, потом сборка. Смешивать их в один цикл
  нельзя, потому что нарушение может обнаружиться в конце строки, а к тому
  моменту ты уже что-то собрал. Условие даёт три запрета, и каждый
  превращается в одну проверку внутри первого цикла: символ не буква —
  выход; заглавная буква стоит последней — выход; заглавная буква и перед
  ней тоже заглавная — выход. Слово "выход" здесь значит return s, то есть
  вернуть исходную строку целиком, не изменив её. Если первый цикл дошёл до
  конца и ни разу не сработал, строка правильная, и можно собирать ответ. Во
  втором цикле идём по символам и перед каждой заглавной, кроме самой первой
  позиции, добавляем подчёркивание. Позицию ноль надо исключить отдельно,
  иначе "HelloWorld" даст "_Hello_World". Пустая строка обрабатывается сама
  собой: оба цикла не выполнятся ни разу, и вернётся пустая переменная
  result.

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: Подчёркивание ставится перед заглавной буквой
  только тогда, когда СЛЕДУЮЩАЯ за ней буква строчная. Поэтому в подряд
  идущих заглавных подчёркивание попадёт лишь перед последней из них. Если
  строка содержит что-то кроме букв — она возвращается без изменений.

    	return s >= 'A' && s <= 'Z'

    func CamelToSnakeCase(s string) string {
    	result := ""
    	if len(s) == 0 || !containOnlyAlphabet(s) {
    		return s
    	}
    	for i := 0; i < len(s); i++ {
    		if i != 0 && isUpper(rune(s[i])) && i+1 < len(s) && !isUpper(rune(s[i+1])) {
    			result += "_"
    			result += string(s[i])
    		} else if !isUpper(rune(s[i])) || (i == 0 && isUpper(rune(s[i]))) {
    			result += string(s[i])
    		} else {
    			return s
    		}
    	}
    	return result
    }

------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * строка (string) — последовательность символов, например "hello"; в Go
  строку нельзя изменить, можно только собрать новую
  * байт (byte) — число от 0 до 255; каждая латинская буква хранится в
  строке как один байт с кодом этой буквы
  * s[i] — обращение к байту строки по номеру позиции; нумерация начинается
  с нуля
  * len(s) — встроенная функция, возвращающая длину строки в байтах
  * bool — тип из двух значений: true (истина) и false (ложь)
  * && — логическое «и»: всё выражение истинно, только если истинны обе
  части
  * ! — логическое «не»: превращает истину в ложь и наоборот
  * string(c) — преобразование байта в строку из одного символа, чтобы его
  можно было склеить с другой строкой
  * += — сокращение записи «прибавь к переменной»: result += "_" это то же
  самое, что result = result + "_"
  * return — немедленно завершает функцию и отдаёт указанное значение
  вызвавшему коду
  * руна (rune) — целое число, обозначающее один символ Юникода; для
  латиницы можно обойтись байтами, но для русских букв нужны именно руны,
  так как одна русская буква занимает два байта

  * Забыть проверку на цифры и знаки — тогда "hey2" превратится в что-то

  * Ставить подчёркивание перед каждой заглавной. Тогда подряд идущие
  заглавные разъедутся.
  * Забыть, что строка с цифрами или знаками возвращается как есть, без

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Программа получает из командной строки одну строку и печатает её «чистой»:
  между словами ровно один пробел, в начале и в конце пробелов и табов нет,
  в конце добавляется перевод строки. Словом считается кусок строки между
  пробелами/табами (или между началом/концом строки и пробелом). Если
  аргументов не ровно один, либо слов в строке нет вообще, программа
  печатает просто перевод строки.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано: строка, в которой пробелы и табы расставлены как попало. Надо: та же
  последовательность слов, но разделитель ровно один пробел, и по краям
  чисто. Первое наблюдение: задача не про «удалить лишние пробелы», а про
  «найти слова и склеить их заново». Если думать через удаление, придётся
  ловить кучу случаев (два пробела подряд, таб рядом с пробелом, пробел в
  самом начале). Если думать через сборку — все эти случаи исчезают сами,
  потому что разделители мы вообще не переносим, мы их печатаем сами. Приём
  называется «два указателя в одном проходе»: одна переменная-счётчик i идёт
  по строке слева направо; сначала она проматывает все подряд идущие
  разделители, потом запоминает позицию начала слова и проматывает все
  не-разделители до конца слова. Кусок строки между этими двумя позициями и
  есть слово. Дальше вопрос: куда ставить пробел — перед словом или после?
  Если ставить после каждого слова, в конце останется лишний пробел, который
  придётся отрезать. Поэтому ставим ПЕРЕД словом, но только если в
  накопителе уже что-то есть — тогда перед первым словом пробел не появится,
  а между всеми остальными появится ровно один. Проверку количества
  аргументов делаем самой первой строкой, до всякой работы: os.Args[0] — это
  имя самой программы, значит одна переданная строка означает длину os.Args
  равную 2. И последнее: когда слов нет вообще (пустая строка, одни
  пробелы), накопитель останется пустым, и последняя строка напечатает
  пустой накопитель плюс перевод строки — то есть ровно тот перевод строки,
  который требует условие. Отдельную ветку под это писать не нужно.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

  🔴 Вся полезная работа лежит ВНУТРИ этого if. Если аргументов ноль или больше одного — тело пропускается целиком.

  Компиляция шаблона — перевод текста шаблона в готовый к работе объект. Делается один раз, потом объектом пользуются.
  Обратные кавычки ` ` — «сырая» строка: внутри неё обратный слэш и пробелы берутся буквально, без обработки. Для шаблонов это стандартный приём.

  re — имя получившегося объекта-шаблона.

		fmt.Print(re.ReplaceAllString(strings.Trim(os.Args[1], " "), " "))
  Читается изнутри наружу:
  strings.Trim(os.Args[1], " ") — срезает с ОБОИХ краёв строки все символы из второго аргумента. Второй аргумент — это НАБОР символов, а не подстрока; здесь в наборе один символ — пробел;

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Программа получает из командной строки одну строку и печатает её так, что
  между словами стоит ровно три пробела, а в начале и в конце пробелов и
  табов нет. В конце добавляется перевод строки. Словом считается
  непрерывная последовательность видимых символов. Если аргументов не ровно
  один или слов в строке нет, программа не печатает вообще ничего — даже
  перевода строки.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Это та же задача, что cleanstr, с двумя отличиями, и именно на этих двух
  отличиях люди и заваливаются. Отличие первое: разделитель между словами не
  один пробел, а три. Отличие второе, и оно важнее: при неверном вводе не
  печатается НИЧЕГО, тогда как в cleanstr печатается перевод строки. Значит
  копировать cleanstr целиком нельзя, надо поменять две вещи. Ход мысли по
  самому алгоритму тот же: не пытаться чинить пробелы внутри исходной
  строки, а вырезать из неё слова и собрать ответ заново, самому расставляя
  разделители. Идём по строке одной переменной-счётчиком i: сначала
  проматываем подряд идущие пробелы и табы, потом запоминаем позицию начала
  слова и проматываем непробельные символы до его конца, вырезаем кусок
  между этими позициями. Разделитель дописываем перед словом и только когда
  накопитель уже не пуст — так первое слово остаётся без отступа, а
  хвостового разделителя не возникает вовсе. По выводу: сначала проверяем
  количество аргументов, и если их не один — просто выходим, ничего не
  печатая. Потом, уже после сборки, проверяем накопитель: если он пуст,
  значит слов не нашлось, и по условию тоже надо выйти молча. Печать
  перевода строки должна стоять после этой проверки, иначе на пустом вводе
  программа выдаст лишнюю пустую строку и тест не пройдёт.

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: 🔴 Поведение в краевых случаях взято из ЭТАЛОНА
  школы, а не из текста задания — они местами расходятся, а бот сверяет
  ответ именно с эталоном. Обрати внимание, что происходит при отсутствии
  аргументов и при пустом результате: молчание и печать пустой строки — это
  разные вещи, и бот их различает.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот

	"fmt"

  fmt — печать (Println).
  os — доступ к операционной системе, отсюда берутся аргументы командной строки.

func deleteExtraSpaces(a []string) (res []string) {
  Вспомогательная функция. Имя с маленькой буквы — она нужна только внутри этого файла.
  Параметр a типа []string — срез строк. Срез это список элементов переменной длины; []string читается «срез строк».
  (res []string) в скобках после параметров — именованный результат: переменная res объявляется прямо в заголовке функции и сразу существует внутри неё. Её начальное значение — nil, то есть «пустой срез, под который ещё не выделена память».

	for _, v := range a {
  Цикл по всем элементам среза a. range на каждом проходе выдаёт ДВА значения: индекс элемента и сам элемент.
  _ — подчёркивание на месте индекса означает «это значение мне не нужно, выбрось». 🔴 Просто пропустить его нельзя: Go не соберёт код, если объявленная переменная не используется, поэтому и придумано подчёркивание.
  v — очередная строка из среза. := создаёт _ и v заново на каждом проходе.

		if v != "" {
  Берём только непустые куски. != — «не равно».

			res = append(res, v)
  append добавляет элемент в конец среза и ВОЗВРАЩАЕТ новый срез — поэтому результат обязательно присваивают обратно в res. Написать просто append(res, v) без присваивания бесполезно, значение потеряется.
  append спокойно работает с nil-срезом: первый вызов сам создаст под него память.

		}
	}
	return
  Голый return — без значения после него. Так можно только при именованном результате: функция вернёт то, что лежит в res на этот момент.

}
  Конец вспомогательной функции. Итог её работы: из среза выброшены все пустые строки, остались только настоящие слова.

func main() {
  Точка входа программы.

	if len(os.Args) == 2 {
  os.Args — срез строк с аргументами командной строки. 🔴 os.Args[0] — это ВСЕГДА имя самой программы, а не первый аргумент. Поэтому «ровно один аргумент от пользователя» записывается как длина 2: имя программы плюс аргумент.
  Если условие ложно, тело if не выполняется, программа просто заканчивается и не печатает ничего — это и есть требование «при неверном числе аргументов молчать». Отдельного else с сообщением об ошибке быть не должно.

		arg := strings.Split(os.Args[1], " ")
  os.Args[1] — сам аргумент, строка. strings.Split режет её на куски по разделителю, здесь разделитель — один пробел " ". Результат — срез строк, кладём его в новую переменную arg (:= создаёт).
  🔴 Split режет ровно по одному пробелу и НЕ схлопывает подряд идущие. Из "a   b" получится ["a", "", "", "b"] — между словами появляются пустые строки. Пробелы по краям тоже дают пустые строки по краям среза. Именно ради этого мусора и написана deleteExtraSpaces.

		arg = deleteExtraSpaces(arg)
  Вызываем вспомогательную функцию и кладём результат обратно в ту же переменную. Один знак = — присваивание, arg уже создана строкой выше. После этой строки в arg лежат только слова, без пустых кусков.

		fmt.Println(strings.Join(arg, "   "))
  strings.Join — обратная операция к Split: склеивает все элементы среза в одну строку, вставляя между ними указанный разделитель. Здесь разделитель — ТРИ пробела, как требует условие.
  🔴 Join ставит разделитель только МЕЖДУ элементами, не до первого и не после последнего. Поэтому пробелы по краям не появляются сами собой — отдельно обрезать ничего не нужно.
  Println печатает результат и добавляет перевод строки в конце.

	}
}
  Закрываются if и main.

Проверено запуском:
  "  Hello   World  " → "Hello   World" и перевод строки. Верно.
  🔴 "a\tb" (с табом) → "a\tb" — таб остаётся на месте. Эталон режет ТОЛЬКО по пробелу, табы он разделителем не считает, хотя условие говорит о видимых символах.
  🔴 Пустой аргумент или аргумент из одних пробелов → эталон печатает ОДИН перевод строки, а не полное молчание: Join от пустого среза даёт "", а Println всё равно ставит \n.   разделение. Первая часть: уметь отвечать на вопрос «данное число простое
  или нет». Вторая часть: перебирать числа вниз от заданного и спрашивать

  каждая часть по отдельности проста, а вместе, в одной функции с вложенными
  циклами, легко запутаться. Что такое простое число: целое число больше
  единицы, которое делится без остатка только на 1 и на само себя. Отсюда
  сразу два следствия. Первое: числа меньше 2 (то есть 1, 0 и все
  отрицательные) простыми не бывают никогда, это отдельная проверка в самом
  начале. Второе: чтобы проверить число nb, достаточно попробовать поделить
  его на все числа от 2 и выше; если ни одно не поделило нацело — число
  простое. Дальше важная оптимизация, ради которой стоит подумать:
  перебирать делители до самого nb не нужно. Если nb делится на какое-то
  число a, то есть и парный делитель b, причём nb = a * b. Один из этой пары
  обязательно не больше квадратного корня из nb — иначе их произведение было
  бы больше nb. Значит если до квадратного корня делителей не нашлось, то их
  нет вообще. Записывать это через корень необязательно и даже нежелательно
  (потребуется пакет math и дробные числа), достаточно условия i*i <= nb —
  оно означает ровно то же самое, но целыми числами. Вторая часть
  тривиальна: цикл от nb вниз с шагом минус один, до 2 включительно, и
  первое же простое возвращаем. Если цикл закончился и ничего не нашлось —
  значит nb был меньше 2, и по условию возвращаем 0. Замечание про имя
  вспомогательной функции: пакет piscine общий на все задания, поэтому её
  нельзя назвать просто isPrime — имя может уже быть занято другим заданием.
  Отсюда префикс findprevprime.

    package piscine
    
    func findprevprimeIsPrime(nb int) bool {
    	if nb < 2 {
    		return false
    	}
    	for i := 2; i*i <= nb; i++ {
    		if nb%i == 0 {
    			return false
    		}
    	}
    	return true
    }
    
    func FindPrevPrime(nb int) int {
    	for n := nb; n >= 2; n-- {
    		if findprevprimeIsPrime(n) {
    			return n
    		}
    	}
    	return 0
    }

func FindPrevPrime(nb int) int {
  Основная функция задания. Имя с БОЛЬШОЙ буквы — иначе тест школы её не увидит.
  Принимает int, возвращает int.
  По условию: вернуть ближайшее простое число, меньшее ИЛИ РАВНОЕ nb.

	for n := nb; n >= 2; n-- {
  Цикл, идущий ВНИЗ. Три части заголовка:
  n := nb — создаём собственный счётчик и ставим его на само переданное число.
  🔴 Именно поэтому «или равное» работает: первым делом проверяется сам nb.
  n >= 2 — условие продолжения; ниже двойки простых чисел нет, спускаться дальше
  бессмысленно.
  n-- — уменьшение на единицу после каждого прохода (в отличие от обычного i++).
  🔴 Отдельная переменная n нужна, чтобы не портить параметр nb. Технически nb —
  копия и портить её можно, но с отдельным счётчиком код читается однозначно.

  Вызов вспомогательной функции. Она возвращает bool, поэтому результат ставится
  в if напрямую — писать == true не нужно и не принято.

  простое и есть ближайшее снизу. Дальше искать нечего.
  🔴 Здесь return, а не break: break вышел бы только из цикла, а результат надо

  * простое число — целое число больше 1, которое делится без остатка только
  на 1 и на себя; 2, 3, 5, 7, 11 и так далее
  * составное число — целое число больше 1, у которого есть делитель,
  отличный от 1 и себя самого
  * bool — тип данных с двумя значениями: true (истина) и false (ложь)
  * % — операция взятия остатка от деления; 7%3 равно 1, а 6%3 равно 0
  * int — тип целого числа; на современных компьютерах занимает 64 бита
  * вспомогательная функция — отдельная функция, вынесенная ради того, чтобы

  * экспортируемое имя — имя, начинающееся с заглавной буквы; только такие
  функции видны из других пакетов, поэтому FindPrevPrime обязана быть с
  большой буквы
  * неэкспортируемое имя — имя со строчной буквы, видное только внутри
  своего пакета
  * for с тремя частями — цикл вида for инициализация; условие; шаг, где
  инициализация выполняется один раз, условие проверяется перед каждым
  проходом, шаг — после каждого
  * i*i <= nb — целочисленная замена проверки «i не больше квадратного корня

  * -- — уменьшение переменной на единицу
  * ранний возврат — приём, когда функция выходит сразу, как только ответ
  известен, вместо того чтобы досчитывать цикл до конца


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Считать 1 простым числом. Тогда FindPrevPrime(1) вернёт 1 вместо 0, и
  тест провалится.
  * Забыть, что само nb тоже кандидат. Условие говорит «equal or inferior»,
  поэтому цикл должен начинаться с n := nb, а не с n := nb-1. Иначе
  FindPrevPrime(5) вернёт 3 вместо 5.
  * Не обработать отрицательные числа и ноль. Цикл с условием n >= 2 в этом
  случае не выполнится ни разу и функция сразу дойдёт до return 0 — это
  правильное поведение, но если написать условие n >= 0 или n > 0, программа
  зациклится или вернёт мусор.
  * Проверять делители до nb включительно. Тогда nb%nb == 0 и любое число
  будет объявлено составным. Верхняя граница — квадратный корень, либо
  строго меньше nb.
  * Начинать перебор делителей с 1. Единица делит любое число, поэтому всё
  сразу окажется составным.
  * Использовать math.Sqrt и дробные числа — из-за неточности дробной
  арифметики граница может съехать на единицу. Целочисленное i*i <= nb
  надёжнее.
  * Назвать вспомогательную функцию просто isPrime. Пакет piscine общий, и
  другое задание может уже определить это имя — будет ошибка компиляции
  «redeclared in this block».
  * Написать имя функции со строчной буквы (findPrevPrime). Тестовая
  программа обращается к piscine.FindPrevPrime, и без заглавной буквы
  функция снаружи не видна.

  Начинать надо с проверки входных данных, потому что она отсекает всё
  остальное: если хоть одно число вне диапазона от 0 до 99, ответ известен

  направление счёта. Функция должна уметь считать и вверх (от 1 к 10), и
  вниз (от 10 к 1). Писать под это два отдельных цикла можно, но тогда
  одинаковый код придётся продублировать и любую правку вносить дважды.
  Лучше завести переменную-шаг: если from не больше to, шаг равен плюс
  единице, иначе минус единице. Тогда цикл один, а шаг просто прибавляется к
  текущему числу. Следующий вопрос — где ставить разделитель «, », чтобы он
  не появился после последнего числа. Приём: печатать число, затем
  проверять, не последнее ли оно, и если последнее — выходить из цикла ДО
  того, как допишется разделитель. Именно поэтому цикл написан в форме без
  условия продолжения, а выход сделан через break посередине тела: условие
  остановки должно сработать после числа, но перед запятой. Если бы условие
  стояло в заголовке цикла, разделитель успел бы приписаться. Отдельная
  подзадача — двузначная запись. Число надо превратить в две цифры: десятки
  и единицы. Десятки берутся целочисленным делением на 10, единицы —
  остатком от деления на 10. Для чисел меньше 10 десятки дают ноль, и
  ведущий ноль появляется сам собой, без всяких if. Цифру превращаем в
  символ, прибавляя её к коду символа '0': коды цифр в таблице символов идут
  подряд, поэтому '0' плюс 7 даёт символ '7'. Это стоит вынести в отдельную
  маленькую функцию с уникальным именем, потому что пакет piscine общий и
  короткие имена вроде twoDigits могут быть заняты другим заданием.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

    package piscine
    
    import "strconv"
    
    func FromTo(from, to int) string {
    	result := ""
    
    	if from > 99 || from < 0 || to > 99 || to < 0 {
    		return "Invalid\n"
    	} else if from == to && from < 10 {
    		return "0" + strconv.Itoa(from) + "\n"
    	}
    	if from > to {
    		for i := from; i >= to; i-- {
    			if i < 10 {
    				result += "0"
    			}
    			result += strconv.Itoa(i)
    			if i-1 >= to {
    				result += ", "
    			}
    		}
    		return result + "\n"
    	}
    	for i := from; i <= to; i++ {
    		if i < 10 {
    			result += "0"
    		}
    		result += strconv.Itoa(i)
    		if i+1 <= to {
    			result += ", "
    		}
    	}
    	return result + "\n"
    }

  **Накопитель** — пустая строка, которая дальше будет расти. `:=` создаёт новую переменную и сразу кладёт в неё значение; тип `string` Go выводит сам из `""`.

```go
	if from > 99 || from < 0 || to > 99 || to < 0 {
		return "Invalid\n"
	}
```
  Четыре проверки через `||` (ИЛИ): достаточно любой одной, чтобы вернуть ошибку. Проверяются **оба** числа, каждое с двух сторон.
  Границы включающие: 0 и 99 допустимы, поэтому `> 99` и `< 0`, а не `>= 99` и `<= 0`.
  🔴 `\n` в конце обязателен — это один невидимый символ перевода строки. Без него ответ не совпадёт.
  🔴 Проверка стоит **первой**, до любых вычислений. Это ранний выход: плохой ввод отсекается сразу.

```go
	} else if from == to && from < 10 {
		return "0" + strconv.Itoa(from) + "\n"
	}
```
  (в эталоне это `else if`, пришитый к предыдущему `if`)
  Отдельный случай: одно и то же число, меньше 10. Возвращается ведущий ноль, само число и перевод строки.
  `strconv.Itoa` = Integer to ASCII, превращает число в строку: `Itoa(5)` даёт `"5"`. Склеивать число со строкой через `+` напрямую Go не даст — типы разные.
  `&&` — «и»: нужны оба условия сразу.
  🔴 Эта ветка **ничего нового не делает**: обычный цикл ниже для `from == to == 5` тоже выдаёт `"05\n"`. Проверено запуском с удалённой веткой — результат совпадает для всех чисел от 0 до 9. В эталоне она есть, значит пиши как есть, но понимай, что это дубль, а не особый случай.

```go
	if from > to {
```
  Развилка по направлению счёта. Если начало больше конца — считаем вниз.
  🔴 Обрати внимание: тут новый `if`, а не `else`. Предыдущая пара `if`/`else if` уже завершилась.

```go
		for i := from; i >= to; i-- {
```
  Классический цикл со счётчиком, три части через точку с запятой:
  1. `i := from` — создать счётчик и положить в него начальное значение. Выполняется один раз.
  2. `i >= to` — условие продолжения, проверяется **перед** каждым проходом.
  3. `i--` — шаг, уменьшить на 1. Выполняется **после** каждого прохода.
  🔴 `>=`, а не `>` — иначе последнее число `to` не попало бы в вывод. Границы в этой задаче включающие с обеих сторон.
  🔴 `i` живёт только внутри цикла, снаружи его нет.

```go
			if i < 10 {
				result += "0"
			}
```
  Ведущий ноль для однозначных чисел: 5 должно печататься как `05`.
  `+=` для строк — дописать справа. То же, что `result = result + "0"`.

```go
			result += strconv.Itoa(i)
```
  Дописываем само число, превращённое в строку.

```go
			if i-1 >= to {
				result += ", "
			}
```
  🔴 Главный приём всего задания: **заглядывание вперёд**. Проверяем не текущее число, а следующее — `i-1` (счёт идёт вниз, значит следующим будет на единицу меньше). Если следующее ещё попадает в диапазон, значит текущее не последнее и после него нужен разделитель.
  🔴 Так разделитель ставится **между** числами, а не после каждого. Иначе в конце строки повис бы лишний `", "`.
  🔴 Разделитель — запятая **и пробел**, ровно в таком порядке. Одна запятая без пробела не подойдёт.

```go
		}
		return result + "\n"
	}
```
  Цикл закончился, дописываем перевод строки **один раз в самом конце** и выходим.
  🔴 `return` стоит вне цикла, но внутри блока `if from > to`. Именно этот выход не даёт коду провалиться в цикл возрастания ниже.

```go
	for i := from; i <= to; i++ {
```
  Сюда попадаем, только если `from <= to`, — потому что ветка `from > to` выше закончилась `return`. Отдельного `else` не нужно.
  Зеркальная копия предыдущего цикла: условие `<=` вместо `>=`, шаг `i++` вместо `i--`.

```go
		if i < 10 {
			result += "0"
		}
		result += strconv.Itoa(i)
```
  Ведущий ноль и само число — как выше, без изменений.

```go
		if i+1 <= to {
			result += ", "
		}
	}
```
  То же заглядывание вперёд, только следующее число теперь `i+1`, и сравнение с верхней границей `<= to`.

```go
	return result + "\n"
}
```
  Перевод строки один раз в конце, и возврат.
  🔴 Здесь у функции два разных `return result + "\n"` — по одному на каждое направление. Оба нужны: без первого код после цикла вниз пошёл бы в цикл вверх.

------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Проверять на диапазон только первое число. Условие говорит «any of the
  arguments» — оба. FromTo(10, 100) обязано вернуть Invalid.
  * Забыть перевод строки в конце. И у обычного результата, и у «Invalid» в
  конце должен быть \n, README показывает это символом $ в выводе cat -e.
  * Не поддержать обратный порядок. FromTo(10, 1) должно давать «10, 09,
  ..., 01», а не пустую строку и не Invalid.
  * Приписать разделитель после последнего числа: получится «01, 02, 10,
  \n». Выход из цикла должен происходить между числом и разделителем.
  * Забыть ведущий ноль. Ожидается «01», а не «1». Формула '0'+n/10 даёт его
  автоматически, отдельный if не нужен.
  * Считать, что 100 допустимо. Граница строгая: разрешён диапазон от 0 до
  99 включительно, 100 — уже Invalid.
  * Написать разделитель как "," без пробела. Нужны два символа: запятая и
  пробел.
  * Забыть случай from == to. Ответ — одно число и перевод строки, например
  FromTo(10,10) даёт «10\n». В коде это работает потому, что break
  проверяется сразу после первого дописанного числа.
  * Использовать strconv.Itoa вместо ручного превращения — на школьных
  проверках сторонние пакеты часто запрещены, и ведущий ноль всё равно
  придётся дописывать вручную.

------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Нужна функция, которая получает строку и отвечает true, если каждое слово
  в ней начинается либо с заглавной латинской буквы, либо с символа, не
  являющегося буквой (цифра, восклицательный знак и так далее). Если хотя бы
  одно слово начинается со строчной буквы — ответ false. Для пустой строки
  ответ тоже false. Слова разделяются пробелами.


------------------------------------------------------------------------------
  ПРОТОТИП — переписывать БУКВА В БУКВУ
------------------------------------------------------------------------------
    func IsCapitalized(s string) bool {
    
    }

  Бот школы сверяет подпись функции посимвольно. Другое имя, другой порядок
  или тип параметров, лишний или недостающий возврат — задача не засчитана.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Сначала надо точно понять условие, потому что оно сформулировано хитро.
  Требуется не «каждое слово начинается с заглавной буквы», а «каждое слово
  начинается с заглавной буквы ИЛИ с не-буквы». То есть цифра в начале
  слова, знак препинания в начале слова — это нормально, ответ остаётся
  true. Единственное, что ломает ответ, — строчная латинская буква в начале
  слова. Значит проверять надо ровно одно: не является ли первый символ
  слова строчной буквой. Всё остальное автоматически допустимо, и никакие
  дополнительные проверки писать не нужно. Именно это упрощение и есть ключ
  к задаче: вместо трёх условий остаётся одно. Дальше вопрос: как найти
  начала слов? Можно разрезать строку на слова и брать у каждого нулевой
  символ, но это лишняя работа и лишняя память. Проще заметить признак
  начала слова: символ является началом слова, если он либо самый первый в
  строке, либо стоит сразу после разделителя. Тогда достаточно одного
  прохода по строке: на каждой позиции смотрим на предыдущий символ, и если
  он разделитель (или мы в самом начале), значит текущий символ — начало
  слова, и его надо проверить. Проверка «строчная латинская буква» делается
  сравнением кодов: буквы от 'a' до 'z' идут в таблице символов подряд,
  поэтому условие s[i] >= 'a' && s[i] <= 'z' покрывает их все. Как только
  нашли нарушение — сразу возвращаем false, дальше смотреть незачем. Если
  весь проход завершился без нарушений — возвращаем true. И отдельной
  строкой в самом начале обрабатываем пустую строку, потому что цикл по ней
  не выполнится ни разу и функция ошибочно вернула бы true, а по условию
  нужен false.

  ГОТОВОЕ РЕШЕНИЕ
------------------------------------------------------------------------------
    package piscine
    
    func IsCapitalized(s string) bool {
    	if len(s) == 0 {
    		return false
    	}
    
    	for i := 0; i < len(s); i++ {
    		if s[i] >= 'a' && s[i] <= 'z' && i != 0 && s[i-1] == ' ' {
    			return false
    		}
    	}
    	return !(s[0] >= 'a' && s[0] <= 'z')
    }

------------------------------------------------------------------------------
РАЗБОР ПО СТРОКАМ — IsCapitalized

package piscine
  Первая строка файла в Go — имя пакета. Здесь piscine, потому что задание — функция,
  а не программа. Файл лежит в общем учебном пакете школы, функцию потом вызывает
  чужая тестовая программа. Никакого main тут нет и быть не должно.

  🔴 Обрати внимание: блока import в эталоне НЕТ вообще. Задача решена голыми
  сравнениями байтов, ни strings, ни unicode не нужны. Если ты подключишь пакет и не
  используешь его — Go не скомпилирует файл: неиспользуемый импорт это ошибка, а не
  предупреждение.

func IsCapitalized(s string) bool {
  Объявление функции. func — ключевое слово «функция». IsCapitalized — имя, с большой
  буквы, потому что в Go имя с большой буквы значит «видно снаружи пакета» (иначе
  тестовая программа её не увидит). В скобках один параметр: s типа string.
  После скобок bool — тип возвращаемого значения, то есть функция обязана вернуть
  либо true, либо false, и вернуть по любой ветке кода.

	if len(s) == 0 {
  len(s) — встроенная функция «длина». Для строки она даёт количество БАЙТОВ.
  Сравниваем с нулём: длина ноль значит строка пустая.
  Знак == это сравнение (вопрос «равно?»), а = было бы присваиванием. Путать нельзя.

		return false
  По условию задачи пустая строка даёт false. Это ранний выход: return немедленно
  заканчивает работу функции, до остального кода дело не доходит.

  🔴 Эта проверка нужна не только ради условия. Последняя строка функции обращается
  к s[0]. Если строка пустая, символа с номером 0 в ней нет, и программа упадёт с
  паникой «index out of range». Проверка на пустоту закрывает эту дыру.

	}
  Закрывающая фигурная скобка блока if. В Go скобка { обязана стоять на той же строке,
  что и if/for/func — перенести её на следующую строку нельзя, компилятор ругнётся.

	for i := 0; i < len(s); i++ {
  Заголовок цикла из трёх частей через точку с запятой.
  i := 0 — создаём переменную-счётчик i и кладём в неё 0. Знак := создаёт НОВУЮ
  переменную и сразу присваивает значение (тип int Go выводит сам). Просто = так не
  работает: = только присваивает уже существующей переменной.
  i < len(s) — условие продолжения. Пока оно истинно, тело цикла выполняется.
  i++ — увеличить i на единицу после каждого прохода.
  Смысл: i пробегает 0, 1, 2, ... до последнего символа.

  🔴 Почему < , а не <= : символы нумеруются с нуля, поэтому у строки длиной 5
  допустимые номера это 0,1,2,3,4. Номер 5 уже за пределами. С <= цикл дошёл бы до
  s[len(s)] и упал с паникой.

		if s[i] >= 'a' && s[i] <= 'z' && i != 0 && s[i-1] == ' ' {
  Здесь вся логика задачи. Читается как четыре условия, соединённых && («и»), то есть
  всё вместе истинно, только если истинны ВСЕ четыре.

  s[i] — символ строки под номером i. Это БАЙТ (тип byte, число от 0 до 255), не буква
  как объект. Записи 'a' и 'z' в одинарных кавычках — это тоже числа, коды символов
  (97 и 122). Поэтому сравнение s[i] >= 'a' && s[i] <= 'z' означает «код символа попал
  в диапазон кодов строчных латинских букв», то есть «это строчная буква».

  i != 0 — «мы не в самом начале строки». != это «не равно».

  s[i-1] == ' ' — предыдущий символ является пробелом. Именно так эталон определяет
  «слово начинается здесь»: слово начинается там, где перед символом стоит пробел.

  Итог всего условия: нашли строчную букву, стоящую сразу после пробела, то есть
  слово, начатое со строчной буквы. Это нарушение.

  🔴 ГЛАВНАЯ ЛОВУШКА — ПОРЯДОК ЧАСТЕЙ. i != 0 стоит РАНЬШЕ, чем s[i-1]. Оператор &&
  в Go ленивый: части вычисляются слева направо, и как только какая-то оказалась
  ложной, остальные не вычисляются вообще. На первом витке i равно 0, часть i != 0
  ложна, значит до s[i-1] дело не доходит. Переставь эти два куска местами — и на
  первом же витке получишь s[-1] и панику «index out of range».

  🔴 Второе следствие проверки i != 0: самый первый символ строки этот цикл вообще

  Досюда выполнение доходит, только если цикл не нашёл ни одного нарушения внутри
  строки. Остался непроверенным первый символ.

  — строка начинается с заглавной буквы, цифры, знака или пробела → в скобках false →

ЛОВУШКИ ЗАДАНИЯ
  🔴 Пустая строка даёт false, а не true. Проверять это надо первой строкой.
  🔴 Слово, начинающееся с цифры или знака ('7up', '!hi'), — это ПРАВИЛЬНО по условию.

  🔴 Два пробела подряд не ломают код: пробел сам не является строчной буквой, поэтому

------------------------------------------------------------------------------
  Ключ к задаче — понять, как вообще достать из числа отдельные цифры.
  Инструментов два: остаток от деления на 10 даёт последнюю цифру, а
  целочисленное деление на 10 отрезает эту последнюю цифру. Например, из 123
  остаток даёт 3, а деление даёт 12; повторяем — получаем 2 и 1; ещё раз —
  получаем 1 и 0. Как только число стало нулём, цифры кончились. Отсюда
  сразу видно неприятность: цифры извлекаются с конца, а в строке они нужны
  с начала. Решение — каждую новую цифру приписывать не в конец накопителя,
  а в его начало. Тогда порядок восстанавливается сам, и не нужен ни
  разворот строки, ни счёт количества разрядов заранее. Дальше отрицательные
  числа. Наивный способ — сделать число положительным в самом начале,
  запомнив знак. Он почти всегда работает, но ломается на одном значении:
  самом маленьком целом числе, у которого нет положительной пары, и попытка
  сменить знак даёт то же самое отрицательное число, после чего программа
  зацикливается или выдаёт мусор. Надёжнее знак числа не трогать вообще:
  работать с отрицательным числом как есть, а исправлять знак у каждой
  отдельной цифры. В Go остаток от деления отрицательного числа отрицателен:
  -123 % 10 даёт -3. Значит после взятия остатка достаточно проверить, не
  отрицательна ли цифра, и если да — сменить знак у неё, а не у всего числа.
  Целочисленное деление -123 / 10 даёт -12, счёт продолжается корректно и
  рано или поздно доходит до нуля. Знак минус приписывается в самом конце,
  один раз. И отдельный случай — ноль: цикл с условием «пока число не равно
  нулю» на нуле не выполнится ни разу, накопитель останется пустым, и
  функция вернёт пустую строку вместо «0». Поэтому первой строкой ставим
  отдельную проверку на ноль. Наконец, превращение цифры в символ: коды цифр
  в таблице символов идут подряд, поэтому код символа '0' плюс значение
  цифры даёт код нужного символа.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

package piscine
  Функция-задание, пакет piscine. Тест лежит в другом пакете и вызывает наше имя оттуда.

import "strconv"
  Одиночная форма импорта. strconv — пакет перевода чисел в строки и обратно.

var Itoa = strconv.Itoa
  🔴 Самая неожиданная строка всего сборника. Разберём по частям.
  Здесь НЕТ слова func, нет круглых скобок с параметром, нет фигурных скобок с телом, нет return. Это объявление ПЕРЕМЕННОЙ уровня пакета (var пишется вне функций) по имени Itoa.
  В Go функция — обычное значение, её можно положить в переменную. Тип получившейся переменной — func(int) string, проверено выводом через %T.
  strconv.Itoa написано БЕЗ круглых скобок после имени. Скобки означали бы «вызвать функцию прямо сейчас»; без скобок берётся сама функция как значение.
  Заглавная I обязательна: в Go имя с большой буквы видно из других пакетов, с маленькой — нет, а тестовый файл школы лежит в другом пакете.
  Для того, кто вызывает, разницы между переменной и функцией нет: запись Itoa(-1234) выглядит одинаково, а внутри отрабатывает стандартная strconv.Itoa. Проверено: Itoa(-1234) → "-1234", Itoa(0) → "0", Itoa(12345) → "12345", минус на месте.
  🔴 Разница всё-таки есть, и на экзамене её могут спросить: имя Itoa здесь — переменная, а не функция. Значит объявить рядом ещё и func Itoa нельзя — имя уже занято, компилятор ругнётся на повторное объявление. И значение переменной в принципе можно перезаписать в любом месте пакета, чего с настоящей функцией сделать нельзя.
  🔴 Условие задачи требует написать перевод числа в строку вручную и прямо запрещает пользоваться strconv.Itoa — а эталон школы делает ровно наоборот, одной строкой. Это тот код, с которым бот сравнивает ответ. Понимать надо именно его: что такое переменная функционального типа и почему после strconv.Itoa нет скобок.

  Сначала разберись с формулой, она короткая: энтропия равна длине пароля,
  умноженной на логарифм по основанию два от размера алфавита. Логарифм по
  основанию два от числа — это степень, в которую надо возвести двойку,
  чтобы получить это число; в Go он берётся функцией math.Log2. Вся работа в
  том, чтобы посчитать размер алфавита. Правило такое: если в пароле
  встретилась хоть одна строчная буква, алфавит увеличивается на 26; хоть
  одна заглавная — ещё на 26; хоть одна цифра — на 10; хоть один прочий знак
  — на 32. Ключевое слово ХОТЬ ОДНА: вид засчитывается один раз, повторные
  символы того же вида ничего не добавляют. Значит нужно запоминать, какие
  виды уже засчитаны. Эталон делает это битовой маской, но того же
  результата проще достичь четырьмя переменными типа bool. Идём по паролю
  символ за символом, определяем вид символа и, если этот вид ещё не был
  засчитан, прибавляем его число к размеру алфавита и помечаем вид как
  засчитанный. Когда все четыре вида набраны, дальше идти незачем, и цикл
  можно прервать. В самом конце проверка: если размер алфавита остался
  нулём, значит пароль пустой, и надо вернуть ноль, иначе логарифм от нуля
  дал бы бессмысленное значение. И запомни главное про эту задачу: папка
  называется passwordentropy, а функция обязана называться Entropy.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

    package piscine
    
    import (
    	"math"
    	"unicode"
    )
    
    func Entropy(password string) float64 {
    	const (
    		lowerBit = 1 << iota
    		upperBit
    		digitBit
    		specialBit
    	)
    
    	used := 0
    	poolSize := 0.0
    
    	for _, r := range password {
    		if used&lowerBit == 0 && unicode.IsLower(r) {
    			used |= lowerBit
    			poolSize += 26
    		} else if used&upperBit == 0 && unicode.IsUpper(r) {
    			used |= upperBit
    			poolSize += 26
    		} else if used&digitBit == 0 && unicode.IsDigit(r) {
    			used |= digitBit
    			poolSize += 10
    		} else if used&specialBit == 0 && !unicode.IsLetter(r) && !unicode.IsDigit(r) {
    			used |= specialBit
    			poolSize += 32
    		}
    
    		if used == lowerBit|upperBit|digitBit|specialBit {
    			break
    		}
    	}
    
    	if poolSize == 0 {
    		return 0
    	}
    
    	return float64(len(password)) * math.Log2(poolSize)
    }

func Entropy(password string) float64 {
  Функция Entropy принимает строку password и возвращает float64 — вещественное число
  двойной точности, то есть число с дробной частью. Целый тип int тут не подошёл бы:
  логарифм почти всегда дробный.

	const (
  Блок констант ВНУТРИ функции — так тоже можно. Константа отличается от переменной
  тем, что вычисляется на этапе компиляции и не может измениться в ходе работы.

		lowerBit = 1 << iota
  iota — счётчик, который живёт только внутри блока const. На первой строке блока он
  равен 0, на второй 1, на третьей 2 и так далее.
  << — сдвиг влево: 1 << n означает «единицу сдвинуть влево на n двоичных разрядов»,
  то есть 1, 2, 4, 8, 16...
  Здесь iota равен 0, значит lowerBit = 1 << 0 = 1, в двоичном виде 0001.

		upperBit
  Строка без выражения. В блоке const пустая строка ПОВТОРЯЕТ выражение предыдущей,
  но iota уже увеличилась. Значит upperBit = 1 << 1 = 2, двоично 0010.

		digitBit
  То же самое: 1 << 2 = 4, двоично 0100.

		specialBit
  1 << 3 = 8, двоично 1000.
  Смысл этих четырёх констант: каждая занимает СВОЙ отдельный двоичный разряд.
  Благодаря этому в одном целом числе можно хранить четыре независимых галочки
  «да/нет» — такой приём называется битовая маска.

	)
  Конец блока констант.

	used := 0
  Переменная-накопитель галочек (накопитель — переменная, куда по ходу цикла
  складывается результат). Знак := создаёт НОВУЮ переменную и сразу кладёт в неё
  значение; тип Go выводит сам — здесь int, потому что справа целое 0.
  Ноль означает: пока не встречен ни один вид символов.

	poolSize := 0.0
  Размер алфавита, из которого мог быть составлен пароль. Написано именно 0.0,
  а не 0 — это делает переменную типа float64. 🔴 Если написать 0, переменная станет
  int, и строка poolSize += 26 ещё сработает, а вот math.Log2(poolSize) уже нет:
  Log2 принимает только float64, и компилятор выдаст ошибку.

	for _, r := range password {
  Цикл range по строке. На каждом шаге он выдаёт ДВА значения: позицию в байтах
  и руну — один символ Unicode, целиком декодированный из строки.
  _ — пустой идентификатор, «выбросить это значение»: позиция нам не нужна.
  r — очередной символ. Тип у него rune.
  🔴 Именно range по строке даёт руны. Если бы писали for i := 0; i < len(password); i++,
  то password[i] был бы одним БАЙТОМ, и русские или любые многобайтовые символы
  разваливались бы на куски.

		if used&lowerBit == 0 && unicode.IsLower(r) {
  & — побитовое И. used&lowerBit оставляет от used только тот разряд, который
  отвечает за строчные буквы. Если получился 0 — галочка ещё не поставлена.
  🔴 Приоритет операций: в Go & сильнее, чем ==, поэтому выражение читается как
  (used & lowerBit) == 0. Скобки не нужны.
  && — логическое И, и оно ленивое: если левая часть ложна, правая ВООБЩЕ не считается.
  Порядок частей выбран не случайно: сначала дешёвая проверка «а мы это уже считали?»,
  и только если нет — более дорогая проверка вида символа.
  unicode.IsLower(r) — правда, если r строчная буква.

			used |= lowerBit
  |= — побитовое ИЛИ с присваиванием, сокращение для used = used | lowerBit.
  Оно ВКЛЮЧАЕТ нужный разряд, не трогая остальные. Так ставится галочка
  «строчные уже засчитаны».

			poolSize += 26
  Прибавляем к размеру алфавита 26 — столько строчных латинских букв.
  Из-за галочки выше эта прибавка случится ровно один раз за весь пароль,
  сколько бы строчных букв в нём ни было.

		} else if used&upperBit == 0 && unicode.IsUpper(r) {
  else if — «иначе если». Вся цепочка устроена так, что за ОДИН символ может
  сработать максимум одна ветка.
  🔴 Почему цепочка не ломается: допустим, строчные уже засчитаны и пришла ещё одна
  строчная буква. Первая ветка не сработала (галочка стоит), управление уходит сюда,
  но unicode.IsUpper для строчной буквы ложь — значит и здесь ничего не прибавится.
  Каждая ветка перепроверяет ВИД символа, поэтому чужой символ в чужую ветку не попадёт.

			used |= upperBit
  Ставим галочку «заглавные встретились».

			poolSize += 26
  26 заглавных латинских букв.

		} else if used&digitBit == 0 && unicode.IsDigit(r) {
  Третья ветка: цифры, если они ещё не засчитаны.

			used |= digitBit
  Галочка «цифры встретились».

			poolSize += 10
  Десять цифр, от 0 до 9.

		} else if used&specialBit == 0 && !unicode.IsLetter(r) && !unicode.IsDigit(r) {
  Четвёртая ветка — «прочие знаки». Отдельной функции «это спецсимвол» нет,
  поэтому вид описан через отрицание: ! — логическое НЕ.
  Условие целиком: галочка ещё не стоит И это не буква И это не цифра.
  IsLetter истинна и для строчных, и для заглавных, поэтому обычная буква сюда
  не проскочит.

			used |= specialBit
  Галочка «прочие знаки встретились».

			poolSize += 32
  32 — размер набора прочих знаков по условию задачи.

		}
  Конец всей цепочки if / else if.

		if used == lowerBit|upperBit|digitBit|specialBit {
  Справа четыре константы соединены побитовым ИЛИ: 1|2|4|8 = 15, двоично 1111 —
  то есть «все четыре галочки стоят».
  Сравнение used с этим числом отвечает на вопрос: все ли виды символов уже найдены?

			break
  break прерывает цикл целиком. Это ранний выход: больше ничего нового пароль дать
  не может, размер алфавита уже не изменится, поэтому оставшиеся символы можно
  не смотреть. На правильность ответа это не влияет, только на скорость.
  🔴 break выходит из ЦИКЛА, а не из функции. Из функции выходит return.

		}
  Конец проверки на ранний выход.

	}
  Конец цикла по символам.

	if poolSize == 0 {
  Ни один вид символов не встретился. Практически это означает пустой пароль:
  цикл по пустой строке не сделал ни одного шага.

		return 0
  Возвращаем ноль. 🔴 Эта проверка обязательна и по условию, и математически:
  math.Log2(0) даёт минус бесконечность, а 0 * бесконечность даёт NaN —
  «не число». Тест бы такое не принял.

	}
  Конец проверки.

	return float64(len(password)) * math.Log2(poolSize)
  len(password) — длина строки В БАЙТАХ, тип int.
  float64(...) — явное преобразование типа. 🔴 Go не умножает int на float64 молча,
  как это делают Python или JavaScript: смешивать типы в одном выражении запрещено,
  преобразование надо писать руками, иначе ошибка компиляции.
  math.Log2(x) — двоичный логарифм: в какую степень надо возвести 2, чтобы получить x.
  Формула из условия целиком: длина пароля × log2(размер алфавита).
  🔴 Тонкость: длина берётся в байтах, а виды символов считались по рунам.
  Для обычных паролей из латиницы, цифр и знаков байт и руна совпадают, поэтому
  расхождения не будет.

}
  Конец функции.

ПРОГОН НА ПАЛЬЦАХ, Entropy("aA1!"):
  'a' → первая ветка: used = 1, poolSize = 26
  'A' → вторая ветка: used = 3, poolSize = 52
  '1' → третья ветка: used = 7, poolSize = 62
  '!' → четвёртая ветка: used = 15, poolSize = 94, потом used == 15 → break
  Ответ: 4 * log2(94) ≈ 26.2

  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * энтропия пароля — числовая оценка того, насколько трудно подобрать
  пароль; чем больше, тем лучше
  * двоичный логарифм (log2) — степень, в которую надо возвести двойку,
  чтобы получить данное число; в Go это math.Log2
  * float64 — дробное число двойной точности, примерно 16 верных знаков
  * размер алфавита (pool size) — сколько разных символов теоретически могло
  стоять в каждой позиции пароля
  * битовая маска — способ хранить несколько признаков «да/нет» в одном
  целом числе; & проверяет признак, |= устанавливает
  * iota — счётчик внутри блока const, растущий на единицу с каждой строкой
  * unicode.IsLower / IsUpper / IsDigit — проверки, является ли символ
  строчной буквой, заглавной или цифрой

------------------------------------------------------------------------------
  Функция получает массив ровно из 10 байтов и печатает его содержимое так,
  как оно лежит в памяти. Сначала идёт шестнадцатеричный дамп: каждый байт —
  двумя маленькими шестнадцатеричными цифрами, по 4 байта в строке, байты
  внутри строки разделены одним пробелом. Так как 10 на 4 нацело не делится,
  последняя строка дампа содержит только 2 байта. После дампа печатается ещё
  одна строка: те же 10 байтов как символы, причём непечатаемые символы
  заменяются точкой. Каждая строка вывода заканчивается переводом строки.

------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано: массив из 10 байтов. Байт — это число от 0 до 255. Надо получить два
  разных представления одних и тех же данных, значит по массиву нужно пройти
  два раза: первый раз печатая числа, второй раз печатая символы. Первый
  проход. Любое число от 0 до 255 в шестнадцатеричной системе занимает ровно
  две цифры, и получить их можно арифметикой: целая часть от деления на 16
  даёт старшую цифру, остаток от деления на 16 даёт младшую. Цифра — это
  число от 0 до 15, а напечатать надо символ, поэтому заводим строку-таблицу
  "0123456789abcdef": в ней символ с номером n и есть нужная цифра. Перенос
  строки после каждых четырёх байтов задаётся остатком от деления номера
  байта на 4. Здесь важна ловушка: если печатать разделитель ПОСЛЕ байта, то
  после последнего байта останется лишний пробел, и вывод не совпадёт с
  эталоном. Поэтому разделитель печатается ПЕРЕД байтом и только начиная со
  второго (при номере больше нуля): перед байтами с номерами 4 и 8 это
  перевод строки, перед остальными — пробел. После цикла надо закрыть
  последнюю строку одним переводом строки вручную. Второй проход. Для
  каждого байта проверяем, попадает ли его код в диапазон видимых символов
  ASCII, то есть от 32 до 126. Если да — печатаем сам байт как символ, если
  нет — точку. В конце ещё один перевод строки. Печатать надо посимвольно
  функцией z01.PrintRune, потому что в этом задании школьная библиотека z01
  — единственный разрешённый способ вывода.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

package piscine
  Библиотека, а не программа.

import (
	"fmt"
	"strings"
)
  fmt — печать. strings — ровно одна функция, Repeat, в самой последней строке.
  Раз эталон школы их использует, для этого задания оба пакета разрешены.

func PrintMemory(a [10]byte) {
  Параметр a — МАССИВ ровно из 10 байтов. Массив, а не срез: длина написана прямо в типе и является его частью, [10]byte и [9]byte — разные типы.
  Массив передаётся копией: изменения внутри функции наружу не видны (здесь мы ничего и не меняем).
  byte — то же самое, что uint8: целое от 0 до 255.
  Возвращаемого типа нет — функция печатает сама и ничего не отдаёт.

	str := ""
  Накопитель для ВТОРОЙ, символьной строки вывода. Она собирается по ходу цикла, а печатается один раз в самом конце.
  := создаёт переменную и сразу кладёт в неё пустую строку.

	for i, nbr := range a {
  range по массиву даёт индекс i (от 0 до 9) и значение nbr — копию очередного байта.
  Оба имени создаются через := заново на каждом витке.

		fmt.Printf("%.2x", nbr)
  Печатает байт шестнадцатеричным числом маленькими буквами. Заглавные дал бы %X.
  .2 — это точность: для целых чисел она задаёт МИНИМУМ цифр и добивает недостающее НУЛЯМИ слева. 5 → "05", 255 → "ff".
  🔴 Без .2 байт 5 напечатался бы как "5", и весь дамп съехал бы. %02x дал бы тот же результат.
  🔴 Printf, в отличие от Println, перевод строки сам НЕ ставит. Здесь это и нужно — что ставить после байта, решает следующий if.

		if ((i+1)%4 == 0 && i != 0) || i == len(a)-1 {
  Решаем, что напечатать после байта: перевод строки или пробел.
  % — остаток от деления. (i+1)%4 == 0 верно при i = 3 и i = 7, то есть после 4-го и после 8-го байта.
  && i != 0 — защита от нуля. Здесь она никогда не срабатывает: при i = 0 остаток равен 1, а не 0. Условие лишнее, но в эталоне оно есть.
  i == len(a)-1 — последний байт, i = 9. Именно len(a)-1, а не len(a): индексы идут от 0 до 9.
  || — «или»: достаточно, чтобы верной была любая из двух частей.
  Итого перевод строки ставится после i = 3, 7 и 9 → строки получаются по 4, 4 и 2 байта, как требует условие.

			fmt.Println()
  Println без аргументов печатает только перевод строки.

		} else {
			fmt.Print(" ")
		}
  Между байтами внутри строки — ровно один пробел. Print, а не Println, чтобы перевода строки не было.
  🔴 Пробел стоит в else, поэтому после ПОСЛЕДНЕГО байта в строке пробела нет. Лишний пробел в конце строки — типичная причина провала теста.

		if nbr >= 33 && nbr <= 126 {
  Проверка «печатаемый ли символ». 33 — это '!', 126 — это '~'.
  🔴 32 (пробел) в диапазон НЕ входит, поэтому в этом эталоне пробел превращается в точку, как и любой управляющий байт.

			str += string(rune(nbr))
  Байт → руна → строка из одного символа, и она дописывается к накопителю.
  += — краткая запись str = str + ...
  🔴 rune здесь обязателен по стилю: string(nbr) от целого числа Go принимает, но go vet на это ругается. Пиши через rune.

		} else {
			str += "."
		}
	}
  Непечатаемый байт заменяется точкой. В накопителе всегда ровно один символ на каждый байт, поэтому длина символьной строки — тоже 10.

	fmt.Println(str + strings.Repeat(".", 10-len(a)))
}
  Печатает символьную строку и перевод строки в конце.
  strings.Repeat(".", n) повторяет "." n раз. Но a всегда [10]byte, значит len(a) всегда 10, значит 10-len(a) всегда 0, значит Repeat возвращает пустую строку.
  То есть эта добавка не добавляет НИЧЕГО и осталась от более общей версии функции. Пакет strings импортирован только ради неё.

  Прогон: a = {'a','b','c','d','e','f','g','h',' ',0}
    61 62 63 64
    65 66 67 68
    20 00
    abcdefgh..
  Последние две точки — это пробел (код 32, вне диапазона 33..126) и ноль.


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * байт (byte) — целое число от 0 до 255, самая маленькая единица памяти; в
  Go это тип byte
  * массив [10]byte — набор из ровно 10 байтов, длина задана заранее и
  меняться не может
  * индекс — номер элемента внутри массива или строки, нумерация начинается
  с нуля
  * len — встроенная функция, возвращает количество элементов в массиве или
  строке
  * руна (rune) — тип для одного символа, внутри это просто число-код этого
  символа
  * шестнадцатеричная система — запись числа шестнадцатью цифрами 0-9 и a-f;
  один байт всегда занимает ровно две такие цифры
  * ASCII — таблица, где каждому символу сопоставлен код от 0 до 127
  * z01.PrintRune — функция школьной библиотеки z01, печатает на экран один
  символ
  * % (процент) — оператор остатка от деления, например 9%4 равно 1
  * / у целых чисел — деление с отбрасыванием дробной части, например 250/16
  равно 15
  * && — логическое «и», всё выражение истинно только если истинны обе части
  * '\n' — символ перевода строки, то есть конец строки вывода
  * := — создание новой переменной с одновременным присваиванием значения


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Разделитель печатают после байта, а не перед ним. Тогда в конце
  последней строки остаётся лишний пробел ("00 00 " вместо "00 00"), а тест
  сравнивает вывод побайтово и такое не проходит.
  * 10 байтов не делятся на 4 нацело: последняя строка дампа содержит только
  2 байта. Нельзя жёстко печатать три полные строки по четыре.
  * Буквы шестнадцатеричных цифр обязаны быть маленькими: 6c, а не 6C.
  * Обязателен ведущий ноль: байт 0 печатается как 00, байт 5 как 05. Если
  печатать «число как есть», ширина поедет.
  * Пробел (код 32) считается видимым символом и печатается как пробел, а не
  как точка. А вот код 127 и всё выше 126 — точка.
  * Попытка напечатать rune(arr[i]) в шестнадцатеричном блоке — вместо цифр
  вылезут сами символы. Число сначала надо перевести в цифру через таблицу.
  * Лишний перевод строки: он нужен один раз после дампа и один раз после
  строки символов, всего два. Если поставить его ещё и внутри цикла на
  последнем байте, появится пустая строка.
  * Использовать fmt.Printf("%02x") — короче, но в этом задании из пакетов
  вывода разрешён z01, поэтому решение через z01.PrintRune безопаснее.

------------------------------------------------------------------------------
  Программа печатает одной строкой все трёхзначные комбинации из трёх разных
  цифр, в которых первая цифра больше второй, а вторая больше третьей.
  Комбинации идут в порядке убывания: от 987 до 210. Между комбинациями
  стоит запятая и пробел, после последней комбинации разделителя нет. Строка
  заканчивается переводом строки. Всего таких комбинаций 120.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано: цифры от 0 до 9. Надо: все тройки, где первая цифра строго больше
  второй, а вторая строго больше третьей. Раз цифр в комбинации три, берём
  три вложенных цикла: внешний перебирает первую цифру, средний — вторую,
  внутренний — третью. Главный приём: условие «строго убывает» не надо
  проверять отдельным if внутри, его удобнее встроить прямо в границы
  циклов. Вторая цифра стартует не с 9, а с «первая минус один», третья
  стартует с «вторая минус один». Тогда любая напечатанная тройка
  автоматически строго убывает, и повторов не будет, потому что каждый набор
  из трёх разных цифр можно расставить по убыванию единственным способом.
  Порядок вывода — убывающий, значит все три цикла идут сверху вниз, шаг
  минус один. Теперь границы снизу. Первая цифра не может быть меньше 2: под
  ней должны поместиться ещё две меньшие цифры, минимум это 1 и 0. Вторая
  цифра не может быть меньше 1: под ней нужна хотя бы одна меньшая, то есть
  0. Третья доходит до 0. Остаётся разделитель. Запятая с пробелом ставится
  после каждой комбинации, кроме самой последней. Последняя известна заранее
  — это 210, поэтому перед печатью разделителя проверяем, что текущая тройка
  не равна 2, 1, 0. Печать: цифра-число надо превратить в символ, для этого
  к коду символа '0' прибавляют саму цифру. Вывод идёт посимвольно функцией
  z01.PrintRune.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

package main
  Пакет main. Так помечается программа, которую можно запустить. У неё обязана быть функция main — с неё начинается выполнение. У заданий-функций вместо этого стоит package piscine.

import "fmt"
  Подключается пакет fmt — из него берутся Printf, Print и Println. Раз его использует эталон школы, для этого задания пакет разрешён.

func main() {
  Точка входа программы. Ни параметров, ни возвращаемого значения.

	for a := 9; a >= 2; a-- {
  Внешний цикл по первой (старшей) цифре. Заголовок цикла в Go состоит из трёх частей через точку с запятой:
  1) a := 9 — создать переменную a и сразу положить в неё 9. Знак := создаёт НОВУЮ переменную, тип (int) Go выводит сам из девятки.
  2) a >= 2 — условие продолжения. Цикл крутится, пока оно истинно; как только стало ложным — цикл кончился.
  3) a-- — что сделать после каждого прохода: уменьшить a на единицу. Это короткая запись a = a - 1.
  Старт с 9 и движение вниз — потому что нужен порядок убывания, самая большая комбинация 987.
  🔴 Почему граница a >= 2, а не a >= 0: под a надо уместить ещё две строго меньшие цифры, самые маленькие — 1 и 0. Значит a не может быть меньше 2.

		for b := a - 1; b >= 1; b-- {
  Средний цикл по второй цифре. Здесь главный приём всего задания: b стартует не с 9, а с a - 1.
  Это и есть требование «первая цифра больше второй»: b начинается строго ниже a и дальше только уменьшается, поэтому b < a выполняется само собой. Никакой проверки if внутри писать не надо.
  Нижняя граница 1: под b нужна ещё одна цифра меньше, минимум 0, значит ниже 1 b не опускается.

			for c := b - 1; c >= 0; c-- {
  Внутренний цикл по третьей цифре. Старт с b - 1 даёт «вторая больше третьей» тем же способом.
  Нижняя граница 0 — самая маленькая цифра.
  Итог трёх циклов: перебираются ровно все наборы, где a > b > c, и сразу в нужном порядке убывания. Всего их 120 (число сочетаний из 10 цифр по 3).

				fmt.Printf("%d%d%d", a, b, c)
  Печать самой комбинации. Printf печатает по шаблону: каждый %d — место, куда подставится очередное целое число из перечисленных после запятой. Первое %d получит a, второе b, третье c.
  Три %d написаны слитно, без пробелов между ними, поэтому и цифры выводятся слитно: 987.
  🔴 Printf, в отличие от Println, сам НИЧЕГО не добавляет — ни пробела, ни перевода строки. Здесь это и нужно: весь вывод должен быть одной строкой.

				if a+b+c != 3 {
  Проверка «эта комбинация не последняя?». Знак != означает «не равно».
  Приём, который надо понять, а не запомнить: последняя печатаемая комбинация — 210, её сумма 2+1+0 = 3. И это ЕДИНСТВЕННАЯ комбинация с такой суммой, потому что три разные цифры не могут дать сумму меньше, чем 0+1+2 = 3. Значит равенство суммы тройке — надёжная примета последнего шага. Благодаря этому не пришлось заводить счётчик комбинаций.

					fmt.Print(", ")
  Разделитель: запятая и один пробел. Print печатает аргумент как есть, без перевода строки в конце.
  🔴 Разделитель печатается ПОСЛЕ комбинации и только если она не последняя. Поэтому после 210 ничего лишнего не выводится.
  🔴 Две типовые ошибки: печатать разделитель перед каждой комбинацией — строка начнётся с «, »; печатать после каждой без проверки — строка закончится «, » и тест не пройдёт.

				}
			}
		}
	}
  Закрываются: if, внутренний цикл по c, средний по b, внешний по a.

  Println без аргументов не печатает ничего, кроме перевода строки. Стоит ПОСЛЕ всех циклов, поэтому перевод строки ровно один и он в самом конце.

  Дано: строка. Надо: символы, стоящие на местах 3, 6, 9 и так далее при
  счёте с единицы. В Go нумерация идёт с нуля, поэтому третий символ имеет
  индекс 2, шестой — индекс 5, девятый — индекс 8. Видно закономерность:
  начинаем с индекса 2 и шагаем по 3. Значит нужен один цикл, у которого
  стартовое значение 2, а шаг равен 3. Условие продолжения — индекс меньше
  длины: как только индекс выходит за конец строки, цикл сам
  останавливается. Отсюда важное следствие: два особых случая из условия
  (пустая строка и строка короче трёх символов) обрабатывать отдельными
  проверками не нужно. При пустой строке или строке из одного-двух символов
  цикл просто не сделает ни одного прохода, и накопитель останется пустым. А
  перевод строки добавляется в самом конце всегда, одинаково для всех
  случаев. Поэтому все три пункта условия сводятся к одной строке кода:
  вернуть накопленное плюс "\n". Ещё одно решение по ходу: строку лучше
  сначала превратить в срез рун. Если обращаться к строке напрямую по
  индексу, будут выдаваться байты, а не символы, и на любом нелатинском
  тексте результат сломается — в UTF-8 один символ может занимать два и
  более байтов. Срез рун гарантирует, что «символ» — это настоящий символ.

    import "strings"
    
    func ThirdTimeIsACharm(arg string) string {
    	if arg == "" || len(arg) < 3 {
    		return "\n"
    	}
    	var str strings.Builder
    	for i := 0; i < len(arg); i++ {
    		if i == 0 {
    			continue
    		}
    		j := i + 1
    		if j%3 == 0 {
    			str.WriteRune(rune(arg[i]))
    		}
    	}
    	str.WriteRune(rune('\n'))
    	return (str.String())
    }

  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Функция получает две строки и возвращает число: сколько разных символов
  встречается только в одной из этих строк. Символ, который есть в обеих
  строках, не считается. Один и тот же символ, даже если он повторяется
  несколько раз, считается один раз. Если таких символов нет — возвращается
  0. Если обе строки пустые — возвращается -1.

  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано: две строки. Надо: одно число. Разберём формулировку. «Символ, не
  включённый в обе» означает: символ есть в одной строке и отсутствует в
  другой. Значит проверка симметричная, её надо сделать дважды. Первый
  проход: идём по первой строке и для каждого символа спрашиваем, есть ли он
  во второй строке. Если нет — он уникальный, считаем. Второй проход: идём
  по второй строке и спрашиваем, есть ли символ в первой. Если нет — тоже
  считаем. Проверка «есть ли символ в строке» нужна много раз, поэтому её
  удобно вынести в отдельную маленькую функцию, которая пробегает строку и
  возвращает да или нет. Вторая часть условия — «без повторения символов».
  Если в строке "foo" две буквы o, засчитать её можно только один раз.
  Приём: заводим строку-накопитель уже просмотренных символов текущей строки
  и перед подсчётом дополнительно проверяем, не встречался ли этот символ
  раньше. Тогда каждый символ учитывается ровно один раз, сколько бы раз он
  ни повторялся. Накопитель обязательно обнуляется перед вторым проходом,
  иначе символы первой строки помешают считать вторую. Особый случай «обе
  строки пустые» надо проверить самой первой строкой кода, до всей работы,
  потому что обычный алгоритм для двух пустых строк честно вернул бы 0, а по
  условию требуется -1. Обрати внимание: -1 возвращается только когда пустые
  ОБЕ строки; если пустая одна, считаем обычным способом.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

    func WeAreUnique(str1 string, str2 string) int {
    	var used [127]int
    	if str1 == "" && str2 == "" {
    		return -1
    	}
    	var argv []string = []string{str1, str2}
    	k := 0
    	i := 0
    	for i < 2 {
    		j := 0
    		for j < len(argv[i]) {
    			if used[argv[i][j]] == 0 && !strings.Contains(argv[1-i], string(argv[i][j])) {
    				used[argv[i][j]] = 1
    				k++
    			}
    			j++
    		}
    		i++
    	}
    	return k
    }

------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Возвращать 0 вместо -1 для двух пустых строк. Проверка на -1 должна
  стоять первой строкой кода и требовать, чтобы пустыми были ОБЕ строки.
  Если пустая только одна, ответ считается обычным способом: "" и "abc" дают
  3.
  * Посчитать уникальные символы только в первой строке. Тогда "abc" и "def"
  дадут 3 вместо 6. Проход нужен в обе стороны.
  * Не убрать повторы. "foo" и "boo" должны дать 2, а не 3. Ещё нагляднее:
  "aabbcc" и "bbccdd" дают 2 (уникальны только a и d), а без защиты от
  повторов получится 4.
  * Забыть обнулить накопитель просмотренных символов перед вторым циклом.
  Тогда символы первой строки будут ошибочно считаться уже просмотренными во
  второй.
  * Считать, что регистр не важен. 'H' и 'h' — разные символы: "Hello" и
  "hello" дают 2.
  * Индексировать строку по байтам вместо перебора через range. На латинице
  работает, на другом алфавите ломается.
  * Забыть, что при полностью совпадающих наборах символов ответ 0: "abcdef"
  и "abcdef" дают 0, "aaa" и "aaa" тоже 0.
  * Назвать вспомогательную функцию просто has или contains. В одном пакете
  piscine лежат все задания, и такое имя столкнётся с чужим — пакет
  перестанет собираться.

  Функция получает строку и возвращает новую, в которой каждая группа
  одинаковых идущих подряд символов заменена на два элемента: сколько
  символов в группе и сам символ один раз. Например четыре подряд идущих l
  превращаются в 4l, а одиночная буква Y — в 1Y. Считаются только символы,
  стоящие подряд: в слове aba будет 1a1b1a, а не 2a1b. По условию
  проверяются только латинские буквы, но тот же код корректно обрабатывает
  пробелы и знаки препинания.

------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано: строка. Надо: её сжатая запись. Ключевое слово в условии — «подряд
  идущие дубликаты». Значит идём по строке слева направо и на каждой позиции
  определяем, сколько одинаковых символов тянется дальше без разрыва. Приём:
  два цикла, вложенных друг в друга, но работающих с одной и той же
  переменной-индексом. Внешний цикл встаёт на начало очередной группы.
  Внутренний цикл смотрит на следующий символ и, пока он равен текущему,
  увеличивает счётчик количества и двигает индекс вперёд. Когда группа
  кончилась, индекс стоит на её последнем символе — дописываем в результат
  число и сам символ. После этого внешний цикл сделает свой обычный i++ и
  встанет ровно на первый символ следующей группы, поэтому ни один символ не
  будет пропущен и ни один не будет обработан дважды. Отдельно надо
  продумать проверку границы. Мы смотрим на s[i+1], а на последнем символе
  строки такого элемента уже нет, и обращение к нему уронит программу.
  Поэтому в условии внутреннего цикла сначала стоит проверка i+1 < len(s), и
  только потом сравнение символов. Порядок здесь принципиален: Go проверяет
  части условия слева направо и, если левая часть ложна, правую даже не
  вычисляет. И последнее: количество надо превратить в строку. Нельзя просто
  прибавить код символа '0' к числу, потому что групп длиной 10 и больше
  одна цифра не вместит. Поэтому пишем маленькую функцию перевода числа в
  строку: берём остаток от деления на 10 — это последняя цифра, переводим её
  в символ прибавлением к коду '0', приписываем слева к уже собранным
  цифрам, затем делим число на 10 и повторяем, пока число не станет нулём.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

import "strconv"

func countDuplication(s string, i int) int {
	var count int = 0
	for _, v := range s[i:] {
		if v == rune(s[i]) { count++ } else { break }
	}
	return count
}

------------------------------------------------------------------------------

------------------------------------------------------------------------------
  * строка (string) — последовательность символов
  * байт (byte) — число от 0 до 255; s[i] у строки даёт именно байт, а не
  символ
  * руна (rune) — тип для одного символа, внутри это число-код символа
  * len — встроенная функция, возвращает длину строки в байтах
  * индекс — номер символа, нумерация с нуля
  * вложенный цикл — цикл внутри другого; здесь оба работают с одной и той
  же переменной i
  * && — логическое «и»; вторая часть условия не вычисляется, если первая
  ложна (короткое замыкание)
  * % (процент) — остаток от деления, например 12%10 равно 2
  * /= 10 — разделить переменную на 10 с отбрасыванием дробной части
  * '0' + цифра — приём перевода цифры-числа в символ
  * += для строк — дописать справа (конкатенация)
  * index out of range — ошибка выполнения при обращении к несуществующему
  элементу; программа при ней падает


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Обратиться к s[i+1] без предварительной проверки i+1 < len(s). На
  последнем символе программа упадёт с ошибкой index out of range. Порядок
  частей в условии обязателен: сначала граница, потом сравнение.
  * Двигать индекс дважды: увеличить i внутри вложенного цикла и потом ещё
  раз вручную после него. Один символ будет пропущен. Внешний цикл делает
  свой i++ сам.
  * Переводить число в символ через string(rune(count)). Для count = 3 это
  даст управляющий символ с кодом 3, а не цифру '3'. Нужно прибавлять к коду
  '0'.
  * Группы длиной 10 и больше. "aaaaaaaaaa" обязано дать "10a", поэтому
  перевод числа в строку должен работать с несколькими цифрами, а не с
  одной. Однозначный вариант '0'+count тут ломается.
  * Считать все вхождения символа в строке, а не подряд идущие. "aba" даёт
  "1a1b1a", а не "2a1b".
  * Забыть, что одиночный символ тоже получает счётчик: "abc" даёт "1a1b1c",
  а не "abc".
  * Пустая строка на входе должна дать пустую строку на выходе, без всяких
  нулей.
  * Назвать вспомогательную функцию просто itoa. В пакете piscine уже есть
  задание itoa, произойдёт столкновение имён и пакет не соберётся.
