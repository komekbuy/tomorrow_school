------------------------------------------------------------------------------
  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Написать интерпретатор эзотерического языка Brainfuck. Исходный код
  программы на Brainfuck приходит первым аргументом командной строки и
  всегда корректен, операций меньше 4096. Внутри интерпретатора — массив из
  2048 байт, все нули, и указатель, который в начале стоит на первом байте.
  Восемь команд: `>` `<` двигают указатель, `+` `-` меняют байт под
  указателем, `.` печатает этот байт в стандартный вывод, `[` и `]` образуют
  цикл. Любой другой символ — комментарий, его надо просто пропустить. Если
  аргумента нет — программа не печатает ничего.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  У задачи два состояния, которые надо держать в переменных: лента памяти и
  позиция в ней. Лента — это `make([]byte, 2048)`, срез байт; Go сам
  заполняет его нулями, отдельный цикл обнуления не нужен. Позиция — обычное
  целое число `pointer`, индекс внутри этого среза, а не настоящий указатель
  Go. Третье состояние — где мы находимся в исходном коде: это счётчик `i`
  обычного цикла `for` по строке. Дальше вся программа — один проход по
  символам кода и `switch` на восемь случаев; `default` писать не надо,
  потому что «любой другой символ игнорируется» — это ровно то, что `switch`
  делает сам, когда ни один `case` не подошёл. Шесть команд из восьми
  пишутся одной строкой каждая. Вся сложность только в скобках, и здесь надо
  понять главную вещь: цикл в Brainfuck не хранится нигде, его надо каждый
  раз находить сканированием по строке кода. Когда встретили `[` и байт под
  указателем ноль — надо перепрыгнуть вперёд за парную `]`. Парная — не
  первая встречная, потому что внутри могут быть вложенные циклы. Приём:
  завести счётчик глубины `depth = 1` и идти вперёд по символам, увеличивая
  его на каждой `[` и уменьшая на каждой `]`; когда `depth` стал нулём — мы
  стоим ровно на парной закрывающей. С `]` симметрично: если байт не ноль,
  идём назад, `depth` растёт на `]` и падает на `[`. Заметь тонкость с `i`:
  после поиска `i` стоит на самой скобке, а `i++` в заголовке главного цикла
  сдвинет его на следующий символ — а условие как раз и требует «перейти к
  команде после скобки», так что ничего дополнительно делать не нужно.
  Печать: `.` должна выдать сырой байт, поэтому
  `os.Stdout.Write([]byte{memory[pointer]})`, а не превращение в строку.
  Перевод строки в конце вывода мы не добавляем — его печатает сама
  программа на Brainfuck, если хочет.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого
  задания разрешены: будь иначе, проверка не собралась бы.

    package main
    
    import (
    	"fmt"
    	"os"
    )
    
    const SIZE = 2048
    
    func main() {
    	if len(os.Args) != 2 {
    		return
    	}
    	progpoint := []byte(os.Args[1])
    	var arby [SIZE]byte
    	pos := 0
    	openBr := 0         // opened brackets
    	i := 0              // iterates through the source code passed in the argument
    	N := len(progpoint) // length of the source code
    	for i >= 0 && i < N {
    		switch progpoint[i] {
    		case '>':
    			// Increment the pointer
    			pos++
    		case '<':
    			// decrement the pointes
    			pos--
    		case '+':
    			// increment the pointed byte
    			arby[pos]++
    		case '-':
    			// decrement the pointed byte
    			arby[pos]--
    		case '.':
    			// print the pointed byte on std output
    			fmt.Printf("%c", rune(arby[pos]))
    		case '[':
    			// go to the matching ']' if the pointed byte is 0 (while start)
    			openBr = 0
    			if arby[pos] == 0 {
    				for i < N && (progpoint[i] != byte(']') || openBr > 1) {
    					if progpoint[i] == byte('[') {
    						openBr++
    					} else if progpoint[i] == byte(']') {
    						openBr--
    					}
    					i++
    				}
    			}
    		case ']':
    			// go to the matching '[' if the pointed byte is not 0 (while end)
    			openBr = 0
    			if arby[pos] != 0 {
    				for i >= 0 && (progpoint[i] != byte('[') || openBr > 1) {
    					if progpoint[i] == byte(']') {
    						openBr++
    					} else if progpoint[i] == byte('[') {
    						openBr--
    					}
    					i--
    				}
    			}
    		}
    		i++
    	}
    }

package main
  Это программа, а не библиотека: пакет main собирается в исполняемый файл, и запуск начинается с функции main.

import (
	"fmt"
	"os"
)
  fmt — печать, os — доступ к аргументам командной строки. Раз их использует эталон школы, здесь они разрешены.

const SIZE = 2048
  Константа — значение, заданное один раз и не меняемое. Размер ленты интерпретатора по условию. Пишется вне функций, на уровне пакета.

func main() {
  Точка входа программы. Ни параметров, ни возвращаемого значения.

	if len(os.Args) != 2 {
  os.Args — срез строк (срез = список переменной длины) со всем, что набрали в командной строке. os.Args[0] — ВСЕГДА имя самой программы, os.Args[1] — первый настоящий аргумент. Поэтому «ровно один аргумент» = длина 2.

		return
  Выход из main. 🔴 Не печатается ничего — ни текста, ни перевода строки.

	}
	progpoint := []byte(os.Args[1])
  Перевод строки в срез байт. Байт — одно число от 0 до 255, код одного символа. Так можно брать символы по индексу и сравнивать их с байт-константами вроде '>'.

	var arby [SIZE]byte
  Массив — набор фиксированной длины, известной заранее (в отличие от среза). Здесь 2048 байт. var без начального значения даёт все нули — ровно то, что требует условие. Это лента интерпретатора.

	pos := 0
  Указатель — номер текущей ячейки ленты. Стартует на первой, то есть на индексе 0.

	openBr := 0         // opened brackets
  Счётчик открытых скобок; нужен только при поиске парной скобки. Всё после // до конца строки — комментарий, компилятор его игнорирует.

	i := 0              // iterates through the source code passed in the argument
  Позиция в исходном коде brainfuck (не на ленте!). Две разные позиции легко перепутать: i — по программе, pos — по ленте.

	N := len(progpoint) // length of the source code
  Длина программы, посчитана один раз заранее, чтобы не вызывать len на каждом обороте.

	for i >= 0 && i < N {
  Цикл ТОЛЬКО с условием, без счётчика в заголовке — потому что i двигается и вперёд, и назад (прыжки по скобкам), обычный for со схемой i++ здесь не подходит.
  Проверка i >= 0 нужна из-за прыжков назад, i < N — чтобы не выйти за конец программы. && — «и», ленивое: если левая часть ложна, правая не вычисляется.

		switch progpoint[i] {
  Выбор ветки по текущему символу программы. В Go после case НЕ нужен break — ветка заканчивается сама и вниз не проваливается.
  Ветки default здесь нет: любой символ, не попавший ни в один case, просто ничего не делает. Это и есть требование «остальные символы — комментарии».

		case '>':
			// Increment the pointer
			pos++
  Указатель на ленте сдвигается вправо на одну ячейку.

		case '<':
			// decrement the pointes
			pos--
  Сдвиг влево. 🔴 Проверки границ нет: '<' на нулевой позиции даст pos = -1 и программа упадёт. По условию входные программы всегда корректны, поэтому эталон это не проверяет.

		case '+':
			// increment the pointed byte
			arby[pos]++
  Плюс один к байту в текущей ячейке. Тип byte — от 0 до 255, при 255+1 значение обнуляется по кругу. Это нормальное поведение brainfuck, не ошибка.

		case '-':
			// decrement the pointed byte
			arby[pos]--
  Минус один; 0-1 даёт 255, тоже по кругу.

		case '.':
			// print the pointed byte on std output
			fmt.Printf("%c", rune(arby[pos]))
  Печать. %c означает «выведи СИМВОЛ с этим кодом», а не само число (%d вывел бы 72 вместо H).
  rune — тип для символа Юникода (по сути int32). Байт переводится в руну, чтобы Printf вывел его как символ.

		case '[':
			// go to the matching ']' if the pointed byte is 0 (while start)
			openBr = 0
  Здесь = , а не := — переменная openBr уже существует, ей просто кладут новое значение. Обнуление перед каждым новым поиском парной скобки обязательно, иначе счётчик потащит мусор с прошлого раза.

			if arby[pos] == 0 {
  Прыгаем вперёд только если текущая ячейка равна нулю (условие цикла не выполнено). Если не ноль — ничего не делаем и просто входим в тело цикла следующим шагом.

				for i < N && (progpoint[i] != byte(']') || openBr > 1) {
  Поиск ПАРНОЙ закрывающей скобки вперёд. || — «или». Цикл останавливается только когда обе вещи разом: символ — ']' И вложенность не глубже одного уровня (openBr не больше 1).
  byte(']') — явный перевод символа в тип byte, чтобы сравнивать с элементом среза байт.

					if progpoint[i] == byte('[') {
						openBr++
					} else if progpoint[i] == byte(']') {
						openBr--
					}
  Подсчёт вложенности. На самом первом обороте под i стоит наша собственная '[', поэтому openBr сразу становится 1 — отсюда и берётся граница openBr > 1 в условии выше. Каждая вложенная '[' поднимает счётчик, каждая ']' опускает.

					i++
  Шаг вперёд по исходному коду.

				}
			}
  Выход из этого цикла означает: i стоит РОВНО на парной ']'. Общий i++ в конце оборота перешагнёт её, и выполнение продолжится после цикла.

		case ']':
			// go to the matching '[' if the pointed byte is not 0 (while end)
			openBr = 0
  То же обнуление счётчика перед поиском.

			if arby[pos] != 0 {
  Возвращаться к началу цикла надо только если ячейка НЕ ноль. Если ноль — цикл окончен, просто идём дальше.

				for i >= 0 && (progpoint[i] != byte('[') || openBr > 1) {
  Тот же поиск, но зеркально: идём назад, пока не найдём открывающую скобку своего уровня.

					if progpoint[i] == byte(']') {
						openBr++
					} else if progpoint[i] == byte('[') {
						openBr--
					}
  🔴 Скобки поменялись местами по сравнению с веткой '[': при движении назад вложенность увеличивает именно ']', а уменьшает '['. Перепутать местами — самая типичная ошибка при переписывании этого кода по памяти.

					i--
  Шаг назад по исходному коду.

				}
			}
  После выхода i стоит на парной '[', а общий i++ поставит его на первый символ тела цикла — тело выполнится заново.

		}
  Конец switch.

		i++
  Общий шаг вперёд после КАЖДОЙ команды, включая только что найденную скобку. Он стоит вне switch, поэтому работает для всех веток разом.

	}
}
  Конец цикла и конец main.

------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * байт — целое число от 0 до 255, тип `byte` в Go; при переполнении
  значение заворачивается по кругу (255+1=0, 0-1=255)
  * срез (slice) — список значений переменной длины, пишется `[]byte`;
  `make([]byte, 2048)` создаёт срез из 2048 нулевых байт
  * указатель — здесь это НЕ указатель Go (`*T`), а просто переменная
  `pointer` типа `int` с номером текущей ячейки ленты
  * руна (rune) — символ Unicode, псевдоним для `int32`; в этой задаче руны
  не нужны, потому что все команды Brainfuck — однобайтовые ASCII-символы, и
  `code[i]` даёт именно байт
  * os.Args — срез строк с аргументами командной строки; `os.Args[0]` это
  имя программы, поэтому один пользовательский аргумент означает
  `len(os.Args) == 2`
  * os.Stdout.Write — запись сырых байт в стандартный вывод без
  преобразования в текст
  * switch без default — конструкция выбора; если ни один `case` не подошёл,
  не выполняется ничего, что и есть «игнорировать комментарий»
  * глубина вложенности (depth) — счётчик открытых скобок при поиске парной;
  растёт на открывающей и падает на закрывающей
  * рекурсия — вызов функцией самой себя; здесь не применяется: поиск парной
  скобки сделан счётчиком глубины в цикле
  * стек — структура «последним пришёл, первым вышел»; в этой задаче его
  можно было бы использовать для скобок, но счётчик `depth` решает то же
  самое без дополнительной памяти


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Печатать байт через `string(rune(memory[pointer]))` или `z01.PrintRune`.
  Для значений больше 127 Go закодирует руну в UTF-8 и выдаст ДВА байта
  вместо одного. Проверено: `string(rune(255))` печатает `c3 bf`, а
  `os.Stdout.Write([]byte{255})` печатает `ff`.
  * Добавить свой `\n` в конец вывода. Не надо: перевод строки печатает сама
  программа на Brainfuck. В примере Hello World последние команды `>+.>.`
  кладут в ячейку число 10 и печатают его — это и есть `\n`, поэтому `cat
  -e` показывает `Hello World!$`.
  * При поиске парной скобки брать ПЕРВУЮ встречную. Внутри цикла бывают
  вложенные циклы — нужен счётчик глубины. Пример `[[+]]+.` без счётчика
  улетит не туда.
  * Двигать `i` в неправильном порядке: сначала проверять символ, потом
  сдвигать. Тогда стартовая скобка посчитается второй раз. Правильно:
  сначала `i++` (или `i--`), потом проверка.
  * Вручную добавлять лишний сдвиг после поиска скобки. `i++` в заголовке
  главного цикла уже переводит на «команду после скобки», как требует
  условие. Двойной сдвиг пропустит одну команду.
  * Забыть проверку числа аргументов. Без неё `os.Args[1]` при запуске `go
  run .` без аргументов уронит программу с паникой index out of range, а по
  условию она должна молча ничего не напечатать.
  * Заводить ленту как `[2048]int` или обнулять её вручную. Нужен именно
  `byte` — на нём работает заворачивание 255→0, а `make` уже даёт нули.
  * Писать ветку `default` со своей логикой. Комментарий = ничего не делать,
  поэтому `default` вообще не нужен.
  * Считать, что `+` и `-` меняют указатель, а `>` и `<` — байт. Это самая
  частая путаница: `>` `<` двигают указатель, `+` `-` меняют содержимое
  ячейки.

  байт вывода; только комментарии `"Hello, this is a comment"` — 0 байт;
  пропуск вложенного цикла `"[[+]]+."` — байт `01` (значит парная скобка
  найдена верно); заворачивание вниз `"-."` — байт `ff`; печать нуля `"."` —
  байт `00`; заворачивание вверх `"-+."` — байт `00`; лишний аргумент `"+."
  "extra"` — 0 байт вывода; вложенное умножение `"+++[>+++<-]>."` — байт
  `09` (3*3=9); длинная прогулка указателем далеко вправо и обратно с
  большими вложенными циклами — байты `31 00`, панику не словил. Отдельно
  проверил утверждение из pitfalls маленькой программой:
  `string(rune(byte(255)))` печатает два байта `c3 bf`, тогда как мой
  `os.Stdout.Write` печатает один байт `ff`. СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ

  Написать программу, которая принимает два аргумента: «регулярное
  выражение» в круглых скобках и текст. Программа повторяет поведение скобок
  в регулярных выражениях: выводит слова текста, внутри которых встречается
  выражение из скобок. Оператор `|` означает «или»: ищутся обе строки по обе
  стороны от него, и слово выводится отдельной строкой за каждое совпавшее
  выражение. Вывод нумеруется в формате `N: слово` по порядку появления в
  тексте. Если аргументов не ровно 2, если выражение невалидно, если
  последний аргумент пустой или если совпадений нет — программа не печатает
  ничего.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Условие тут почти не помогает, а примеры помогают сильно — их надо
  разобрать до последней строки, потому что весь порядок вывода выводится
  именно из них. Смотри второй пример: шаблон `(e|n)`, и слово `currently`
  напечатано ДВА раза подряд, номерами 1 и 2. Значит правило такое: идём по
  словам слева направо, и для каждого слова проверяем варианты в том
  порядке, в каком они стоят в шаблоне; каждое совпадение — отдельная строка
  вывода. Проверь себя на слове `opened`: в нём две буквы `e` и одна `n`, а
  напечатано оно ровно дважды — значит считаем не количество вхождений
  буквы, а количество СОВПАВШИХ ВАРИАНТОВ. Если бы порядок был другой —
  сначала все слова с `e`, потом все слова с `n` — вывод начинался бы с
  `currently, have, opened`, а он начинается с `currently, currently, have`.
  Второй вывод из примеров — про слова. В первом примере в тексте написано
  `heavy,` с запятой, а печатается `heavy` без неё, значит запятая не входит
  в слово, она разделитель. При этом во втором примере `don’t` печатается
  целиком вместе с апострофом, значит рвать слово по любому не-букве нельзя.
  Отсюда решение: слово — это кусок текста между разделителями, а
  разделители — пробельные символы и обычная знаковая пунктуация (`,` `.`
  `!` `?` `;` `:`). Апостроф в список не входит, поэтому `don’t` и `I'm`
  остаются целыми. Дальше техника. Разбиение на слова пиши сам, одним
  проходом с переменной `start`: как только вышли из разделителя — запомнили
  начало, как только вошли в разделитель — отрезали кусок. Шаблон
  разбирается ещё проще: снимаем первый и последний символ (это `(` и `)`),
  а середину режем по `|` — получается список вариантов. Валидность проверяй
  по тому, что видно в примере: `"i"` без скобок не даёт вывода. Значит
  требуем, чтобы строка начиналась на `(`, кончалась на `)` и внутри что-то
  было; плюс отбрасывай пустые варианты типа `(a|)`, иначе пустая строка
  «содержится» в любом слове и напечатается весь текст. Про UTF-8 не бойся:
  текст с символами `’` и `…` можно резать и сравнивать по байтам, потому
  что все байты многобайтового символа больше 127 и никогда не совпадут с
  ASCII-разделителем, а сравнение подстроки по байтам для UTF-8 работает
  корректно.

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: 🔴 Поведение в краевых случаях взято из ЭТАЛОНА
  школы, а не из текста задания — они местами расходятся, а бот сверяет

  аргументов и при пустом результате: молчание и печать пустой строки — это
  разные вещи, и бот их различает.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот

    package main
    
    import (
    	"fmt"
    	"os"
    	"strings"
    	"unicode"
    )
    
    func singleSearch(exp []string, text string) []string {
    	items := strings.Split(text, " ")
    	var result []string
    
    	for _, item := range items {
    		for _, word := range exp {
    			if strings.Contains(item, word) {
    				result = append(result, item)
    			}
    		}
    	}
    	return result
    }
    
    func simpleSearch(runes []rune, text string) []string {
    	exp := string(runes)
    
    	var result []string
    	if !strings.ContainsRune(exp, '|') {
    		helper := []string{exp}
    		result = append(singleSearch(helper, text))
    	} else {
    		expWords := strings.Split(exp, "|")
    		result = append(result, singleSearch(expWords, text)...)
    	}
    	return result
    }
    
    func brackets(regexp, text string) {
    	if text == "" || regexp == "" {
    		return
    	}
    	runes := []rune(regexp)
    
    	if runes[0] == '(' && runes[len(runes)-1] == ')' {
    		runes = runes[1 : len(runes)-1]
    		result := simpleSearch(runes, text)
    		for i, s := range result {
    			if !unicode.IsLetter(rune(s[len(s)-1])) {
    				s = s[0 : len(s)-1]
    			}
    			fmt.Printf("%d: %s\n", i+1, s)
    		}
    	}
    }
    
    func main() {
    	if len(os.Args) == 3 {
    		brackets(os.Args[1], os.Args[2])
    	}
    }

func singleSearch(exp []string, text string) []string {
  Объявление первой вспомогательной функции. Два параметра: exp — срез строк (срез = список переменной длины; здесь это куски выражения, которые надо искать), text — сам текст. Возвращает срез строк — найденные слова.

	items := strings.Split(text, " ")
  Split режет text по одному пробелу и возвращает срез кусков. Знак := создаёт НОВУЮ переменную items и сразу кладёт в неё результат; тип Go выводит сам ([]string).
  🔴 Split — не Fields. Split("a  b", " ") даст три элемента: "a", "", "b" — пустой кусок между двумя пробелами не выбрасывается. Fields бы его выбросил. Эталон взял именно Split.

	var result []string
  Объявление накопителя — переменной, куда складываются найденные слова. var без значения даёт nil-срез: пустой срез длины 0, в который тем не менее можно писать через append.
  Здесь var, а не :=, потому что начального значения нет — только тип.

	for _, item := range items {
  Заголовок цикла: range items идёт по срезу и на каждом шаге отдаёт ДВЕ вещи — индекс и значение. Индекс не нужен, поэтому на его месте стоит _ (пустышка, «выбросить»). item — очередное слово текста.

		for _, word := range exp {
  Вложенный цикл: для каждого слова текста перебираем все куски выражения. word — очередной кусок.

			if strings.Contains(item, word) {
  Contains(item, word) = true, если строка word встречается ВНУТРИ item как подстрока. Именно это требует условие: слово выводится, если выражение встречается внутри него.

				result = append(result, item)
  append добавляет item в конец среза result и возвращает новый срез — поэтому обязательно присваивание обратно в result. Здесь = , а не := , потому что result уже существует; := создало бы новую переменную и потеряло бы накопленное.
  🔴 break тут нет. Если слово подходит под ОБА куска выражения (то, что слева от |, и то, что справа), оно попадёт в результат дважды — и напечатается двумя строками. Это не баг, а требование условия: отдельная строка за каждое совпавшее выражение.

			}
		}
	}
  Три закрывающие скобки: if, внутренний for, внешний for.

	return result
  Отдаём накопленный срез вызывающей стороне.

}
  Конец singleSearch.

func simpleSearch(runes []rune, text string) []string {
  Вторая вспомогательная функция. Первый параметр — []rune, срез рун. Руна = один символ (в Go тип rune, число — код символа), в отличие от байта. Второй — текст. Возвращает срез строк.

	exp := string(runes)
  Обратное превращение: из среза рун собираем обычную строку. Дальше со строкой работать удобнее.

	var result []string
  Снова накопитель, пока пустой.

	if !strings.ContainsRune(exp, '|') {
  ContainsRune проверяет, есть ли в строке exp символ | (одиночные кавычки = руна, двойные = строка). Знак ! переворачивает ответ: заходим внутрь, когда символа | НЕТ, то есть выражение простое, без «или».

		helper := []string{exp}
  Литерал среза: создаём срез строк из одного элемента — самого exp. Это нужно потому, что singleSearch принимает срез, а не одну строку.

		result = append(singleSearch(helper, text))
  🔴 Хитрая строка. append вызван с ОДНИМ аргументом — добавлять нечего, и он просто возвращает переданный срез без изменений. То есть эффект тот же, что и от простого присваивания результата singleSearch в result. Компилятор такое пропускает.

	} else {
  Ветка «символ | в выражении есть».

		expWords := strings.Split(exp, "|")
  Режем выражение по вертикальной черте: из "ab|cd" получаем срез из двух кусков "ab" и "cd". Оба надо искать.

		result = append(result, singleSearch(expWords, text)...)
  Три точки в конце — распаковка среза. singleSearch вернул срез, а append хочет отдельные элементы; ... разворачивает срез в список аргументов. Без трёх точек компилятор выдаст ошибку типов.

	}
	return result
}
  Конец simpleSearch: закрываем else, отдаём результат, закрываем функцию.

func brackets(regexp, text string) {
  Третья функция. Запись regexp, text string означает, что ОБА параметра типа string — тип пишется один раз в конце. Возвращаемого типа нет: функция сама печатает.
  regexp здесь — просто имя переменной, пакет regexp не импортирован и не используется.

	if text == "" || regexp == "" {
  Проверка на пустоту: || это «или». Если пуст текст ИЛИ пусто выражение — работать не с чем.

		return
  Ранний выход: выходим из функции, ничего не напечатав. Это и есть требование «если последний аргумент пустой — не печатать ничего». return без значения возможен, потому что функция ничего не возвращает.

	}
	runes := []rune(regexp)
  (в коде строка записана как: runes := []rune(regexp) ) — превращаем строку выражения в срез рун, чтобы обращаться к отдельным символам по номеру: runes[0], runes[len(runes)-1].

	if runes[0] == '(' && runes[len(runes)-1] == ')' {
  Проверка валидности выражения: первый символ — открывающая скобка И последний — закрывающая. && это «и», нужны оба условия.
  len(runes) — количество рун; последний элемент всегда имеет индекс len-1, потому что нумерация с нуля.
  🔴 Если условие не выполнено, тело if просто не исполняется, функция заканчивается и НИЧЕГО не печатается — ровно как требует условие для невалидного выражения.
  🔴 runes[0] безопасно только потому, что пустой regexp отсечён выше через return. Иначе было бы обращение за границу среза и падение программы.

		runes = runes[1 : len(runes)-1]
  Срез среза: берём элементы с индекса 1 (после открывающей скобки) до len-1 НЕ включая. Правая граница в Go всегда не включается — поэтому закрывающая скобка отбрасывается. Так снимаются обе скобки, остаётся содержимое.
  Здесь = , потому что runes уже существует.

		result := simpleSearch(runes, text)
  Запускаем поиск. := создаёт новую переменную result — она локальная для brackets и никак не связана с переменными result внутри других функций.

		for i, s := range result {
  Цикл по найденным словам. Здесь индекс i НУЖЕН — из него делается номер строки. s — само слово.

			if !unicode.IsLetter(rune(s[len(s)-1])) {
  Разбираем изнутри: s[len(s)-1] — последний БАЙТ слова; rune(...) превращает байт в руну; unicode.IsLetter отвечает, буква ли это; ! переворачивает. Итог: заходим внутрь, если слово оканчивается НЕ буквой — то есть на знак препинания, прилипший к слову в тексте.

				s = s[0 : len(s)-1]
  Отрезаем последний символ: берём с 0 до len-1 не включая. Присваивание в s — это локальная копия переменной цикла, в срезе result ничего не меняется.

			}
			fmt.Printf("%d: %s\n", i+1, s)
  Printf печатает по шаблону: %d — подставить целое число, %s — подставить строку, \n — перевод строки. Аргументы подставляются по порядку: сначала i+1, потом s.
  i+1, а не i, потому что нумерация в цикле идёт с нуля, а в выводе нумерация с единицы.
  🔴 Формат строгий: число, двоеточие, ОДИН пробел, слово, перевод строки. Лишний пробел или его отсутствие — задание не зачтено.

		}
	}
}
  Закрываем цикл, if со скобками и саму функцию brackets.

func main() {
  Точка входа. С неё начинается выполнение программы.

	if len(os.Args) == 3 {

		brackets(os.Args[1], os.Args[2])

ПОРЯДОК ВЫВОДА — главное, что легко перепутать
  Внешний цикл в singleSearch идёт по СЛОВАМ ТЕКСТА, внутренний — по кускам выражения. Значит результат отсортирован по порядку появления слов в тексте, а не по порядку кусков выражения. Поменяешь циклы местами — весь вывод перестроится и задание не зачтётся.


------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * байт — число 0..255, тип `byte`; `s[i]` для строки в Go даёт именно
  байт, а не символ
  * руна (rune) — один символ Unicode, псевдоним `int32`; используется
  только в `groupingItoa`, чтобы превратить код цифры в символ
  * срез (slice) — список переменной длины; здесь `[]string` для слов и
  вариантов, растёт через `append`
  * срез строки s[a:b] — кусок строки от индекса a включительно до b не
  включая; `s[a:]` — до конца строки
  * append — функция добавления элемента в конец среза; всегда присваивай
  результат обратно (`words = append(words, x)`), иначе изменение потеряется
  * os.Args — срез строк с аргументами командной строки; `os.Args[0]` — имя
  программы, поэтому два аргумента пользователя означают `len(os.Args) == 3`
  * os.Stdout.WriteString — запись готовой строки в стандартный вывод
  * UTF-8 — кодировка, в которой один символ занимает 1-4 байта; все байты
  многобайтового символа больше 127, поэтому побайтовое сравнение с
  ASCII-разделителями безопасно
  * вложенный цикл — цикл внутри цикла; здесь внешний идёт по словам,
  внутренний по вариантам, и именно этот порядок задаёт порядок вывода
  * указатель — в этом решении настоящих указателей Go (`*T`) нет; `start` и
  `i` — обычные целые индексы
  * рекурсия — вызов функцией самой себя; в этом решении не применяется, всё
  сделано обычными циклами
  * стек — структура «последним пришёл, первым вышел»; в этой задаче не
  нужен

  * Сортировать вывод по вариантам вместо слов: сначала все слова с `e`,
  потом все с `n`. Тогда второй пример даст `currently, have, opened,
  currently, ...` вместо правильного `currently, currently, have, ...`.
  Внешний цикл — по СЛОВАМ, внутренний — по вариантам.
  * Считать каждое вхождение подстроки. В слове `opened` две буквы `e`, но
  напечатать его надо всего дважды (за `e` и за `n`), а не трижды.
  `groupingContains` возвращает `true`/`false`, а не количество.
  * Резать слова по любому не-букве. Тогда `don’t` превратится в `don` и
  `t`, а второй пример требует напечатать `don’t` целиком. Разделители —
  только пробельные и знаки препинания.
  * Не считать запятую разделителем. Тогда в первом примере напечатается
  `heavy,` вместо `heavy`.
  * Забыть про последнее слово. Если добавлять слово только при встрече
  разделителя, текст, который кончается буквой (`... I'm heavy`), потеряет
  последнее слово. Нужен `if start != -1` после цикла.
  * Пропустить проверку на пустой вариант. Шаблон `(a|)` даёт пустую
  подстроку, а она «содержится» в каждом слове — программа напечатает весь
  текст вместо ничего.
  * Пропустить проверку `len(pattern) < 3`. Шаблон `()` пройдёт проверку на
  первый и последний символ, внутри окажется пустая строка — снова печать
  всего текста.
  * Считать шаблон без скобок валидным. Пятый пример Usage прямо показывает:
  `"i"` не должно печатать ничего.
  * Проверять `len(os.Args) < 3` вместо `!= 3`. Условие говорит «if the
  number of arguments is different from 2» — три и более аргументов тоже
  должны давать пустой вывод.
  * Использовать
  `strings.Split`/`strings.Fields`/`strings.Contains`/`strconv.Itoa`. На
  экзамене список разрешённых пакетов обычно урезан, а всё это пишется в
  несколько строк вручную.
  * Печатать номер без двоеточия и пробела или забыть `\n`. Формат ровно `N:
  слово` и перевод строки после каждой.
  * Сбрасывать счётчик на каждом новом слове. Нумерация сквозная по всему
  выводу, а не по каждому слову.
  * Додумать поведение для случая «аргументов нет» по логике. Проверь
  эталон: иногда там молчание, иногда пустая строка.
