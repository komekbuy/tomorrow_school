  ЧТО ПРОСЯТ СДЕЛАТЬ
------------------------------------------------------------------------------
  Программа принимает неопределённое количество строк-аргументов. Для
  каждого аргумента она печатает в стандартный вывод `OK` и перевод строки,
  если скобки в этой строке расставлены правильно, иначе `Error` и перевод
  строки. Скобками считаются только `(` `)`, `[` `]`, `{` `}` — все
  остальные символы просто игнорируются. Открывающая скобка должна
  закрываться ПАРНОЙ закрывающей и в правильном порядке; строка вообще без
  скобок считается правильной. Если аргументов нет, программа не печатает
  ничего.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  Дано: строка произвольных символов. Надо получить один ответ — да или нет.
  Главное наблюдение: любая закрывающая скобка обязана закрывать ту
  открывающую, которая была последней из ещё не закрытых. Структура данных,
  которая отдаёт именно последний положенный элемент, называется стек —
  значит задача решается стеком, и это единственный приём, который тут
  нужен. Алгоритм: идём по строке слева направо; встретили открывающую —
  кладём её в стек; встретили закрывающую — смотрим на верх стека: если там
  парная открывающая, снимаем её, если там чужая скобка или стек пуст, сразу
  возвращаем false. Дойдя до конца, проверяем, что стек пуст: если там
  что-то осталось, эти скобки никто не закрыл, значит false. Почему нельзя
  обойтись тремя счётчиками (сколько открытых круглых, квадратных,
  фигурных): на строке `([)]` все три счётчика сойдутся в ноль, а строка
  неправильная — счётчик хранит количество, но не хранит порядок, а порядок
  хранит только стек. Все остальные символы не требуют отдельной ветки: если
  байт не попал ни в одно из двух условий, цикл просто идёт дальше, и это
  ровно то, что просит условие словом «ignored». Идти по байтам, а не по
  рунам, здесь безопасно: все шесть скобок лежат в ASCII, а байты внутри
  многобайтовых UTF-8 символов всегда имеют значение 0x80 и выше и ни с
  одной скобкой совпасть не могут. Сам стек — это обычный срез: `append`
  кладёт наверх, `s[len(s)-1]` читает верх, `s[:len(s)-1]` снимает верх.
  Отдельно держим в голове два требования условия, которые легко потерять:
  строка без скобок — правильная (её обрабатывает та же финальная проверка
  `len(stack) == 0`), и при нуле аргументов не должно быть напечатано вообще
  ничего (это выходит само собой, потому что цикл по пустому срезу
  аргументов не выполнится ни разу).

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: 🔴 Поведение в краевых случаях взято из ЭТАЛОНА
  школы, а не из текста задания — они местами расходятся, а бот сверяет
  ответ именно с эталоном. Обрати внимание, что происходит при отсутствии
  аргументов и при пустом результате: молчание и печать пустой строки — это
  разные вещи, и бот их различает.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот

    package main
    
    import (
    	"fmt"
    	"os"
    )
    
    func matchBrackets(exp string) bool {
    	runes := []rune(exp)
    	var opened []rune
    	ptr := -1
    	for _, c := range runes {
    		if c == '(' || c == '[' || c == '{' {
    			opened = append(opened, c)
    			ptr++
    		} else if c == ')' {
    			if ptr < 0 || opened[ptr] != '(' {
    				return false
    			}
    			opened = opened[:len(opened)-1]
    			ptr--
    		} else if c == ']' {
    			if ptr < 0 || opened[ptr] != '[' {
    				return false
    			}
    			opened = opened[:len(opened)-1]
    			ptr--
    		} else if c == '}' {
    			if ptr < 0 || opened[ptr] != '{' {
    				return false
    			}
    			opened = opened[:len(opened)-1]
    			ptr--
    		}
    	}
    	return len(opened) == 0
    }
    
    func main() {
    	if len(os.Args) == 1 {
    		fmt.Println()
    	} else {
    		for _, v := range os.Args[1:] {
    			if matchBrackets(v) {
    				fmt.Println("OK")
    			} else {
    				fmt.Println("Error")
    			}
    		}
    	}
    }

```go
func matchBrackets(exp string) bool {
```

  Вспомогательная функция: получает строку, возвращает `bool` — логическое значение, `true` (правда) или `false` (ложь). Никакой печати внутри, только ответ да/нет. Печать вынесена в `main`.

```go
	runes := []rune(exp)
```
  (в эталоне строка записана как `runes := []rune(exp)`)
  `[]rune(exp)` превращает строку в **срез рун**. **Руна** — один символ целиком, каким бы длинным он ни был в байтах. Латинская буква занимает 1 байт, русская 2, эмодзи 4 — как руна каждая из них одна.
  Без этого преобразования проход по строке шёл бы по байтам и на не-латинице символы бы разваливались.

```go
	var opened []rune
```
  `var` без значения: срез создан пустым (`nil`), длина 0. `append` с таким срезом работает нормально.
  Это **стек** — список, куда кладут и откуда забирают только с конца. Здесь копятся ещё не закрытые открывающие скобки.

```go
	ptr := -1
```
  Номер последней открытой скобки в `opened`. `-1` значит «стек пуст», потому что номер 0 — уже существующий первый элемент.
  🔴 `ptr` всегда равен `len(opened)-1`. Это дублирующий счётчик: код мог бы обходиться одной длиной среза, но эталон ведёт обе величины параллельно. Главное — не забывать менять обе.

```go
	for _, c := range runes {
```
  Проход по всем рунам. `_` выбрасывает номер элемента, он не нужен. `c` — очередная руна.

```go
		if c == '(' || c == '[' || c == '{' {
```
  🔴 Одинарные кавычки `'('` — это **руна** (одиночный символ). Двойные `"("` — строка. Сравнить руну со строкой Go не даст, будет ошибка компиляции.
  `||` — «или»: достаточно любого совпадения.

```go
			opened = append(opened, c)
			ptr++
```
  Открывающая скобка кладётся на верх стека. `append` возвращает новый срез, поэтому результат присваивают обратно в `opened`.
  `ptr++` увеличивает счётчик на 1. В Go это отдельная инструкция, а не выражение: написать `x := ptr++` нельзя.

```go
		} else if c == ')' {
```
  Встретили круглую закрывающую.

```go
			if ptr < 0 || opened[ptr] != '(' {
				return false
			}
```
  🔴 **Порядок частей в этом условии обязателен.** `||` в Go вычисляется слева направо и останавливается, как только левая часть оказалась истинной. Если стек пуст (`ptr < 0`), правая часть просто не выполняется. Поменяй местами — и `opened[-1]` уронит программу с `index out of range` на строке `")"`.
  Два случая ошибки: закрывающая пришла, а открывать было нечего; либо наверху стека лежит скобка **другого вида** — значит `(]` или `[)`, порядок нарушен.
  `return false` — ранний выход: как только нашли ошибку, дальше проверять смысла нет.

```go
			opened = opened[:len(opened)-1]
			ptr--
```
  `opened[:len(opened)-1]` — **срез от среза**: берём элементы с начала до номера `len(opened)-1`, не включая его. То есть выбрасываем последний. Пара закрылась.
  `ptr--` уменьшает счётчик на 1, чтобы он снова совпадал с новой длиной минус один.

```go
		} else if c == ']' {
			if ptr < 0 || opened[ptr] != '[' {
				return false
			}
			opened = opened[:len(opened)-1]
			ptr--
		} else if c == '}' {
			if ptr < 0 || opened[ptr] != '{' {
				return false
			}
			opened = opened[:len(opened)-1]
			ptr--
		}
```
  То же самое для квадратной и фигурной. Меняется только ожидаемая открывающая скобка: `[` для `]`, `{` для `}`.
  🔴 Ни одного `else` в самом конце нет. Любой другой символ — буква, цифра, пробел — не попадает ни в одну ветку и просто игнорируется, как и требует задача.

```go
	}
	return len(opened) == 0
}
```
  Дошли до конца строки без ошибок. Осталось проверить, что все открытые скобки закрылись.
  🔴 `len(opened) == 0` — это уже готовое логическое значение, его возвращают напрямую. Писать `if len(opened) == 0 { return true } else { return false }` не нужно, результат тот же.
  🔴 Именно эта строка ловит `"(()"`: ошибок по пути не было, но одна скобка осталась незакрытой.

### Что реально печатается (проверено запуском)
```
./brackets "()" "[]" "{}" "([{}])"   →  OK OK OK OK   (каждое на своей строке)
./brackets "(]"                       →  Error
./brackets "hello"                    →  OK      (скобок нет — правильно)
./brackets ""                         →  OK      (пустая строка — правильно)
./brackets "(()"                      →  Error   (не закрыли)
./brackets "())"                      →  Error   (лишняя закрывающая)
./brackets "a(b[c]d)e"                →  OK      (буквы игнорируются)
./brackets                            →  пустая строка
```



------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * стек — хранилище, из которого всегда достают тот элемент, который
  положили последним; здесь реализован срезом
  * срез (slice) — список значений одного типа переменной длины; len(x) даёт
  текущую длину
  * append — встроенная функция, добавляющая элемент в конец среза и
  возвращающая новый срез; результат надо присваивать обратно
  * байт (byte) — число от 0 до 255; обращение к строке по индексу s[i] даёт
  именно байт
  * руна (rune) — код одного символа Unicode целиком; здесь руны не нужны,
  потому что все скобки помещаются в один байт
  * ASCII — набор символов с кодами 0..127, куда входят все шесть скобок
  * UTF-8 — кодировка, в которой русская буква занимает 2 байта, а все её
  байты имеют код 0x80 и выше, поэтому со скобками не путаются
  * os.Args — срез строк с аргументами командной строки, где os.Args[0] —
  путь к самой программе
  * os.Stdout.WriteString — запись строки в стандартный вывод без
  форматирования и без добавления перевода строки
  * stack[:len(stack)-1] — операция снятия верхнего элемента: новый срез без
  последнего элемента
  * stack[len(stack)-1] — чтение верхнего элемента без его удаления
  * return — немедленный выход из функции с указанным значением


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Считать скобки счётчиками вместо стека: на `([)]` количества сходятся, и
  программа ошибочно напечатает OK вместо Error. Порядок хранит только стек.
  * Забыть проверку len(stack) == 0 перед чтением верхушки: на строке `)`
  программа упадёт с паникой index out of range.
  * Забыть финальную проверку len(stack) == 0: строка `(((` напечатает OK
  вместо Error.
  * Забыть, что строка без скобок правильная: не надо добавлять условие
  «если скобок нет — Error», условие требует ровно наоборот, `abc` это OK.
  * Пустая строка '' — это полноценный аргумент, для неё надо напечатать OK.
  В примере README третья команда передаёт '' первым аргументом и ждёт две
  строки OK.
  * Начать цикл с os.Args[0]: нулевой элемент это путь к программе, а не
  аргумент пользователя, и он бы дал лишнюю строку вывода.
  * Печатать OK/Error без перевода строки: README явно требует newline после
  каждого ответа, и cat -e в примерах показывает $ в конце каждой строки.
  * Печатать что-нибудь при нуле аргументов: `go run .` должен вывести
  пустоту, ни пустой строки, ни пробела.
  * Проверять только одну из трёх пар скобок, а забыть про две другие — код
  проходит примеры из README и валится на смешанных строках вроде `(]`.
  * Пытаться сделать проверку рекурсией или разбором вложенности — работает,
  но длиннее и легче ошибиться; стек короче и на экзамене пишется быстрее.
  * Додумать поведение для случая «аргументов нет» по логике. Проверь
  эталон: иногда там молчание, иногда пустая строка.

  Программа получает ровно один аргумент — строку с выражением в обратной
  польской записи (RPN), где оператор пишется после своих двух операндов, а
  операнды и операторы разделены хотя бы одним пробелом. Программа вычисляет
  выражение и печатает целый результат и перевод строки. Поддерживаются
  операторы `+`, `-`, `*`, `/`, `%`. Если строка невалидна или аргументов не
  ровно один, печатается `Error` и перевод строки. Лишние пробелы строку не
  портят. Все операнды по условию помещаются в int.


------------------------------------------------------------------------------
  КАК ДУМАТЬ НАД ЗАДАЧЕЙ (читать до кода)
------------------------------------------------------------------------------
  В обратной польской записи скобок нет, порядок действий задан самим
  расположением: оператор относится к двум ближайшим слева результатам.
  Отсюда сразу следует алгоритм и структура данных — стек: читаем куски
  строки слева направо, число кладём в стек, оператор снимает два верхних
  числа, применяет операцию и кладёт результат обратно. Порядок снятия
  критичен: верхний элемент стека — это ПРАВЫЙ операнд, а тот, что под ним,
  — ЛЕВЫЙ; для `+` и `*` перепутать безвредно, для `-`, `/` и `%` перепутать
  значит получить неправильный ответ (`5 3 -` это 2, а не -2). Задача
  распадается на три независимые части, и удобно писать их отдельными
  функциями: разбить строку на токены, прочитать токен как число, напечатать
  число. Разбивать нельзя через деление по одному пробелу, потому что README
  прямо разрешает лишние пробелы, а деление по одному пробелу на двойном
  пробеле выдаст пустой кусок, который потом не прочитается как число и даст
  ложный Error; поэтому пишем свой сплиттер, который сначала проматывает
  подряд идущие пробелы, а потом вырезает непустой кусок. Проверка токена
  делается в правильном порядке: сначала сравниваем с пятью операторами, и
  только если не совпало, пробуем прочитать как число — иначе токен `-`
  (оператор) спутается с началом отрицательного числа. Валидность выражения
  проверяется тремя условиями, и все три нужны: перед оператором в стеке
  должно быть минимум два числа, делить и брать остаток на ноль нельзя (в Go
  это не ошибка, а аварийная остановка программы, поэтому проверять
  обязательно самому), и в самом конце в стеке должно остаться ровно одно
  число — если осталось два и больше, значит операторов не хватило, если
  ноль, значит строка была пустая. «Ровно один аргумент» на языке Go это
  len(os.Args) == 2, потому что нулевой элемент os.Args — это путь к самой
  программе. Печатать результат лучше своим itoa: делим число на 10 в цикле,
  остаток от деления даёт очередную цифру справа налево, поэтому каждую
  новую цифру приклеиваем СЛЕВА к уже собранной строке; отдельно
  обрабатываем ноль (цикл для него не выполнится ни разу) и минус
  (запоминаем знак до цикла, а цифры берём по модулю).

  СВЕРЕНО С ЭТАЛОНОМ ШКОЛЫ: 🔴 Поведение в краевых случаях взято из ЭТАЛОНА
  школы, а не из текста задания — они местами расходятся, а бот сверяет
  ответ именно с эталоном. Обрати внимание, что происходит при отсутствии
  аргументов и при пустом результате: молчание и печать пустой строки — это
  разные вещи, и бот их различает.

  ПРО ПАКЕТЫ: здесь приведён код ЭТАЛОНА ШКОЛЫ — ровно тот, с которым бот
  сравнивает твой ответ. Значит все пакеты, которые он подключает, для этого

    package main
    
    import (
    	"fmt"
    	"os"
    	"strconv"
    	"strings"
    )
    
    func deleteExtraSpaces(a []string) (res []string) {
    	for _, v := range a {
    		if v != "" {
    			res = append(res, v)
    		}
    	}
    	return
    }
    
    func main() {
    	if len(os.Args) != 2 {
    		fmt.Println("Error")
    		return
    	}
    	var values []int
    	op := strings.Split(os.Args[1], " ")
    	op = deleteExtraSpaces(op)
    	for _, v := range op {
    		val, err := strconv.Atoi(v)
    
    		if err == nil {
    			values = append(values, val)
    			continue
    		}
    
    		n := len(values)
    		if n < 2 {
    			fmt.Println("Error")
    			return
    		}
    
    		switch v {
    		case "+":
    			values[n-2] += values[n-1]
    			values = values[:n-1]
    		case "-":
    			values[n-2] -= values[n-1]
    			values = values[:n-1]
    		case "*":
    			values[n-2] *= values[n-1]
    			values = values[:n-1]
    		case "/":
    			values[n-2] /= values[n-1]
    			values = values[:n-1]
    		case "%":
    			values[n-2] %= values[n-1]
    			values = values[:n-1]
    		default:
    			fmt.Println("Error")
    			return
    		}
    	}
    	if len(values) == 1 {
    		fmt.Println(values[0])
    	} else {
    		fmt.Println("Error")
    	}
    }

## РАЗБОР ПО СТРОКАМ

Программа-калькулятор для обратной польской записи: `"3 4 + 5 *"` значит `(3+4)*5`. Оператор идёт **после** своих двух чисел.

```go
package main
```
  Исполняемая программа, а не библиотека функций.

```go
import (
	"fmt"
	"os"
	"strconv"
	"strings"
)
```
  Четыре пакета. Раз их использует эталон школы — для этого задания они разрешены.
  `fmt` — печать. `os` — аргументы командной строки. `strconv` — строка в число. `strings` — разрезание строки.

```go
func deleteExtraSpaces(a []string) (res []string) {
```
  Вспомогательная функция. Принимает срез строк, возвращает срез строк.
  🔴 `(res []string)` — **именованный результат**. Переменная `res` создаётся автоматически при входе в функцию и сразу равна `nil` (пустой срез). Объявлять её отдельно внутри не нужно.

```go
	for _, v := range a {
```
  Проход по всем кускам. `_` выбрасывает номер элемента, он не нужен. `v` — очередная строка.

```go
		if v != "" {
			res = append(res, v)
		}
```
  `append(срез, элемент)` дописывает элемент в конец и **возвращает новый срез** — поэтому результат обязательно присваивают обратно в `res`. Просто `append(res, v)` без присваивания ничего бы не изменило.
  В результат попадают только непустые куски.
  🔴 Зачем это вообще нужно: `strings.Split("1  2", " ")` при двух пробелах подряд даёт `["1", "", "2"]` — между двумя разделителями появляется пустой кусок. Эта функция их выбрасывает. Без неё `Atoi("")` дал бы ошибку, дальше `switch` ушёл бы в `default` и напечатал `Error` на нормальном выражении.

```go
		}
	}
	return
}
```
  🔴 Голый `return` без значения при именованном результате возвращает то, что сейчас лежит в `res`. Это называется «голый возврат». Работает только потому, что результат назван в заголовке.

```go
func main() {
	if len(os.Args) != 2 {
		fmt.Println("Error")
		return
	}
```
  🔴 `os.Args[0]` — путь к самой программе. Поэтому «ровно один аргумент» это `len(os.Args) == 2`. Проверка стоит первой: без неё `os.Args[1]` ниже вызвал бы падение при нуле аргументов.
  `Println` сам добавляет перевод строки, `\n` дописывать не нужно.
  `return` завершает `main` — ранний выход.

```go
	var values []int
```
  `var` без значения: срез создан пустым (`nil`), длина 0. `append` с пустым срезом работает нормально.
  Это **стек** — список, куда кладут и откуда забирают только с конца. Весь алгоритм RPN держится на нём.

```go
	op := strings.Split(os.Args[1], " ")
```
  Режем аргумент по **одному** пробелу. Куски — числа и операторы вперемешку, все пока строки.

```go
	op = deleteExtraSpaces(op)
```
  🔴 Здесь `=`, а не `:=`: переменная `op` уже существует, второй раз объявлять нельзя. Выбрасываем пустые куски от лишних пробелов.

```go
	for _, v := range op {
```
  Идём по всем кускам слева направо. `v` — очередной кусок, строка.

```go
		val, err := strconv.Atoi(v)

```
  `Atoi` пытается прочитать строку как целое число и возвращает **два** значения: число и ошибку. Пустая строка ниже — просто отступ в эталоне, смысла не несёт.

```go
		if err == nil {
			values = append(values, val)
			continue
		}
```
  `err == nil` значит «ошибки нет», кусок оказался числом — кладём его на верх стека.
  🔴 `continue` перескакивает к следующему куску, не выполняя остаток тела цикла. Без него число тут же попало бы в `switch` и ушло в `default` → `Error`.
  🔴 Отрицательные операнды работают сами собой: `Atoi("-5")` даёт -5 без ошибки. А одиночный `"-"` числом не читается и попадает дальше, в оператор.

```go
		n := len(values)
```
  Текущий размер стека, посчитанный **до** операции. Дальше он используется трижды, поэтому запомнили в переменную.

```go
		if n < 2 {
			fmt.Println("Error")
			return
		}
```
  Любому оператору нужно два числа. Если их меньше — выражение битое, выходим сразу.
  🔴 Эта проверка обязана стоять **до** обращений к `values[n-1]` и `values[n-2]`. При `n = 1` индекс `n-2` равен -1 и программа упала бы.

```go
		switch v {
```
  `switch` сравнивает строку `v` по очереди с каждым `case`. В Go после сработавшего `case` выполнение не проваливается в следующий — `break` писать не нужно.

```go
		case "+":
			values[n-2] += values[n-1]
			values = values[:n-1]
```
  🔴 `values[n-1]` — последний элемент, тот что положили **позже**, это правый операнд. `values[n-2]` — предыдущий, левый операнд. Результат записывается на место левого.
  `values[:n-1]` — **срез от среза**: берём элементы с начала и до номера `n-1`, не включая его. То есть отрезаем последний. Два числа превратились в одно.

```go
		case "-":
			values[n-2] -= values[n-1]
			values = values[:n-1]
```
  🔴 Порядок здесь критичен: «предпоследний минус последний». Для `"5 3 -"` это 5 - 3 = 2. Поменяешь местами — получишь -2. Для `+` и `*` порядок не важен, для `-`, `/`, `%` важен.

```go
		case "*":
			values[n-2] *= values[n-1]
			values = values[:n-1]
```
  Умножение, всё то же самое.

```go
		case "/":
			values[n-2] /= values[n-1]
			values = values[:n-1]
```
  🔴 Деление **целочисленное**: дробная часть отбрасывается. `"1 2 * 3 /"` даёт 0, потому что 2/3 = 0. Проверено запуском.
  🔴 Деления на ноль эталон не проверяет: `"1 0 /"` роняет программу с `panic: integer divide by zero`, а не печатает `Error`. Проверено запуском. Знай об этом, но эталон повторяй как есть.

```go
		case "%":
			values[n-2] %= values[n-1]
			values = values[:n-1]
```
  `%` — остаток от деления. `"7 2 %"` даёт 1.

```go
		default:
			fmt.Println("Error")
			return
		}
	}
```
  `default` срабатывает, когда не подошёл ни один `case`. Сюда попадает всё, что не число и не известный оператор: `^`, `abc`, `3.5`.

```go
	if len(values) == 1 {
		fmt.Println(values[0])
	} else {
		fmt.Println("Error")
	}
}
```
  🔴 Финальная проверка. В правильном выражении на стеке остаётся **ровно одно** число — ответ.
  Ноль элементов — ввод был пустой. Больше одного — операндов больше, чем операторов: `"1 2 3 4 +"` оставляет `[1, 2, 7]`, значит `Error`.
  `Println` печатает число и сам добавляет перевод строки.

### Что реально печатается (проверено запуском)
```
"3 4 + 5 *"     →  35
"  1   2 +  "   →  3        (лишние пробелы не мешают)
"7 2 %"         →  1
"-5 3 +"        →  -2
"1 2 * 3 /"     →  0        (целочисленное деление)
"1 2 3 4 +"     →  Error    (осталось 3 числа)
"1 +"           →  Error    (мало операндов)
"1 2"           →  Error    (нет оператора)
""              →  Error
два аргумента   →  Error
```



------------------------------------------------------------------------------
  ТЕРМИНЫ, КОТОРЫЕ ЗДЕСЬ ВСТРЕТИЛИСЬ
------------------------------------------------------------------------------
  * RPN (обратная польская запись) — форма записи, где оператор идёт после
  обоих своих операндов и скобки не нужны
  * операнд — число, над которым выполняется операция; оператор — знак самой
  операции (+ - * / %)
  * токен — отдельный кусок строки без пробелов внутри: либо число, либо
  оператор
  * стек — хранилище, отдающее последний положенный элемент; здесь
  реализован срезом []int
  * срез (slice) — список значений одного типа переменной длины; append
  добавляет в конец, x[:len(x)-2] снимает два последних элемента
  * байт (byte) — число от 0 до 255; s[i] у строки даёт именно байт, поэтому
  сравнения с ' ' и '0' работают напрямую
  * руна (rune) — код одного символа Unicode; в rpnItoa через rune('0'+d)
  цифра превращается в символ
  * множественный возврат — функция в Go может вернуть сразу несколько
  значений; rpnAtoi возвращает (int, bool), где bool говорит, удалось ли
  прочитать число
  * os.Args — срез строк с аргументами командной строки; os.Args[0] — путь к
  программе, поэтому «ровно один аргумент» это len(os.Args) == 2
  * целочисленное деление — деление int на int отбрасывает дробную часть:
  10/9 равно 1, -10/3 равно -3
  * остаток (%) — то, что остаётся после целочисленного деления; знак
  результата в Go совпадает со знаком левого операнда: -7 % 2 равно -1
  * паника (panic) — аварийная остановка программы; возникает при делении на
  ноль и при обращении к элементу за границами среза
  * накопление числа n = n*10 + цифра — стандартный приём чтения числа из
  строки слева направо


------------------------------------------------------------------------------
  ГДЕ ЗАВАЛИВАЮТСЯ НА ЭТОЙ ЗАДАЧЕ
------------------------------------------------------------------------------
  * Перепутать порядок операндов. Левый — это stack[len-2], правый —
  stack[len-1]. `5 3 -` должно дать 2, а не -2; `10 2 /` должно дать 5, а не
  0. На + и * ошибка не видна, поэтому проверять надо именно на - и /.
  * Разбивать строку делением по одному пробелу. README прямо разрешает
  лишние пробелы: на "     1      3 * 2 -" такое деление даст кучу пустых
  кусков, которые не прочитаются как числа, и программа напечатает Error
  вместо 1. Нужен свой сплиттер, который проматывает пробелы пачкой.
  * Забыть проверку деления и остатка на ноль. В Go это не ошибка, а паника:
  программа рухнет вместо печати Error. Проверять надо и для /, и для %.
  * Забыть проверку len(stack) < 2 перед оператором. На строке "1 +"
  программа упадёт с паникой по отрицательному индексу.
  * Забыть финальную проверку len(stack) == 1. Без неё "1 2" напечатает 2
  вместо Error, а именно на этом построен второй пример README ("1 2 3 4 +"
  → Error).
  * Проверять число раньше оператора. Если сначала пробовать прочитать токен
  как число, надо отдельно следить, чтобы одиночный "-" не стал числом.
  Проще сравнить с пятью операторами первым делом.
  * Написать len(os.Args) >= 2 вместо != 2. Условие требует РОВНО один
  аргумент, значит два и больше аргументов — тоже Error.
  * Не обработать ноль в itoa отдельно. Цикл while n != 0 для нуля не
  выполнится ни разу и вернёт пустую строку — вывод получится пустым вместо
  "0".
  * Приклеивать цифру справа, а не слева. Цифры достаются с конца числа,
  поэтому каждую новую надо ставить в НАЧАЛО накопителя, иначе число
  напечатается задом наперёд.
  * Печатать результат без перевода строки. README требует newline после
  числа, cat -e в примерах показывает $ в конце.
  * Переполнение int в коде не проверяется — это осознанно: README
  гарантирует «All the given operands must fit in a int». Если на экзамене
  подсунуть операнд больше int, вывод будет мусорным числом, а не Error.
  * В README у четвёртого примера опечатка: показано `1` без `$`, хотя
  команда идёт через cat -e. Реально программа печатает `1$` — перевод
  строки там есть, и он нужен.
  * Додумать поведение для случая «аргументов нет» по логике. Проверь
  эталон: иногда там молчание, иногда пустая строка.
