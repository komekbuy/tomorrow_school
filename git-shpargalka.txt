КАЖДАЯ ПАПКА СО СВОИМ .git — ОТДЕЛЬНЫЙ РЕПОЗИТОРИЙ.
Они ничего не знают друг о друге. Адрес хранится внутри .git,
поэтому git всегда шлёт туда, куда надо — если ты в правильной папке.

piscinego исключён из родительского репозитория через .gitignore,
иначе получился бы репозиторий внутри репозитория и всё сломалось бы.

ПРОВЕРИТЬ, КУДА УЙДЁТ PUSH:
    git remote -v

--------------------------------------------------------------------------------
ЕЖЕДНЕВНЫЙ ЦИКЛ
--------------------------------------------------------------------------------

    git status              что изменилось
    git add .               выбрать всё для сохранения
    git commit -m "текст"   сохранить у себя
    git push                отправить на сервер

Схема:
    рабочая папка ──add──► подготовлено ──commit──► сейв ──push──► сервер

Пропустить шаг нельзя: push отправляет только ЗАКОММИЧЕННОЕ.

Сокращение (только для уже отслеживаемых файлов, новые так не добавятся):
    git commit -am "текст"

--------------------------------------------------------------------------------
РАБОТА НА ДВУХ КОМПЬЮТЕРАХ
--------------------------------------------------------------------------------

НАЧАЛО РАБОТЫ — всегда сначала забрать чужие изменения:
    git pull

КОНЕЦ РАБОТЫ — отправить свои:
    git add .
    git commit -m "текст"
    git push

Забудешь pull перед работой — получишь конфликт при push.

--------------------------------------------------------------------------------
ПЕРВАЯ НАСТРОЙКА НА НОВОМ КОМПЬЮТЕРЕ (Mac Mini)
--------------------------------------------------------------------------------

1. Проверить, есть ли SSH-ключ:
       ls ~/.ssh/*.pub

2. Если НЕТ — создать:
       ssh-keygen -t ed25519 -C "komekbuy@gmail.com"
       (три раза Enter — путь по умолчанию, без пароля)

3. Скопировать публичный ключ:
       cat ~/.ssh/id_ed25519.pub
       (выделить вывод и скопировать целиком)

4. Добавить на GitHub:
       github.com → аватар справа вверху → Settings
       → SSH and GPG keys → New SSH key
       → Title: любое (например "Mac Mini")
       → Key: вставить скопированное
       → Add SSH key

5. Проверить:
       ssh -T git@github.com
   Должно ответить: Hi komekbuy! You've successfully authenticated...

6. Склонировать:
       cd ~/Documents
       git clone git@github.com:komekbuy/tomorrow_school.git
       cd tomorrow_school
       git clone https://01.tomorrow-school.ai/git/nzhanshu/piscinego.git

   Второй клон встанет внутрь первого — так и надо,
   .gitignore его проигнорирует.

7. Настроить имя и почту (если git ругается при коммите):
       git config --global user.name "komekbuy"
       git config --global user.email "komekbuy@gmail.com"

ВАЖНО: SSH-ключ привязан к КОМПЬЮТЕРУ, а не к аккаунту.
На каждой новой машине — свой ключ.

--------------------------------------------------------------------------------
СОЗДАТЬ НОВЫЙ РЕПОЗИТОРИЙ С НУЛЯ
--------------------------------------------------------------------------------

1. На github.com: + → New repository
   имя → БЕЗ ГАЛОЧЕК (README, .gitignore, license) → Create

   Почему без галочек: они создадут файлы на сервере, репозиторий станет
   непустым, и первый push упрётся в расхождение историй.

2. В терминале:
       cd <папка проекта>
       git init
       git add .
       git commit -m "первый коммит"
       git remote add origin git@github.com:komekbuy/ИМЯ.git
       git push -u origin main

   Флаг -u запоминает связь: дальше хватает просто  git push

--------------------------------------------------------------------------------
.gitignore
--------------------------------------------------------------------------------

Файл со списком того, что git должен НЕ ЗАМЕЧАТЬ.
Лежит в корне репозитория. Имя начинается с точки — файл скрытый.

Мой текущий:
    piscinego/
    .DS_Store

Слеш на конце = это папка, игнорировать целиком.

Создать:
    touch .gitignore
    open -a "Visual Studio Code" .gitignore

Проверить, что работает:
    git status
    (исключённого в списке быть не должно)

--------------------------------------------------------------------------------
ЧТО ЗНАЧАТ СОСТОЯНИЯ В git status
--------------------------------------------------------------------------------

Untracked files (красное)          git файл не отслеживает → нужен add
Changes to be committed (зелёное)  добавлено → нужен commit
Your branch is ahead by N commits  закоммичено, но не отправлено → нужен push
nothing to commit, working tree clean + up to date   всё отправлено ✅

--------------------------------------------------------------------------------
HTTPS vs SSH
--------------------------------------------------------------------------------

    https://...      спрашивает логин и пароль
                     (у школы credential.helper store запомнил пароль,
                      он лежит открытым текстом в ~/.git-credentials)

    git@github.com:  использует SSH-ключ, пароль не спрашивает вообще

SSH удобнее и безопаснее. Для GitHub используем его.
