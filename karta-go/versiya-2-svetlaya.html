Карта Go.

Шесть областей языка в порядке, в котором они опираются друг на друга. Читается слева направо: каждая следующая область пользуется тем, что объяснено в предыдущей.

Как читать. Стрелка между колонками значит «дальше нужно то, что слева». Белые блоки — понятия. Цветные блоки с подписью ОТЛИЧИЕ — пары, которые чаще всего путают между собой.
→ зависит от предыдущего
↳ ведёт к другой теме
Цвет = область. Он один и тот же у заголовка, точки и полоски кода.

Программа

из чего собрана

Пакет и точка входа

Файл начинается со слова package — это имя папки-пакета. Пакет с именем main и функцией main внутри — единственное, что можно запустить.

package main

func main() {
}

Любое другое имя пакета — библиотека: она компилируется, но сама не запускается, её подключают другие.

Как код становится программой

Go — компилируемый язык. Твой текст не выполняется напрямую: сначала компилятор целиком переводит его в машинный код процессора.

исходник
файл .go, текст, который читает человек
компиляция
перевод текста в машинный код
бинарник
готовый файл-программа, который читает процессор

Ошибку компилятор находит до запуска. Поэтому в Go программа либо не собирается вовсе, либо работает.

ОТЛИЧИЕ go run и go build

go run .

  • собирает во временную папку
  • запускает
  • файл удаляет
  • для проверки на ходу

go build .

  • собирает рядом с кодом
  • не запускает
  • файл остаётся
  • чтобы отдать или хранить
Бинарник Go ни от чего не зависит — внутри уже всё нужное, поэтому весит мегабайты. Он собран под конкретную систему: сделанный на Mac на Linux не запустится.

Имя решает видимость

Имя с большой буквы — видно из других пакетов. С маленькой — только внутри своего. Это вся система доступа в языке.

func Sum() видна снаружи · func sum() нет

Модуль и чужой код

Модуль — папка с файлом go.mod, где записано имя проекта. С него начинается любая работа.

go mod init myproject

import подключает чужой пакет. Всё, что идёт в поставке Go, доступно сразу — качать ничего не надо.

fmt печать
strings строки
strconv число ↔ строка
os аргументы и файлы

Значения

что программа хранит

Переменная и тип

Переменная — имя, за которым стоит значение. Тип решает, что там можно хранить и что с этим можно делать.

x := 10        // создать
x = 20         // изменить
var y int      // создать пустой
const Pi = 3.14
:=
создаёт новую переменную, работает только внутри функции
=
записывает в уже существующую
const
значение, которое нельзя менять

Нулевое значение

В Go нет «пустой» переменной. Всё созданное сразу имеет нулевое значение своего типа — им можно пользоваться, не боясь мусора.

int 0
float64 0
string ""
bool false
указатель, слайс, map nil
ОТЛИЧИЕ целое и дробное

int

  • целые числа
  • 7/2 = 3, остаток отброшен
  • точно всегда

float64

  • дробные числа
  • 7.0/2 = 3.5
  • точно не всегда
Дробные хранятся приблизительно, поэтому сравнивать их через == нельзя: 0.1+0.2 не равно 0.3. Сравнивают разницу с очень малым числом.

Типы сами не смешиваются

Go не приводит типы за тебя. Сложить int и float64 нельзя — не соберётся. Нужно перевести явно.

var a int = 3
var b float64 = 1.5
float64(a) + b   // 4.5

↳ Дальше это станет важно в наборах: тип элемента там тоже строгий.

Операторы

+ - * / счёт
% остаток от деления
++ -- на единицу
== равно
!= не равно
< > <= >= сравнение

% — самый нужный на экзаменах: n % 2 == 0 проверяет чётность, n % 10 даёт последнюю цифру числа.

+ у строк означает склейку, а не сложение: "a" + "b" даёт "ab".

Текст

особый вид значения

Строка — это байты

Строка хранится не как набор букв, а как набор байтов. Для латиницы одна буква = один байт, для кириллицы = два.

s := "Привет"
len(s)   // 12, а не 6
s[0]     // 208 — байт

Поэтому len считает байты, а взятие s[i] даёт число, а не букву.

ОТЛИЧИЕ byte и rune

byte

  • одна ячейка памяти
  • число 0…255
  • другое имя типа uint8
  • даёт s[i]

rune

  • один символ любого языка
  • число-код символа
  • другое имя типа int32
  • даёт range
Нужны символы, а не байты — иди по строке через range либо переведи её в []rune. Тогда длина совпадёт с числом букв.

Строку нельзя изменить

Строка неизменяема: s[0] = 'H' не соберётся никогда. Изменение — это всегда сборка новой строки.

s = s + "!"        // новая строка
r := []rune(s)     // копия в рунах
r[0] = 'П'         // её менять можно
s = string(r)      // и собрать обратно

Символ и строка — разное

В одинарных кавычках — один символ, это число. В двойных — строка, даже если буква одна.

'a' это руна 97 · "a" это строка длиной 1

'9' - '0' даёт число 9 — так цифра-символ превращается в цифру-число.

Готовые инструменты

Их даёт стандартная библиотека. На заданиях школы часто запрещены — тогда то же самое пишут руками.

strings.Splitстрока → слова
strings.Joinслова → строка
strings.Containsесть ли кусок внутри
strconv.Atoiстрока → число
strconv.Itoaчисло → строка

Наборы

много значений вместе
ОТЛИЧИЕ массив и слайс

[3]int — массив

  • длина вшита в тип
  • длина не меняется никогда
  • [3]int и [5]int — разные типы
  • при передаче копируется весь
  • append не работает

[]int — слайс

  • длины в типе нет
  • длина растёт через append
  • тип один — []int
  • при передаче копируется только окно
  • основной рабочий инструмент
Слайс — это окно в массив, а не сами данные. Внутри него лежат три числа: где начало, сколько видно (len) и сколько влезет (cap). Данные лежат отдельно, и у двух слайсов они могут быть общими.

Как работать со слайсом

s := []int{1, 2, 3}
s = append(s, 4)   // s = обязательно
len(s)             // сколько видно
cap(s)             // сколько влезет
s[1:3]             // с 1 по 2

append возвращает новый слайс и не меняет старый — поэтому результат обязательно присваивают обратно.

Настоящая копия данных делается только через copy. Простое b := a копирует окно, и запись в b изменит a.

ОТЛИЧИЕ слайс и map

слайс

  • адрес — номер 0,1,2…
  • номер задаёт язык
  • порядок сохраняется
  • за границей — падение

map

  • адрес — ключ, любой
  • ключ выбираешь сам
  • порядок случайный
  • нет ключа — нулевое значение
Порядок обхода map Go перемешивает намеренно, чтобы на него не полагались. Нужен предсказуемый вывод — собери ключи в слайс и отсортируй.

Как работать с map

m := make(map[string]int)
m["a"] = 1
delete(m, "a")
v, ok := m["нет"]  // 0, false

ok отвечает, лежал ли ключ вообще — иначе «нет ключа» и «ключ со значением 0» не отличить.

Без make map равна nil: читать можно, запись обрушит программу.

что программа делает

Выбор пути

if n > 0 && n < 10 {
} else {
}

switch c {
case 'a', 'e':
default:
}
&&
верны оба условия
||
верно хотя бы одно

В switch ветка сама останавливается — break писать не нужно, в отличие от других языков.

Повторение

В Go один-единственный цикл — for. Слов while и do в языке нет.

for i := 0; i < 10; i++ {}  // счётчик
for n > 0 {}                // пока верно
for {}                      // вечный
for i, v := range s {}      // по набору

break выходит из цикла целиком, continue переходит к следующему шагу.

Функция

Функция принимает значения и возвращает результат. Тип после скобок обязывает его вернуть.

func Sum(a, b int) int {
    return a + b
}

Go возвращает несколько значений сразу — на этом построена работа с ошибками.

func Div(a, b int) (int, error)
ОТЛИЧИЕ напечатать и вернуть

fmt.Println(x)

  • показывает человеку на экране
  • программе не отдаёт ничего
  • результат нельзя присвоить

return x

  • отдаёт значение программе
  • на экране не появляется
  • результат можно присвоить
return к тому же немедленно прекращает функцию — код после него не выполнится никогда.

Где живёт переменная

Переменная живёт только внутри тех фигурных скобок, где создана. Вышли из блока — её больше нет.

for i := 0; i < 3; i++ {
    x := i * 2   // x живёт
}                // здесь x уже нет

Поэтому накопитель, нужный после цикла, создают до него. И ещё: неиспользованная переменная — ошибка сборки, а не замечание.

Связи

значение или ссылка
ОТЛИЧИЕ копия и ссылка

передаётся копия

  • число, строка, bool
  • массив целиком
  • struct
  • изменения внутри функции снаружи не видны

передаётся ссылка

  • указатель *T
  • слайс и map
  • изменение элемента видно снаружи
  • но append снаружи не виден
Это самая частая причина «поменял, а не изменилось». Если функция должна дописывать в слайс — пусть она его возвращает.

Указатель

Указатель — адрес значения, а не само значение. Нужен, чтобы функция меняла оригинал, а не копию.

func Older(u *User) {
    u.Age++
}
Older(&u)
&x
взять адрес значения
*T
тип «адрес значения типа T»
nil
указатель в никуда

Свой тип из полей

struct — свой тип из нескольких значений под одним именем.

type User struct {
    Name string
    Age  int
}
u := User{Name: "Нурс", Age: 30}

↳ Поля тоже подчиняются правилу большой буквы из области 1.

Ошибка — это значение

В Go нет исключений. Функция, которая может не справиться, возвращает ошибку вторым значением.

n, err := strconv.Atoi(s)
if err != nil {
    // не получилось
}

nil в переменной ошибки значит ошибки не было. До проверки результату доверять нельзя.

Метод — функция своего типа

Если в скобках перед именем указать тип, функция станет методом этого типа.

func (u User) Hello() string {
    return "Привет, " + u.Name
}
u.Hello()

Со звёздочкой (u *User) метод меняет оригинал, без неё — копию. Правило то же, что у функций.
